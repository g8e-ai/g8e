## [2.2.1] - 2026-09-27

### Overview

v2.2.1 is an operator architecture, evaluation rollout and telemetry, binary export resilience, harness dispatch normalization, Python environment alignment, and integration test performance release. It introduces first-class operator role distinction (`inference`, `provenance`, `observer`, `data`) and multi-attribute composite fingerprinting enabling multiple operator instances to run concurrently on the same host without collision, establishes a discriminative 5-scenario Tier 1 smoke gate evaluation catalog with automated qualification promotion, adds sequential batch execution across all 4 sovereign topology formations, enhances Evaluation Explorer live event streaming with category filtering, run boundary dividers, active elapsed timers, and active-run event retention, enables automatic derivation and bidirectional normalization of event types and action types in the agent harness dispatch client, improves binary artifact reader resilience for source-only environments, corrects Docker entrypoint packaging rules in `.dockerignore`, handles heterogeneous evaluation assignment variants, fixes Python path resolution across ensemble services and test suites, and optimizes integration test execution and token store isolation.

### Added

* **Operator role distinction & composite fingerprinting** — Introduced first-class `OperatorRole` differentiation (`inference`, `provenance`, `observer`, `data`) and the `operatorcapability` package (`internal/services/operatorcapability/role.go`). Multiple operator instances running on the same physical host or container runtime are completely disambiguated by their operational role, local directory, launching account, port, and a composite SHA-256 `system_fingerprint`. Role capability enforcement (`ValidateOperatorRoleCapabilities`) and separation verification (`VerifyOperatorSeparation`) guarantee that witness and inference operators cannot be conflated with data operators.
* **Tier 1 smoke gate evaluation catalog & automated promotion** — Added a frozen 5-scenario discriminative screening catalog (`BuildSmokeGateScenarioCatalog`, `ValidateSmokeGateScenarioCatalog` in `internal/services/evaluation/scenario_catalog.go` yielding 15 assignments across 3 roles: `instruction-exact-format`, `tool-select-file-read`, `tech-error-diagnosis`, `security-policy-deny-delete`, `recovery-tool-failure`). Added `--gate-smoke` and `--promote-on-pass` flags to `g8e eval rollout run` and `g8e eval campaign start`, enabling fast candidate screening and conditional promotion to full 75-assignment qualification.
* **Evaluation formation catalog execution** — Added `--catalog` (alias `--all`) flag to `g8e eval formations run`, allowing sequential batch execution of all 4 sovereign topology formations (`ultra-light-speedster`, `balanced-analyst`, `deep-reasoner`, `frontier-orchestrator`) through the governed Inference Operator path with peak VRAM tracking and structured summary output.
* **Evaluation Explorer live stream UX enhancements** — Added live event stream category filtering dropdown, visual run boundary dividers (`.stream-run-divider`) between events from consecutive campaign runs, real-time tabular elapsed duration timers for in-progress assignments, and an active-run-only event retention mode lifting the default 100-event window limit.
* **Harness dispatch action/event normalization** — The agent harness dispatch client (`internal/tools/agent_harness/client/protocols.go`) automatically derives and normalizes missing `EventType` and `ActionType` pairs (e.g., `ActionTypeOllamaModelResidency`, `ActionTypeOllamaModelInventory`, `ActionTypeExecuteBash`), ensuring interoperable dispatch across client invocations.
* **Evaluation Explorer category test coverage** — Added component tests (`LiveEventStream.test.tsx`) verifying category classification, badge styling, and fallback rendering.

### Changed

* **Operator registration & session routing** — Updated Gateway registration (`registration_service.go`), bootstrap authentication (`bootstrap.go`), and session management (`operator_session_service.go`) to record and enforce `operator_role`, `local_dir`, `account`, and `port`, ensuring general tool commands route strictly to governed data operators via `IsGovernedDataOperator`.
* **Hardware-based inference operator selection** — Added `SelectInferenceOperatorForHardware` to resolve inference operators by exact system fingerprint.
* **Protocol & wire models** — Extended `protocol/models/operator_document.json`, Go wire and authentication models (`internal/models/auth.go`, `internal/models/wire.go`), and Python ensemble operator models (`ensemble/app/models/operators.py`) with `operator_role`, `local_dir`, `account`, and `port`.
* **Python path normalization & test setup** — Standardized root and relative path resolution in `ensemble/app/utils/path.py`, `ensemble/app/constants/paths.py`, `ensemble/app/models/settings.py`, and test fixtures (`ensemble/tests/conftest.py`), eliminating path resolution anomalies during local and CI execution.
* **Protocol & package synchronization** — Protocol packages, Python packages (`protocol/python/pyproject.toml`, `protocol/python/g8e/__init__.py`), lockfiles (`protocol/python/uv.lock`, `ensemble/uv.lock`), and specification headers synchronized to `v2.2.1` / `2.2.1`.

### Fixed

* **Evaluation Explorer live event category display** — Corrected event category rendering in `LiveEventStream.tsx` to properly display categorized live event streams and rebuilt static web assets.
* **Binary artifact reader resilience** — `g8ebinaries.OpenReader` gracefully handles missing manifest files in development environments without complete catalogued binaries, preventing fatal errors when reading uninitialized artifact roots.
* **Docker build entrypoint ignore rule** — Updated `.dockerignore` to explicitly retain `scripts/docker-entrypoint.sh` while excluding non-container scripts.
* **Campaign aggregate heterogeneous variant projection** — Corrected assignment variant role resolution in `campaign_aggregate_projector.go` to cleanly branch between heterogeneous and homogeneous assignment models.
