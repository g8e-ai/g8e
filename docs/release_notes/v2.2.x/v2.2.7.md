## [2.2.7] - 2026-10-01

### Overview

v2.2.7 grades the whole g8ee chain of a scored turn, not only the reasoning persona, and closes correctness gaps in the `1.1.0` evaluation grader that v2.2.6 introduced. A scored turn now records one typed step per player that did its job (Triage, Sage or Dash, the Tribunal seats and vote, Marshal, the Auditor, Codex), the trace schema is `7`, and a scenario can declare per-player gold. The built-in suite now publishes its public criteria, a trace the grader cannot read is a harness failure instead of a model failure, and the denial rule matches g8ee's policy decisions exactly. Outside evaluation, the release makes an Operator keep retrying its command channel for as long as it runs, verifies an Inference Operator's provider before it claims a session, and fixes tool declarations that strict providers (Ollama's qwen3.5 template) rejected with HTTP 500. v2.2.7 follows v2.2.6 directly (v2.2.7 was never tagged before this release). It changes no `.proto` contract and no L1-L5 governance behavior.

### Added

* **Trace schema `7` and `player_steps`** — A scored turn records the chain: one typed `EvaluationPlayerStep` per player that did its job (`triage`, `sage` or `dash`, the Tribunal seats `axiom`, `concord`, `variance`, `pragma`, `nemesis`, the deterministic `tribunal` vote, `marshal_command`, `marshal_error`, `auditor`, `codex`), each carrying the tier it resolved from, the model, and at most one typed output (INV-EVAL-TRACE-05). Tribunal-chain steps are recorded through a new `TribunalObserver` on the real Tribunal pipeline (`TribunalEmitter`), so a failed seat, a second round, and a failed Auditor are recorded as well as successes. Recording never changes how the chain runs, an observer that raises is logged and ignored, and a production request has no observer. The wire shape is pinned by `protocol/vectors/eval/player_steps.json`, which `test_player_steps.py` and the Go grader both test.
* **Per-player grading (INV-EVAL-CAMP-17)** — A scenario can declare `players` gold (`ScenarioPlayerExpectations`): what Triage must classify, the command contract the Tribunal's seats, vote and Auditor must meet, the risk band Marshal may assign, and what Codex's memory must contain and redact. Each player the trace shows is graded on its own job as a `player:<id>` grade (`player:triage`, `player:sage`, `player:axiom`, `player:tribunal`, `player:marshal_command`, `player:auditor`, `player:codex`, ...). A player the chain never reached is not graded, a player that did not run when it should have is a failure, and a malformed chain is a grading error. Results carry `tier_primary`, `tier_assistant`, and `tier_lite` decomposed scores, so a failing Triage lowers the lite tier and not the persona's. Catalog validation rejects player gold that grades nothing or names a label g8ee never emits. The built-in suite does not declare player gold yet.
* **Interrogation content check** — `ScenarioContentCheck.Interrogation` requires the whole answer to be one `<interrogation>` block of exactly three numbered, strictly yes/no questions, the Interrogation Protocol Sage and Dash are told to follow.
* **`policy_deny_error_types` in the agent tool registry** — `protocol/constants/agenttools/agent-tool-registry.json` now exports the tool failures g8ee records as a `deny` policy decision (`POLICY_DENY_ERROR_TYPES` in `ensemble/app/services/evaluation/tool_evidence.py`). The Go grader's denial set must equal it, and `TestDeniedErrorTypes_MatchG8eePolicyDenySet` plus `make agent-tool-registry-check` fail on drift.
* **`ErrEvaluationTraceUnreadable`** — A trace whose `tool_calls`, seed, or workspace cannot be decoded fails grading as a harness failure (`internal/constants/errors.go`).
* **Rejection logging on the observe producer routes** — The Gateway logs why it answered `400` or `403` on `/api/v1/observe/producer/*` requests. The ensemble treats those calls as best-effort and never surfaced the reason; the `403` response body stays non-disclosing.
* **Response body in ensemble HTTP error logs** — A failed outbound HTTP call logs the response body alongside the status.

### Changed

* **An Operator never gives up on its command channel** — `listenForCommands` previously stopped after three consecutive failed or closed subscriptions, leaving an Operator that still heartbeated over its publish socket but could never receive a command. It now retries with capped exponential backoff until the service context ends, so a Gateway restart or upgrade of any length is survived. The `[RECONNECT]` log lines report the next retry delay instead of an attempt count, and `shouldGiveUp` is removed (`internal/services/pubsub/pubsub_commands.go`).
* **An Inference Operator verifies its provider before it claims a session (#335)** — `G8eoService.Start` checks provider reachability and every configured role model before `RequestBootstrapConfig`, so a provider that is down or missing a model fails startup without leaving a claimed session that never heartbeats and ages to `stale`. The check logs the endpoint, models, and timeout first, because it can block up to the provider status timeout. The `operators list` Hostname column is still populated only by heartbeats, so an Operator that fails the check never reports one. The `operator.crt` container healthcheck is unchanged and stays enrollment-scoped.
* **Tool declarations render through one typed method** — `ToolDeclaration.parameters` is a `Schema` and every provider (Anthropic, Gemini, Ollama, OpenAI, g8e) renders it with `Schema.to_json_schema()`. The `schema_to_dict` helper and the dict form of `parameters` are removed. Gemini receives `parameters_json_schema`. An `OBJECT` schema always carries `properties`, empty for a tool with no arguments.
* **Denial classification matches g8ee** — A call is denied when g8ee records a `deny` policy decision: `validation.error` and `g8e.resolution.error` now count, and `approval.denied` and `user.denied` no longer do, because g8ee records those as `refused`. `state_observation` fails when any of the scenario's forbidden tools succeeds, wherever it acted, or when an `allow` governed action is bound to one, even a call recorded as failed; `recovery` is driven by the typed `missing_resource` recovery expectation instead of a scenario id.
* **The Auditor is a primary-tier player** — Its model calls report the tier they resolved from (`primary`, or `lite` when the Tribunal falls back to the lite provider), and the call-site inventory says `primary`. Earlier traces attributed them to `lite`.
* **`g8e eval gates chat` uses the g8ee client** — The chat request and the trace poll go through the same g8ee client (`--ensemble-url`, default `http://localhost:8000`) that scored runs and the canaries use, instead of the Gateway's chat proxy.
* **Chat probe trace validation is stricter and more specific** — A failed assignment's error reads `assignment failed: <recorded error>` (or says none was recorded), and a non-object `evaluation_context.workspace` is rejected instead of skipped.
* **Public failure sentence is value-free for a wrong argument** — The public form names the argument and says it failed validation. The rule text quotes gold samples, the attempt-scoped workspace path, and the model's own value, so it stays in the private sentence (INV-EVAL-EVID-07).
* **Catalog `1.1.0` digest changes** — Public criteria, public tool score dimensions, and the player-gold contract are part of the frozen catalog, so the digest differs from the one v2.2.6 shipped. The catalog version stays `1.1.0`: v2.2.6's Deferred section records that no campaign had been run against `1.1.0`, and runs already frozen keep the digest they were frozen with.

### Fixed

* **Default-suite runs published no scenario summary** — The built-in catalog carried no public criteria or tool score dimensions, so `ResolvePublicScenarioContext` rejected every default-suite scenario as malformed, and publication and export fell back to the no-scenario-context path: the enriched public `scenario_summary` (including `trajectory_policy` and the value-free `prompt_hint`) was never published, and every tool-scorecard cell read from raw grades instead of the scenario's applicability (#337). `materializeScenarioBlueprint` now derives both from each blueprint's typed shape (INV-EVAL-CAMP-18). The text is a fixed vocabulary that names what is checked, never the answer, and is not drawn from the private gold descriptions. Custom suites get the same criteria with no suite-file change, and `ValidateScenarioCatalog` rejects a scenario with no criteria. Answer-only scenarios now publish `scenario_not_applicable` for every tool dimension.
* **Tool declarations that strict providers rejected** — A tool that takes no arguments was declared without `properties`, and Ollama's qwen3.5 template failed the whole request with HTTP 500 "properties must be an object". Every provider now receives a complete JSON Schema object.
* **Evaluation Explorer rejected valid public summaries** — The Gateway's protojson omits empty repeated fields, so a scenario summary with no allowed, expected, or forbidden tools, criteria, or dimensions failed the explorer's wire assertion. Absence now means an empty list (`campaign-wire.ts`).
* **`governed_action` evidence had no grading rule** — `tool-arg-run-commands` requires it, so the scenario could never score 1. It now passes when an `allow` governed action resolves, by non-empty id, to a successful call.
* **Unreadable trace blamed on the model** — A malformed `tool_calls`, seed, or workspace in a trace read as "the model made no tool call". Grading now fails with `ErrEvaluationTraceUnreadable`, and a wrong-typed `tools_declared` is an import error rather than "no tools declared".
* **Scored operator calls crashed evidence capture** — The tool evidence recorder read `operator.id` from a bound Operator, which only has `operator_id`, so the first successful operator tool call in a scored request that binds an Operator raised `AttributeError`. It now binds the governed action to the Operator's id and session.
* **Catalog validation trusted references over content** — `ValidateScenarioCatalog` compared a scenario artifact's reference to its own stored reference but never hashed the body, so a body edited after freezing still validated. It now requires the body to match its digest.
* **Failure sentence with an empty hint value** — A hint argument whose value resolves to nothing no longer renders as an empty quoted value.

### Deferred

* **Player gold in the built-in suite** — The built-in `default-suite@1.1.0` declares no `players` gold, so no built-in scenario yet produces a `player:*` grade other than the persona's. Authoring that gold is separate from the grading machinery shipped here.
* **Tool-scorecard dimensions beyond two** — Only the `role-invoked` and `governed-inference` grades map to a tool-scorecard dimension (`tool_recognition`, `follow_up_decision`). The other applicable dimensions publish `source_not_captured` until a producer exists for the `tool-selection` and `policy-expectation` grades.
* **Re-baselined `1.1.0` results** — No campaign has been re-run against catalog `1.1.0`; the canaries have not been run against a live stack.
* **Production tool stripping for unregistered models** — Production chat still declares no tools for a model tag its static `supports_tools` table does not register; `tool_gate: bypassed_for_eval` keeps the eval divergence visible.
* **`EnsembleResourceCreation.CaseTitle` cleanup** — `ResourceCreationRequest.case_title` is unused by g8ee but still set by agent-harness scenarios.
