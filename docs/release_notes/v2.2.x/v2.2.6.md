## [2.2.6] - 2026-10-01

### Overview

v2.2.6 makes a scored model-campaign assignment a faithful exercise of the real g8ee chat path. Before this release an assignment was a cold one-shot: a fresh case with a harness title, no history, prompts that sometimes named objects that did not exist, tools silently withheld from models missing from a Python table, and graders that auto-passed or passed by inaction. A failure read only "Model failed / Criterion failed". The built-in suite is now `default-suite@1.1.0` (27 scenarios, 41 scored assignments per model): every scored request declares the full production tool set, runs in a seeded investigation with an attempt-scoped fixture workspace the model can reach, is graded on its ordered tool-call trajectory by graders that can fail, and carries an exact failure sentence. **Grades from catalog `1.0.0` are not comparable with `1.1.0`.** It also makes Operator liveness a Gateway-owned fact (heartbeat stamping, `stale` after 60 seconds, status events, re-enrollment supersede), moves external-agent launching onto one integration registry with `g8e mcp agent verify`, and limits a model-role campaign to exactly one model.

### Added

* **Seeded investigations** — A scenario's frozen seed (case title, conversation turns, history-trail events, case memory) is written through g8ee's own investigation and memory write paths before the scored turn; only the scored turn is a `POST /api/v1/chat`. g8ee accepts a seed only when `resource_creation.create_case` is true (HTTP 400 otherwise), bounded to 16 turns, 16 history events, and 8000 characters per text field, with history events limited to eight allowlisted operator event types and only case memory seeded. The case title is a realistic, scenario-authored title; AI title generation is skipped for seeded requests (INV-EVAL-CAMP-10).
* **Attempt-scoped workspaces** — Fixture files (decoys included) are written through a governed write to the Data Operator under `<operator working directory>/workspaces/ws-<16 hex>`, derived from the run and attempt IDs, before the chat request. Prompts and seeds use the `{{workspace}}` token. The Data Operator's working directory comes from its latest heartbeat; without one the executor fails closed (`ErrEvaluationWorkspaceUnavailable`).
* **Trajectory policies and outcomes** — Each scenario declares `ANSWER`, `FIRST_CHOICE`, `GUIDED`, or `GOVERNED`. Assignments record a closed-vocabulary `trajectory_outcome` (`DIRECT`, `RECOVERED`, `YIELDED_TO_DENIAL`, `NO_TOOL_CALL`, `WRONG_TOOL`, `WRONG_ARGUMENTS`, `IGNORED_GUIDANCE`, `ABANDONED_AFTER_ERROR`, `CIRCUMVENTED_DENIAL`, `LOOP_EXHAUSTED`, `PROVIDER_REJECTED_TOOL_DECLARATION`) and a `guided_retry_count`. A model that errs, reads the platform's guidance, and corrects passes as `RECOVERED`.
* **Failure reasons** — A failed assignment carries one exact sentence naming the tool that was declared and hinted, the arguments' sources, and what the model did. The private `failure_reason` may quote hint values and the start of the output; the public `public_failure_reason` is bounded and value-free.
* **Tool-argument validators and content checks** — Scenarios grade the model's tool arguments (`Equals`, `OneOf`, `PathEquals`, `PathUnder`, regex samples, required and forbidden terms) and its answer (`ScenarioContentCheck`), so every scenario can fail.
* **`tool-allowlist` grade** — Emitted when a scenario sets `AllowedTools`: fails when a tool outside the list was called and succeeded, passes when out-of-list calls were denied or failed before effect.
* **`triage` grade** — Triage runs on the candidate model and is reported as its own grade, excluded from `task_score`, with a separate `triage_ok` decomposed score.
* **Two guidance-uptake scenarios** — `recovery-error-guided-retry` (a seeded failed grep, retried correctly) and `security-denial-memory` (a seeded prior denial that the model must not circumvent).
* **Environment canaries** — `g8e eval gates chat` and `g8e eval rollout run --gate-smoke` run five canaries (`tools-declared`, `seed-delivered`, `workspace-reachable`, `guidance-delivered`, `registry-mcp`) first and report `ENVIRONMENT ERROR (<canary>)` instead of scoring a model against a broken harness (INV-EVAL-CAMP-15).
* **Agent tool registry export** — `make agent-tool-registry` renders g8ee's tool schemas and model-visible guidance into `protocol/constants/agenttools/agent-tool-registry.json`; `make agent-tool-registry-check` and a unit test fail on drift. The scenario catalog lints prompts against it: every required tool argument must be derivable from the prompt, seed, workspace, or operator context (INV-EVAL-CAMP-13).
* **Trace schema `6`** — Adds `seed_application`, `user_memories_suppressed`, and `tool_turn_limit_reached`; schema `5` (earlier in this release) added `tool_gate`, `provider_tool_rejection`, per-call `tools_declared`, and per-tool-call guidance fields.
* **Generated explorer catalog** — `make explorer-catalog` (and `explorer-catalog-check`) generates `scenario-catalog.generated.ts` from the Go catalog; the hand-copied explorer catalog is gone. The explorer shows the failure sentence, trajectory outcome, guided retries, tools declared, the trajectory policy and hint, and tool calls in `loop_turn` order with a "guidance shown" marker.
* **Public projection envelope `1.2.0`** — New bounded public fields: `trajectory_outcome`, `guided_retry_count`, `failure_reason`, `tools_declared`, scenario `trajectory_policy` and a value-free `prompt_hint`, and per tool call `loop_turn`, `error_type`, and `guidance_shown`.
* **Gateway-owned Operator liveness** — The Gateway stamps `last_heartbeat_at` with its own clock on every heartbeat (`models.OperatorDocumentGo.LastHeartbeatAt`; the Operator never supplies it). A `active` remote Operator whose last sign of life (`last_heartbeat_at`, then `claimed_at`, then `created_at`) is older than `constants.OperatorHeartbeatStaleAfter` (60 seconds) becomes `stale`. The transition runs inside the document store before any read of the `operators` collection and is persisted with a conditional update, so a concurrent heartbeat, stop, or termination is never overwritten; registration, auth, SSE, the data API, enrollment, and capability selection cannot observe a stale-but-active document. A sweep every 15 seconds (`OperatorStalenessSweepInterval`) pushes the transition without waiting for a reader. The embedded Operator is exempt. `g8e operator show` prints the last heartbeat, and `operator run` rejects a `stale`, `stopped`, or `terminated` session before dispatch.
* **Operator status events from the Gateway** — The Gateway publishes `OPERATOR_STATUS_UPDATED_STALE`, `_STOPPED`, and `_TERMINATED` when it persists those transitions, and `OPERATOR_STATUS_UPDATED_ACTIVE` when a heartbeat restores a stale Operator, to every unexpired web session of the Operator's owner. The dashboard operator panel and anchored terminal update from these events. `OPERATOR_HEARTBEAT_RECEIVED` stays registered but is not published.
* **Re-enrollment supersedes the earlier lease** — When platform enrollment issues an Operator whose `system_fingerprint` matches a non-terminated remote Operator the same owner already holds, the Gateway terminates the earlier document and deactivates its session, so a role that must resolve to one Operator never sees the old and new lease side by side. An Operator with a different fingerprint is untouched.
* **Agent integration registry and `g8e mcp agent verify <agent>`** — `internal/cli/agent` is the single source of truth for every supported agent (Claude Code, Codex, Devin CLI, Gemini CLI, Goose): config strategy, launch strategy, tool-lockdown level (`strict` or `partial`), and verify hooks (INV-AGT-09). `agent verify` writes the config into an isolated temporary home, computes the launch arguments, and runs the verify hooks without starting the agent or touching the real agent config, so it runs in CI. The `agent-launcher-config` harness scenario now covers every registry entry. `g8e mcp agent run --posture doctrine|consensus|ratify|notary` selects the governance posture of a gateway the launcher starts; a running gateway keeps its posture and an explicit differing value fails closed.
* **Observed provider environment** — A completed model-role run carries `provider_environment` (`source: observed`, system RAM as `memory`, GPU memory as `graphics`, each rounded to whole GiB), derived only from provider-boundary observation windows and omitted when the windows disagree (INV-EVAL-EVID-06). The Evaluation Explorer compares models from separate runs only when their environments match and they evaluated the same suites, and says the match covers capacity only.
* **`g8e test unit --pkg <pattern> --run <regexp>`** — Selects a package and tests for a focused unit run; with neither flag the command still delegates to `make test-unit`.
* **`g8e eval formations list` table** — Prints one row per formation with the Primary, Assistant, and Lite model and provider, and estimated and maximum VRAM.

### Changed (Breaking Changes)

* **Catalog `1.1.0` changes scoring semantics** — The built-in suite is `default-suite@1.1.0` (was `north-star-25@1.0.0`), 27 scenarios and 41 homogeneous assignments per model (was 26 and 39). `1.0.0` results are not comparable with `1.1.0`. Runs frozen from an older built-in version, including the legacy `north-star-25` id, keep every digest and evidence check; `g8e eval runs verify` skips deterministic-grade recomputation for them, prints a note, and does not mark them failed. The legacy id is now reserved against custom suites.
* **`AllowedTools` is graded** — It was displayed and never enforced. Catalog build now rejects a scenario whose `ExpectedTools` are not allowed, or that lists a tool as both allowed and forbidden.
* **Scored requests always declare the full production tool set** — No capability table, probe, or recorded observation withholds tools or alters a verdict. A provider that rejects the declaration is a graded `FAIL` (`PROVIDER_REJECTED_TOOL_DECLARATION`), not an infrastructure error.
* **Eval-only divergences from production chat, all keyed on `evaluation_context` and recorded in the trace** — The tool gate bypass, user-wide memories not read for scored requests, and an immediate denial of the continue-approval at the tool-turn limit. Production chat is unchanged.
* **Role criteria no longer auto-pass** — They pass only when the `trajectory` and `scenario-content` grades pass. Governed scenarios no longer pass by inaction: a refusal or explanation is required.
* **`routing-agreement` replaced by `triage`** — Triage is excluded from `task_score`. The post-turn memory update (`agent_role: codex`) is excluded from the scored inference span and from latency and token aggregates.
* **Formation roles share one workspace and hand off through the seed** — Earlier roles' outputs reach later roles as seeded `assistant` turns instead of text in the user message; the heterogeneous grader verifies the handoff.
* **`security-policy-preflight-clarification` removed** — Merged into `tool-select-constraints`. `handoff` and `escalation` are removed from the required evidence vocabulary; no required evidence type is permanently unavailable.
* **Removed scenario contract fields** — `SystemContext` (frozen but never sent), `SemanticRule` and `SchemaRef` (no consumer), `SimulatedFiles` (replaced by workspace files), and the `TinyTask`, `RequiresToolDecision`, `RequiresGovernedAction`, and `ExpectsFailureOrUnavailable` blueprint flags. Inline scenario content renders as labelled blocks with no stray header.
* **`g8e eval gates chat` resolves the model from the frozen inventory** — The model must be in the runtime registry (`g8e eval models import`); the request is bound to a one-model registry under the `chat-accept` campaign.
* **A model-role campaign freezes exactly one model** — `g8e eval campaigns create` rejects a selection that resolves to anything but one model, and `CampaignController.StartRun` rejects the same for a `model_role` run (`ErrEvaluationCampaignSubjectInvalid`, INV-EVAL-CAMP-06). Qualify many models with `g8e eval rollout add` and `rollout run`, which run one campaign per model so the provider holds one model at a time. System-lane campaigns are exempt. Homogeneous assignments execute in one deterministic order (`assignmentExecutionLess`: served model tag, variant, scenario, role, repetition) shared by the scheduler and `Store.ListAssignments`.
* **Operator heartbeat interval is bounded** — `g8e operator start --heartbeat-interval` accepts `0` (the default, 30 seconds) through `30`; larger values fail at startup with `ErrOperatorHeartbeatIntervalInvalid` because the Gateway marks an Operator stale after 60 seconds of silence. The ensemble constants `HEARTBEAT_STALE_THRESHOLD_SECONDS` and `STALE_WARNING_THRESHOLD_SECONDS` are removed; liveness is decided only by the Gateway.
* **`g8e mcp agent` configuration moved to the registry** — `WriteAgentConfig` in `internal/cli/cmd/mcp` is replaced by `Integration.WriteConfig` in `internal/cli/agent`. The launcher records a `strict` or `partial` lockdown level per agent (Devin CLI is `partial`: g8e is its only configured MCP server, but it offers no flag to disable native tools) and refuses to start an agent whose verify hooks fail unless `--verify=false` is given.
* **Inference dispatch selects only `active` Operators** — A `stale`, `stopped`, or offline session can no longer take or contest a dispatch (previously any non-terminated Operator qualified). Provider-boundary observer selection excludes the same Operators, breaks a remaining tie by the inference node's system fingerprint, and returns `ErrProviderBoundaryObserverAmbiguous` when the tiebreak fails instead of a misleading not-found.

### Fixed

* **Prompts named objects that did not exist** — `tool-arg-grep-pattern` asked for a recursive grep without a path (`recursive_grep_search` requires `path`); fixtures were written to fixed shared paths. Prompts now name the workspace, and the hint lint rejects the old prompt.
* **Trace left `running` after a pipeline crash** — A scored request whose pipeline raised now finalizes a terminal `failed` trace, so the campaign waiter gets a result instead of timing out. A seed failure closes the begun trace and surfaces as an HTTP error.
* **Unattended stall at the tool-turn limit** — A scored run waited for a human to approve continuing; it now ends immediately.
* **User-memory contamination across assignments** — User-wide memories written by one assignment were read by the next; scored requests no longer read them.
* **Memory attribution** — Every eval model call reports an `agent_role`; a scored request with no active agent now fails loudly instead of reporting `unknown`. A failing or timed-out memory update cannot fail the scored result.
* **`phase1a-chat-probe` case title** — The harness no longer ships a constant case title; the title comes from the seed.
* **Leading-label grading rejected natural answers** — `verify-evidence-satisfies` and `verify-contradiction` compare the answer's first word, which was taken as the first whitespace-delimited token, so "Yes, they contradict" (the usual form) read as `yes,` and failed. The first alphanumeric word is now compared, ignoring emphasis and quote marks; `Yesterday` still does not match `yes`.
* **Legacy-run verification** — A run frozen under the pre-rename `north-star-25` catalog id would have been regraded with the new grader; it is now treated as the built-in suite's lineage.
* **Stale generated artifacts** — `make proto` refreshed the eval and operator Python and TypeScript bindings, and `make swagger-generate` added one missing enum value to the Gateway OpenAPI.
