## [2.2.8] - Unreleased

Draft. Release acceptance, live campaign comparison, and signed compliance evidence remain pending.

### Changed

* **Count each independent grading observation once** — Deterministic grades carry a typed basis: observation, derived, or structural. Derived grades remain visible without padding the pass-rate denominator. The Triage call grade stays separate from task scoring and the verdict. The built-in catalog is `1.2.0`; verification skips grade recomputation for older catalogs.
* **Verify stored scores against their grades** — Assignment verification recomputes task, deterministic pass-rate, Triage, and tier scores from verified grades for current catalogs. Formation results receive this check when graded from role traces. Re-sealing a result cannot make forged scores verify.
* **Compare runs with the shared scoring rules** — `g8e eval runs compare` uses the assignment verdict and deterministic pass rate. `INVALID_EVIDENCE` cells remain visible, appear in the invalid-evidence count, and are excluded from regressions, improvements, and mean scores. JSON includes each cell's verdict and each side's `invalid_evidence` count.
* **Reject retired evidence declarations** — New scenario catalogs reject the `deterministic_grade` evidence type with `ErrEvaluationScenarioContractInvalid`. Stored catalogs remain readable under their recorded version.
* **Typed public live events** — Live events are now the protobuf message `PublicLiveEvent`, encoded only through the canonical protojson owner instead of a hand-written Go struct with `omitempty`. Progress counts and metric values track presence, so a zero (no progress yet, or a failed assignment's `pass` of 0) is emitted, and an event that omits a count is rejected by the Gateway validator and the Explorer's new `decodeLiveEventWire` rather than read as zero. The validator decodes the message strictly, so a field outside it is rejected, and requires each metric to carry exactly one finite value or an unavailable reason. On the wire a live event's `release_basis` is now the `PublicReleaseBasis` enum name, as on lifecycle and result records; the Explorer maps it to its lowercase view vocabulary. The Explorer view contract version is unchanged at `1.6.0`, which has not shipped.

### Added

* **Assignment diagnostics** — `g8e eval runs assignments <run>` reports scenario, model/role or stack, repetition, duration, verdict, deterministic pass rate, and failed grades with recorded causes. `--failed` includes terminal results that did not pass, including invalid evidence. `--assignment <id>` shows every grade and its basis. `--json` carries canonical assignment/result protojson and explicit verdict and pass rate, preserving scored zero as `0` and an unscored result as `null`.
* **Execution log context** — Each assignment log line identifies the scenario, target, repetition, and duration beside lifecycle, verdict, pass rate, and failed grades.
* **Release-tagged campaigns** — A campaign now records the platform release (and source revision) that froze it, bound into its digest. Starting a run under a different release fails with `ErrEvaluationPlatformReleaseMismatch`. Campaigns frozen before v2.2.8 keep their digests; `g8e eval campaigns tag --release <vX.Y.Z> <campaign>...` asserts their release, shown as `(asserted)` beside `(recorded)` in `campaigns list` and `show`.
* **Release provenance in campaign exports** — Export schema `1.2.0` adds `release`, `release_basis`, and `source_revision` to `run_summary.json` and SQLite metadata. The command's JSON report also identifies the release and basis. Untagged historical campaigns remain explicitly unknown. Compliance bundles retain the digest-bound campaign spec and exclude operator release tags from protected artifacts and inventories.
* **Public release provenance and filtering** — Assignment lifecycle/result protobufs and Explorer schema `1.6.0` preserve campaign release provenance through live events, snapshots, catch-up, verification revisions, and exports. The Explorer defaults to the platform release from its build's `VERSION`, offers “All releases,” and distinguishes recorded, asserted, and unknown campaigns. Historical detail links remain readable. Malformed release tags stop publication instead of acquiring the publisher's identity.

### Fixed

* **Provider and harness failures counted against the model** — A provider error, execution error, escalation, or grader failure no longer publishes a model `FAIL`. Each terminal lifecycle now publishes its own outcome (`provider_failed`, `execution_failed`, `escalated`, `grader_failed`, `invalid_evidence`, `stopped`) from one mapping, and its verdict is `INVALID_EVIDENCE`: shown, with no `pass` metric, and excluded from `runs compare` and pairwise agreement. The Explorer shows each outcome and filters failures by it. An unrecognized lifecycle is an error, not a model failure. Run and per-model `pass_rate` now divide by assignments judged on the model, so a provider outage no longer lowers it; with none judged the rate is unavailable rather than zero.
* **Export pass-rate denominator** — Model CSV and SQLite exports use the same judged-assignment denominator and publish a `judged` count. One pass, one miss, and one provider failure exports as `0.5`; with nothing judged the CSV cell is empty and SQLite stores `NULL`. Coverage continues to count all terminal assignments.

* **Failed scores displayed as unavailable** — The Explorer's wire decoder materializes the protobuf default of zero for a present score record whose `value` is omitted. A missing `task_score` record is a validation error instead of an inferred verdict.
* **Live rows showed the wrong outcome or later evidence** — Terminal rows display the verdict outcome while retaining lifecycle in detail. Started rows no longer receive final assignment metrics. Assignment metric updates carry the designated role and binary `pass` metric, which the stream reads without deriving a pass from a rate.
* **Scenario applicability lost at adaptation** — Benchmark observation metrics use the shared metric decoder, preserving normalized `scenario_not_applicable` reasons.
* **Failure cause missing from live rows** — A failed row's Status tooltip displays the existing public failure sentence from the matching assignment. Assignment details show the same sentence. The tooltip is limited to failed terminal events and matching dataset, assignment, and run identity. Grade basis stays private.
* **Generated constants failed formatting checks** — The constants generator formats its Go outputs before writing or checking them. Regenerated event and action constants change whitespace only.
* **Stale embedded Explorer** — Rebuilt the production Explorer and refreshed Gateway assets through `make embed-explorer`.

### Tests

* **Shared failed-score wire vector** — Go constructs a failed public result, checks canonical bytes against `protocol/vectors/eval/public_assignment_result_failed.json`, and verifies round-trip equality. The Explorer consumes those same bytes and checks `task_score = 0`, `pass = 0`, and `model_failed` on the assignment and terminal event.
* **Shared live-event wire vector** — Go constructs a `metric_updated` event with zero progress and a measured zero `pass`, checks its canonical bytes against `protocol/vectors/eval/public_live_event.json`, and verifies round-trip equality. The Explorer decodes the same bytes and checks that both zeros survive. Validator tests reject a missing count, a field outside the message, the view-form release basis, and a metric with both or neither of value and reason.
* **Generator output contract** — Existing generation tests now require both Go outputs to be formatted before writing or checking generated artifacts.
* **Failure presentation and disclosure** — Stream tests cover model, grader, and invalid-evidence failures and prevent the sentence from appearing on earlier, passing, or other-run rows. Assignment detail tests check the public sentence, and adapter tests reject private grade basis and detail fields.
* **Export and compliance provenance** — Tests cover recorded, asserted, and unknown releases in JSON and SQLite, reject malformed release tags, preserve campaign digests, and check that compliance sources retain recorded identity while excluding operator assertions. CSV and SQLite regression tests reproduce the old terminal denominator and scored-zero substitution before the fix.
* **Public release identity** — Publication regression tests cover recorded, asserted, and unknown campaigns across lifecycle, result, aggregate, completion, and live-event records. Gateway/browser decoder tests reject inconsistent provenance; Explorer tests check the current-release default, explicit all-release URL state, historical selection, and adapter preservation.
