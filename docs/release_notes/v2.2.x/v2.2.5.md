## [2.2.5] - 2026-09-30

### Overview

v2.2.5 consolidates MCP agent operations, gateway downstream egress, and application identity, moves platform configuration out of the environment, hardens destructive operations, and adds evaluation-evidence backup and restore. It removes the CLI L1 governance reverse proxy wrapper (`g8e mcp agent run --url` and `g8e mcp agent run -- <cmd>`), narrows `g8e mcp agent run <agent>` to a fail-closed agent launcher, and introduces governed Subprocess Downstream Egress on the Gateway (`--mcp-downstream-cmd` and `--mcp-downstream-args`). All third-party MCP tool calls and resources now flow through the unified L1–L5 Gateway pipeline (`HandleMCP` -> L1–L5 -> `ActionReceipt`).

### Added

* **Gateway Subprocess Downstream Egress** — Added `--mcp-downstream-cmd` and `--mcp-downstream-args` flags to `g8e serve gateway` and `g8e gw start`. The Gateway can spawn and manage a downstream stdio MCP subprocess (such as `@modelcontextprotocol/server-filesystem`), proxying `tools/list`, `resources/*`, and `prompts/*`, and executing governed `tools/call` mutations through the complete L1–L5 governance pipeline with circuit breaker protection, sensitive data scrubbing, and signed `ActionReceipt` generation.
* **Shared MCP Stdio Transport** — Extracted `internal/cli/mcptransport` package providing `ServeStdio` transport for clean JSON-RPC 2.0 framing, notification dropping, parse error handling, and initialize handshakes.
* **Platform Application Enrollment (`g8e auth enroll app <name>`)** — Added generic `application` platform component kind (`PLATFORM_COMPONENT_KIND_APPLICATION = 4` in `protocol/proto/g8e/common/v1/common.proto`) and `g8e auth enroll app <name>` CLI command, providing an owner-approved enrollment workflow for applications and agents. Applications generate local keys, submit a CSR, and poll until approved via `g8e auth enroll approve <request-id>`. The issued certificate binds the app and approving-owner SPIFFE identities, and reserved first-party names are rejected.
* **Bulk enrollment approval** — `g8e auth enroll approve` accepts any mix of space-separated selectors (request ID, instance ID, or hostname) and `--all`. Every selector must match a pending request or nothing is approved; matched requests are displayed and confirmed once, then decided independently.
* **Evaluation evidence backup and restore (`g8e eval backup`, `g8e eval restore`)** — `eval backup` copies runs, campaigns, archives, exports, the rollout queue, and the frozen model inventory into a timestamped snapshot directory outside `.g8e/` with a SHA-256 manifest; run and lease state is not copied. `eval restore <snapshot-dir>` verifies every file against the manifest before writing, skips identical files, and refuses to overwrite differing files without `--overwrite`. Restoring does not rebuild the Gateway mirror; run `g8e public restore --queue` after re-enrolling a fresh stack. Plural aliases (`evals`, `backups`, `restores`, and the other eval resource groups) resolve to the same commands.
* **Multi-operator deployment and binding** — `g8e operator deploy` gains `--count N` (N Operators per host under `<remote-dir>/op-00001` .. `op-N`) and `--approve` (approves each Operator's enrollment as the owner, one at a time, and waits until every approved Operator is active, printing each operator session ID). Redeploying over a running Operator is safe: the binary uploads as `g8e.new` and is renamed into place. This replaces `scripts/loadtest-operators.sh`. `g8e operator bind <operator-session-id>...` binds the CLI session to many operator sessions in one Gateway call; every target is validated before any binding changes, and the first target is the primary binding.
* **Ensemble launcher and typed bootstrap settings** — The ensemble container entrypoint is now `python -m app.serve`, whose explicit arguments (`--gateway-http-url`, `--gateway-url`, `--gateway-https-url`, `--gateway-pubsub-url`, `--runtime-dir`, `--pki-dir`, `--secrets-dir`, `--ca-cert-path`, `--host`, `--port`) become frozen `BootstrapSettings` (`ensemble/app/constants/bootstrap.py`) before the application imports.
* **External console example** — Added `examples/external-console/`, a self-contained static browser console that connects directly to a local Gateway over HTTPS (first-owner passkey registration and sign-in, approvals, platform enrollments, and the live audit stream) for use with `g8e gw connect`. It does not modify the Gateway or the first-party dashboard.
* **Preflight Clarification Evaluation Scenario (`security-policy-preflight-clarification`)** — Added a dedicated security policy scenario evaluating an agent's capability to seek clarification on command constraints and operational boundaries without invoking execution tools when presented with preflight command execution requests.

### Changed (Breaking Changes)

* **Removed `g8e mcp agent run --url` and `g8e mcp agent run -- <cmd>`** — The CLI-level L1 reverse proxy wrapper has been removed entirely. `g8e mcp agent run` is now exclusively an agent launcher that accepts only supported agent IDs (`claude`, `codex`, `devin`, `gemini`, `goose`). Unknown agent names fail closed with `ErrAgentNotFound`. Third-party MCP servers (stdio subprocess or HTTP) must be attached directly to the Gateway using `--mcp-downstream-cmd` / `--mcp-downstream-args` or `--mcp-downstream-url`.
* **Consolidated Application Credentials to Platform Enrollment** — Removed delegated application enrollment (`POST /api/v1/pki/apps/delegated`), CLI flags `--app-cert`/`--app-key`, and environment variables `G8E_APP_ID`, `G8E_APP_CERT`, `G8E_APP_KEY`. The one replacement is `g8e mcp stdio --app <name>`, which resolves the managed credentials created through owner-approved platform enrollment. `g8e mcp agent run` writes `--app <agent>` into the agent's generated MCP configuration and no longer passes credentials, paths, or endpoints to the agent process through the environment.
* **Environment Variables Limited to Secrets, User-Specific Endpoints, and Host Facts (INV-ENV-04)** — Platform configuration no longer comes from the environment. Removed: the `g8e mcp stdio` variables `G8E_CLIENT_CERT`, `G8E_CLIENT_KEY`, `G8E_CA_BUNDLE`, `G8E_GATEWAY_URL`, and `G8E_APP` (use `--client-cert`, `--client-key`, `--ca-bundle`, `--gateway-url`, `--app`, or the enrolled credentials on disk); `G8E_ENSEMBLE_URL` (use `--ensemble-upstream-url` on the gateway and `--ensemble-url` on eval commands); `G8E_EVAL_EXPLORER_ROOT` (use `--eval-explorer-root`); and `G8E_DOCKER_COMPOSE` (use the new `--public-spectator-allow-container-bind` gateway flag). The Docker Compose stack no longer interpolates `G8E_PREFIX`, the host port variables, `G8E_PUBLIC_MIRROR_*_PORT`, `G8E_EVAL_EXPLORER_PORT`, `G8E_HEARTBEAT_INTERVAL_SECONDS`, `G8E_PUBLIC_BASE_URL`, `G8E_INFERENCE_{PRIMARY,ASSISTANT,LITE}_MODEL`, or `G8E_INFERENCE_KEEP_ALIVE`; those are literals in `docker-compose.yml` or `g8e operator start` defaults, and a checked-in `docker-compose.override.yml` changes them. `.env.example` now lists only `G8E_OLLAMA_ENDPOINT` (required; the Inference Operator fails fast without it), `G8E_HOSTNAME`, and `G8E_USER_HOSTNAME`. Every Go environment key is declared with a category in `protocol/constants/env_vars.json`, and a ratchet test keeps the set of remaining platform-configuration variables from growing.
* **Inference Operator Default Models** — `g8e operator start --inference-enabled` now defaults the Primary, Assistant, and Lite roles to `gemma4:e4b`, `qwen3:1.7b`, and `qwen2.5:0.5b-instruct-q4_K_M` (keep-alive `-1`) when the `--inference-*-model` flags are not given; previously an unset role skipped the provider readiness check for that role. The provider must serve those models, or the flags must name the models to use. The default models previously varied between `.env.example` and Compose.
* **Removed deprecated `g8e eval gates probe --model`** — The model is the positional argument (`gates probe <model>`).
* **Examples relocated and the env-var MCP example removed** — Protocol examples moved from `protocol/examples/` and `protocol/python/examples/` to the top-level `examples/` tree (`governance-envelope`, `workload-identity`, `mcp-client-configs`, `python`). `g8e_gateway_mcp_config_env.json` is gone; it described environment variables that the g8e binary does not read.
* **Tribunal Auditor model rename** — `protocol/models/agents/agent_harness.json` is now `auditor.json`: model `AgentHarness` becomes `Auditor`, id `agent_harness` becomes `auditor`, and the result `reason_enum` value `agent_harness_error` becomes `auditor_error`. Consumers of the JSON model registry must update. The g8e-native agent harness used by demos and evaluation scenarios is a separate concept and is unchanged.
* **System One decision provider targets local Ollama** — The `jev` decision provider now calls Ollama's local System One API (`POST /v1/systemone`) instead of the TypeSafe service. The `jev_endpoint` and `jev_api_key` settings are replaced by the Ollama endpoint and optional API key, no API key is required, and requests over the System One body limit fail before dispatch.
* **`gw reset` no longer preserves the CA** — It runs the same full cleanup as `gw clean` and starts a new gateway with a new trust domain; CLI credentials become invalid.
* **Destructive Clean Commands Confirm, Offer a Backup, and Archive `.g8e/`** — `g8e docker clean` no longer skips confirmation by default (its `--yes` flag now defaults to `false`, so scripts must pass `--yes`). `docker clean`, `docker reset`, `docker init --clean`, `gw clean`, and `gw reset` now confirm, then offer a backup of host evaluation evidence to `eval/backups/` before wiping; `--yes`/`--force` skips the confirmation (the backup still runs) and the new `--skip-backup` opts out. A failed backup aborts the clean. `gw clean` and `gw reset` no longer delete the runtime directory: they rename `.g8e` to `.g8e-<MMDDHHMM>` (new `RuntimeFileService.ArchiveRuntime`, INV-FS-10). `ProcessManager.Clean` now returns the archive path. Docker volumes cannot be archived and are still deleted outright.
* **Evaluation Runner Application Identity** — Evaluation runner (`./g8e eval runs start`, `formations smoke`, etc.) now presents the platform-enrolled `g8e-eval` application identity instead of attempting delegated self-enrollment or impersonating `g8ee`. On a missing or untrusted credential, it fails closed with an actionable error directing the operator to run `./g8e auth enroll app g8e-eval`.
* **Tool Selection Scenario Prompt Tightening (`tool-select-constraints`)** — Updated the `tool-select-constraints` scenario prompt to explicitly direct calling `get_command_constraints`, and added `ForbiddenTools: ["run_commands_with_operator"]` to isolate pure tool selection behavior. Expand catalog matrix to 26 scenarios across 9 behavior categories (39 scored assignments per homogeneous model).

### Fixed

* **Tool-selection grader required any expected tool, not all** — The deterministic `tool-selection` grade passed when any one of a scenario's expected tools was selected. It now fails unless every expected tool is selected and reports the full list on pass. Results graded before this release are not comparable for scenarios that declare more than one expected tool.
* **Governed inference rejected tool results containing `<`, `>`, or `&`** — The inference operator verifies canonical JSON by round-tripping through Go `encoding/json`, which escapes those characters (and U+2028/U+2029) inside strings, while ensemble's `_canonical_json` emitted them literally. Any governed model turn that carried such a character failed with `G8E-1700: inference: execution failed on inference node`. `get_command_constraints` always hit this because the default blacklist contains patterns such as `> /dev/sd` and the fork-bomb pattern. Ensemble now emits the same escaped form, which also fixes the reverse check on model tool-call arguments.
* **Stale generated artifacts** — `make proto` refreshed `common_pb2.py` and `protocol/docs/reference/api/g8e/common/v1/index.md`, which did not yet include `PLATFORM_COMPONENT_KIND_APPLICATION`, and `make swagger-generate` removed the `gateway.AppEnrollResponse` definition and `/api/v1/pki/apps/delegated` path that still described the removed endpoint.
* **Stale documentation** — Pinned install snippets (`go get`, `pip install`, wheel names) and the README version badge now match `VERSION`; the native MCP tool count is corrected to the 32 tools `RegisterNativeTools` registers; the unified stack campaign table reflects the 26-scenario, 39-assignment matrix; and `build_apps.md` describes platform application enrollment instead of the removed delegated endpoint.
