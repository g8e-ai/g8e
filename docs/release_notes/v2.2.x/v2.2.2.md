## [2.2.2] - 2026-09-27

### Overview

v2.2.2 is an evaluation model inventory management and Evaluation Explorer usability release. It adds `g8e eval models add`, `remove`, and `import` with parameter-count and family filtering, extends `g8e eval rollout init` and `g8e eval rollout run` with parameter-count scoping, expands the checked-in base inventory to 50 models, and registers three additional Ollama models in the ensemble model registry. Campaign publication batches assignment lifecycle records and publishes bounded `model_response` and `failure_output` text on public assignment records, which the Evaluation Explorer renders as a Model Response and failure diagnosis section. The Explorer also gains a navigation drawer, an assignment column and filter in the live stream, compact campaign progress, and an `exploratory_verified` default quality filter. The gateway clears the HTTP write deadline for inference dispatch, and the ensemble response `text` accessor now concatenates every non-thought text part. Release evidence preparation is now one command, `g8e compliance release-prepare`, and the Operator's automatic heartbeat no longer fabricates an L5 receipt and ledger commitment for a transaction that never passed L1 through L4.

### Added

* **Evaluation model inventory management** — Added `g8e eval models add` (insert or replace one variant and recompute the registry digest and homogeneous cell count), `g8e eval models remove` (delete by served tag or variant ID), and `g8e eval models import` (copy variants from a source inventory into the runtime freeze by tag, family, parameter count, or all). `add` and `remove` accept `--sync-base` to apply the change to both the checked-in and runtime inventories. Backed by `AddOrUpdateModelVariant`, `MergeModelVariants`, and `RemoveModelVariant` in `internal/services/evaluation/model_inventory.go`.
* **Parameter-count and family filtering** — Added `--max-parameters` (alias `--params`) to `g8e eval models list`, `g8e eval rollout init`, and `g8e eval rollout run`, `--family` and `--detailed` to `g8e eval models list`, and the `ParseParameterCount`, `FormatParameterCount`, `FilterVariantsByMaxParameters`, and `FilterVariantsByFamily` helpers.
* **Model response and failure output on public assignment records** — `PublicAssignmentRecordExtensions` carries optional `model_response` (the designated-role output from the assignment trace) and `failure_output` (the recorded error, failure output, or non-`stop` finish reason for an assignment that did not complete). The gateway public disclosure validator accepts both fields and rejects text over 256 KiB or containing `BEGIN PRIVATE KEY` or `spiffe://`; the Explorer contract validator checks only that each present field is a string.
* **Explorer Model Response section** — Assignment detail renders a Model Response section, with a failure diagnosis callout listing failing criteria and the missingness reason when an assignment did not complete.
* **Explorer navigation and stream controls** — Added a `NavDrawer` primary navigation, an Assignment column linking to assignment detail with abbreviated identifiers, an assignment filter, and sortable assignment ordering in the live event stream.
* **Release evidence preparation** — Added `g8e compliance release-prepare`, which derives the protected assessment scope from `VERSION`, git, the running Gateway image digest, and the assessment window; exports the bounded operational evidence for that window; builds the external report and source-evidence trust policies from the signing identity and the signer keys present in the exported evidence; generates a public bundle; verifies it offline; and projects the verified bundle into `docs/release_notes/vX.Y.x/`. It reuses an existing signing key (rejecting one outside its validity interval), creates one only with `--new-key`, and stops before projection when verification fails. Backed by `BuildReleaseAssessmentScope`, `CollectOperationalSignerKeys`, `BuildReleaseReportTrustPolicy`, `BuildReleaseEvidenceTrustPolicy`, and `GenerateReportSigningKey` in `internal/services/compliance/report/release_inputs.go` and `ReadOnlyOperationalEvidence.LatestCommitmentAt`.
* **Ensemble Ollama models** — Registered `gemma4:12b`, `granite4.2:8b`, and `granite4.2:3b` (native off/high thinking toggle, tool support, 131,072-token input window) in the ensemble model registry and protocol status constants.

### Changed

* **Base model inventory** — `eval/base-model-inventory.json` now lists 50 models (3,750 homogeneous cells), adding `gemma4:12b`, `glm-5.3-air`, and `qwen2.5:1b-rlcd`, with model family, parameter count, and quantization recorded per variant. `eval/rollout-intake-priority.json` is now empty.
* **Assignment lifecycle publication** — The campaign controller publishes queued assignment lifecycles through `PublishAssignmentLifecycles`, which emits one bounded feed batch per run instead of one publication per assignment.
* **Tool-selection scenario prompts** — Reworded the `tool-select-investigation`, `tool-select-file-read`, `tool-select-grep`, and `tool-select-constraints` scenario prompts to name the target resource or intent directly. Results recorded against the previous prompt text are not directly comparable.
* **Explorer presentation** — Campaign progress renders as a compact bottom bar with screen-reader status text, the Evaluations view defaults to the `exploratory_verified` quality filter (`all` remains selectable and is written explicitly to the URL), and the production build splits framework dependencies into a `vendor` chunk.
* **Automatic heartbeat** — `HeartbeatService.SendAutomatic` publishes the heartbeat directly and produces no receipt or ledger commitment. It previously hand-built a `VerifiedTransaction` and dispatched it through the L5 actuator, which recorded an `L5_EXECUTION` receipt and a commitment (about 3,800 a day per Operator) with no L1 through L4 stages. The `HeartbeatService` no longer holds an actuator; `SetActuator` is removed.
* **Protocol & package synchronization** — Protocol packages, Python packages (`protocol/python/pyproject.toml`, `protocol/python/g8e/__init__.py`), lockfiles (`protocol/python/uv.lock`, `ensemble/uv.lock`), and specification headers synchronized to `v2.2.2` / `2.2.2`.

### Fixed

* **Heartbeat evidence fails the protocol chain** — Any operational evidence window that contained an automatic heartbeat was rejected by the operational importer with "L4 verification stage is missing", because heartbeat receipts carried only persistence, commitment, and L5 stages. Heartbeats no longer produce receipts. Heartbeat receipts and commitments already in an existing runtime database remain there; select an assessment window after the upgrade.
* **Automatic heartbeat labeled as requested** — The automatic heartbeat reached the publisher through the request handler and was published with the `requested` type. It is now published with the `automatic` type.
* **Long-running inference dispatch** — `InferenceDispatchController.HandleDispatch` clears the per-response write deadline so a slow local model is not cut off by the server `WriteTimeout`.
* **Multi-part model text** — `GenerateContentResponse.text` in the ensemble returns all non-thought text parts of the first candidate joined together instead of only the first part.
* **Explorer long model output** — The Explorer campaign wire validator no longer applies the 128-byte generic string limit to `model_response` and `failure_output`, so multi-line model output renders instead of failing validation.
