## [1.1.9] - 2026-06-23

### Overview

v1.1.9 is a code review and cleanup release that addresses unfinished code sections discovered during audit and significant gaps found during testing. During review and testing, several partially implemented subsystems were identified — including auto-approval bypass, the intent grant/revoke mechanism, and the standalone token store — that had been left in an incomplete state. Major architectural gaps were also found: the L5 Actuator had no enforcement of zero standing privileges, state tiering between bound and observed data was missing, and CLI L3 notary verification lacked cryptographic proof binding. This release completes, corrects, or removes those subsystems and fills the gaps to right the ship.

### Breaking Changes

* **`auto_approved` Field Removed from `L3Metadata`** — The `auto_approved` boolean has been removed from the `L3Metadata` proto message. Deployments that relied on auto-approval for doctrine/consensus postures must now configure posture-appropriate L3 verification instead.
* **`GRANT_INTENT` and `REVOKE_INTENT` Action Types Removed** — The intent grant/revoke subsystem has been fully removed, including action types, events, proto messages, and tool result models. Any code referencing these will fail to compile.
* **`TokenStoreService` Replaced by `EncryptedKVAdapter`** — The standalone `token_store.db` and `TokenStoreService` have been removed. Token persistence now routes through the canonical gateway DB KV store via `EncryptedKVAdapter`.

### Added

* **Architecture Documentation** — Added new documentation covering transport-to-envelope identity binding and governance postures, and updated the transaction process documentation with detailed layer descriptions and component tables.

### Changed

* **Warden Verification Order** — The L4 Warden now verifies L2 (machine consensus) before L3 (human-presence), preserving the architectural invariant that the human's approval bond is spent only on transactions that have already cleared tribunal consensus.
* **Tribunal Deliberation Under Notary Posture** — The gateway now sends envelopes to the Tribunal for L2 deliberation under both consensus and notary postures, ensuring L2 signatures are collected before L3 human authorization is requested.
* **Gateway Start Config Refactor** — Refactored gateway startup functions to accept struct parameters instead of long parameter lists, improving readability and maintainability.
* **Token Persistence Consolidation** — Token storage now uses the `EncryptedKVAdapter` backed by the canonical gateway DB instead of a separate `TokenStoreService` with its own SQLite database.

### Fixed

* **Warden Order Bug** — Discovered during code review that L3 (human-presence) was being checked before L2 (consensus), violating the protocol ordering invariant (L1 → L2 → L3 → L4). The verification order has been corrected.
* **Proof Binding Circularity** — Found that L3 proof was included in the transaction hash computation, creating a circular dependency where L2 could not sign until the human had already acted. L3 proof is now intentionally excluded from the hash; tamper-evidence is provided at verification time instead.
* **Missing JIT Execution Capabilities** — Found during testing that the L5 Actuator had no enforcement of zero standing privileges. Added a just-in-time capability system where the Actuator mints a scoped, single-action, self-dissolving capability before execution and dissolves it immediately after. Capabilities bind action type, target resource, transaction hash, and expiry.
* **Missing Bound vs Observed State Tiering** — Found during testing that the canonical DB did not distinguish bound-state from observed-state data. Added a `state_tier` column to separate bound-state rows (included in the transaction freshness root) from observed-state rows (hashed separately for audit ledger chaining without churning in-flight envelopes). A migration automatically upgrades existing databases.
* **Missing Observed-State Root** — Found that observed-state entries had no tamper-evidence mechanism. The `StateRootService` now computes a separate observed-state root chained into the audit ledger, without gating transaction admission or breaking the bound root that in-flight envelopes depend on.
* **Missing Token Keymap Hash Binding** — Found that the UEI token keymap hash was not bound into the state root, allowing rehydration substitution after a transaction hash was computed to go undetected. The keymap hash is now bound into the bound state root, ensuring substitution produces a broken transaction rather than silent corruption.
* **Incomplete CLI L3 Verification** — Found during testing that CLI L3 notary verification relied solely on the mTLS certificate fingerprint without verifying the approver's actual signature. The notary now verifies the approver's Ed25519 signature against a stored public key.

### Removed

* **Auto-Approval (`acktheater`)** — Removed an unfinished auto-approval bypass that was never fully implemented: the `auto_approved` field from `L3Metadata` proto, auto-approval logic from the gateway transaction processor, and the bypass path in L3 posture verification.
* **Intent Grant/Revoke Subsystem** — Removed a partially implemented intent grant/revoke subsystem that was never completed: all intent-related action types, events, proto messages, tool result models, validation logic, and event-to-action mappings across the codebase and protocol definitions.
* **Standalone Token Store** — Removed the `TokenStoreService` implementation and its separate SQLite database, which was superseded by the canonical gateway DB. Associated configuration constants and path definitions were also removed; the `TokenStore` interface is retained as a thin contract.
* **Deprecated Integration Tests** — Removed legacy E2E and integration tests that required external infrastructure, to be replaced with proper Tier 1/2 unit tests.

### Test Coverage Impact

This release significantly improves test coverage for governance and verification components:
* **Warden Tests** — Decomposed monolithic warden tests into posture-specific test files covering consensus, doctrine, and notary verification paths.
* **Capability Tests** — Added comprehensive unit tests for JIT capability minting, verification, dissolution, expiry, and context extraction.
* **L3 Notary Tests** — Added unit tests covering CLI L3 verification paths including signature verification and public key validation.
* **L3 Proof Hash Exclusion** — Added tests verifying that L3 proof does not affect the transaction hash and that L1-only governance metadata does not change the hash.
