## [1.1.9] - 2026-06-23

### Overview

v1.1.9 is a core architecture realignment release that corrects the governance verification ordering, eliminates auto-approval bypass, introduces just-in-time execution capabilities, and separates bound vs observed state in the canonical database. This release also hardens CLI L3 notary verification with cryptographic proof binding, consolidates token persistence into the canonical KV store, and removes the deprecated intent grant/revoke subsystem.

### Breaking Changes

* **`auto_approved` field removed from `L3Metadata` proto**: The `bool auto_approved` field has been removed from `L3Metadata` in `common.proto`. Deployments that relied on auto-approval for doctrine/consensus postures must now configure posture-appropriate L3 verification instead. The gateway no longer auto-sets L3 metadata for any posture.
  ```proto
  // Before
  message L3Metadata {
    L3Proof proof = 1;
    bool auto_approved = 2;  // removed
  }

  // After
  message L3Metadata {
    L3Proof proof = 1;
  }
  ```

* **`GRANT_INTENT` and `REVOKE_INTENT` action types removed**: The intent grant/revoke subsystem (action types, events, proto messages, tool result models) has been fully removed. Any code referencing these action types or events will fail to compile. The `GrantIntentRequested`, `GrantIntentResult`, `RevokeIntentRequested`, and `RevokeIntentResult` proto messages have been removed from `operator.proto`.

* **`TokenStoreService` replaced by `EncryptedKVAdapter`**: The standalone `token_store.db` and `TokenStoreService` have been removed. Token persistence now routes through `gateway.EncryptedKVAdapter` backed by the canonical gateway DB (`g8e.db`) KV store. Existing `token_store.db` files are no longer read or written.
  ```go
  // Before
  tokenStore, err := storage.NewTokenStoreService(config, logger, vault)

  // After
  tokenStore := gateway.NewEncryptedKVAdapter(gatewayDB.KVStore, encryptionVault)
  ```

### Added

* **JIT Execution Capabilities**: New `internal/services/governance/capability.go` providing `Capability`, `MintCapability`, and `ContextWithCapability`. The L5 Actuator now mints a scoped, single-action, self-dissolving capability before execution and dissolves it immediately after, enforcing zero standing privileges. The capability binds:
  - Action type (what the holder may do)
  - Target resource (what the holder may act upon)
  - Transaction hash (cryptographic binding to the verified intent)
  - Expiry (inherited from the envelope's `ExpiresAt`)

  Downstream handlers can extract and verify the capability via `CapabilityFromContext(ctx)`.

* **Bound vs Observed State Tiering**: Added `state_tier` column to `kv_store` and `blobs` tables in the canonical gateway DB. Bound-state rows are included in the transaction freshness root; observed-state rows are hashed separately in `GetObservedStateRoot()` for audit ledger chaining without churning in-flight envelopes. A migration (`migrateStateTierColumns`) automatically adds the column to existing databases.

* **Observed-State Root**: `StateRootService` now computes a separate `calculateObservedStateRoot()` for observed-tier KV and blob entries. This root does NOT gate transaction admission; it is chained into the audit ledger so observed evidence is tamper-evident without breaking the bound root that in-flight envelopes depend on.

* **Token Keymap Hash Binding**: The UEI token keymap hash is now bound into the bound state root (§9 binding), ensuring rehydration substitution after a transaction hash was computed produces a broken transaction rather than silent corruption.

* **Cryptographic CLI L3 Verification**: CLI L3 notary now verifies the approver's Ed25519 signature against a stored public key, not just the mTLS certificate fingerprint. `ApprovalPublicKey` field added to `SuspendedTransaction` model and `handleCLIApproval` endpoint now requires `approval_public_key` in the request body.

* **Posture-Specific Warden Tests**: Decomposed monolithic `l4_warden_test.go` (525 lines reduced) into:
  - `l4_warden_consensus_test.go` (413 lines): consensus posture verification
  - `l4_warden_doctrine_test.go` (184 lines): doctrine posture verification
  - `l4_warden_notary_test.go` (318 lines): notary posture verification

* **Capability Unit Tests**: New `internal/services/governance/capability_test.go` (258 lines) with comprehensive coverage of minting, verification, dissolution, expiry, context extraction, and nil-safety.

* **L3 Notary Unit Tests**: New `internal/services/governance/l3_notary_test.go` (241 lines) covering CLI L3 verification paths including signature verification, public key validation, and error scenarios.

* **L3 Proof Hash Exclusion Test**: New `TestGenerateMessageID_L3ProofNotInHash` in `pkg/governance/types_test.go` verifying L3 proof does not affect the transaction hash, and that L1-only Governance metadata also does not change the hash.

* **Architecture Documentation**: New `docs/architecture/binding.md` (444 lines) covering transport-to-envelope identity binding. New `docs/architecture/postures.md` (250 lines) documenting governance postures. Updated `docs/architecture/transaction-process.md` with detailed layer descriptions, component table, and transaction flow.

### Changed

* **Warden Verification Order**: `verifyPosture` in `l4_warden.go` now verifies L2 (machine consensus) before L3 (human-presence). This preserves the architectural invariant: the human's approval bond is spent only on transactions that have already cleared tribunal consensus. A human should never be asked to authorize content the machines have not yet vetted.
  ```go
  // Before: L3 checked first, then L2
  l3Valid, err := tv.verifyL3Posture(ctx, envelope)
  l2Valid, err := tv.verifyL2Posture(envelope, computedHash)

  // After: L2 checked first, then L3
  l2Valid, err := tv.verifyL2Posture(envelope, computedHash)
  l3Valid, err := tv.verifyL3Posture(ctx, envelope)
  ```

* **Tribunal Deliberation Under Notary Posture**: The gateway now sends envelopes to the Tribunal for L2 deliberation under both consensus and notary postures (previously consensus only). This ensures L2 signatures are collected before L3 human authorization is requested.

* **Gateway Start Config Refactor**: `resolveStartConfig` and `runGatewayMode` refactored to accept struct parameters (`startConfig` / `GatewayStartConfig`) instead of long parameter lists, improving readability and maintainability.

* **Token Persistence Consolidation**: `G8eoService` now uses `gateway.NewEncryptedKVAdapter` for token storage instead of a separate `TokenStoreService` with its own SQLite DB. The `TokenStore` interface in `internal/services/storage/token_store.go` is retained as the shared contract.

* **Scrubbing Test Simplification**: Scrubbing service tests replaced real vault/tokenstore setup with `fakeTokenStore` in-memory implementation, reducing test complexity and eliminating filesystem dependencies.

### Fixed

* **Warden Order Bug**: Fixed verification ordering where L3 (human-presence) was checked before L2 (consensus), causing humans to be asked to authorize content the machines had not yet vetted. This violated the protocol ordering invariant (L1 → L2 → L3 → L4).

* **Proof Binding Circularity**: L3 proof is now intentionally excluded from `GenerateMessageID` transaction hash computation. Including L3 in the hash created a circular dependency: L2 could not sign until the human had already acted, violating the invariant that the human is never bothered until all machine-checkable layers pass. Tamper-evidence for L3 is provided by `verifyL3Posture`, which checks the proof against `envelope.TransactionHash` at verification time.

### Removed

* **Auto-Approval (`acktheater`)**: Removed `auto_approved` field from `L3Metadata` proto, auto-approval logic from gateway `processGatewayTransaction`, and auto-approval bypass in `verifyL3Posture`. The gateway no longer auto-sets `L3Metadata.AutoApproved = true` for doctrine/consensus postures.

* **Intent Grant/Revoke Subsystem**: Removed:
  - `ActionTypeGrantIntent` and `ActionTypeRevokeIntent` from `internal/constants/action_types.go`
  - All `EventOperatorIntent*` events from `internal/constants/events.go`
  - `GrantIntentRequested/Result` and `RevokeIntentRequested/Result` from `operator.proto`
  - Intent tool result models from `protocol/models/tool_results.json`
  - `GRANT_INTENT` and `REVOKE_INTENT` action type entries from `protocol/constants/status.json`
  - Intent validation from `TribunalMember.evaluateSafety` and `L1Doctrine`
  - Intent event-to-action mappings from `internal/mapping/mapping.go`

* **Standalone Token Store**: Removed `TokenStoreService` implementation (~280 lines), `TokenStoreConfig`, `TokenStoreDBFilename`, `TokenStoreDBPath` from constants, and `TokenStoreDBPath` from `internal/paths/paths.go`. The `TokenStore` interface is retained as a thin contract.

* **Deprecated Integration Tests**: Removed `byo_client_e2e_test.go` (368 lines), `gateway_integration_test.go` (365 lines), and `tribunal_consensus_test.go` (482 lines) to be replaced with proper Tier 1/2 tests that do not require external infrastructure.
