## [1.4.1] - 2026-07-12

### Overview

Patch release focused on release tooling and CI automation. Introduces a unified `make release` / `make release-tag` workflow that consolidates version syncing, testing, building, and git tagging into two commands. Adds a new binary release GitHub workflow triggered by `v*` tags and a CI version sync check that fails builds if Python package versions drift from `VERSION`.

### Added

* **`make release` target** — New Makefile target that auto-syncs `protocol/python/pyproject.toml` and `protocol/python/g8e/__init__.py` from `VERSION`, runs protocol tests, and builds binaries. Prints next-step instructions for committing and tagging. Does not touch git.
* **`make release-tag` target** — Replaces the old `make release-protocol` target. Verifies a clean working tree, confirms Python versions match `VERSION`, checks that tags don't already exist, then creates and pushes both `vX.Y.Z` and `protocol/vX.Y.Z` tags to trigger all three CI release workflows (binary, Go protocol, Python protocol).
* **Binary release workflow** — New `.github/workflows/release-binary.yml` triggered by `v*` tags. Builds all platforms via `make build-all` and creates a GitHub release with binary assets using `softprops/action-gh-release`.
* **CI version sync check** — New step in `.github/workflows/build-and-test.yml` that verifies `pyproject.toml` and `__init__.py` versions match `VERSION`. Fails CI on mismatch with a helpful message pointing to `make release`.

### Changed

* **`docs/devs/release_process.md`** — Comprehensive rewrite to reflect the new `make release` / `make release-tag` workflow. Replaces the old per-file manual checklist with a streamlined 7-step process. Documents the CI workflows triggered by each tag, the version sync check, and the hotfix procedure. Clarifies that only 2 files need manual version edits (VERSION + CHANGELOG) while Python files are auto-synced.
* **Makefile help text** — Updated release section to list `release` and `release-tag` instead of `release-protocol`.

### Removed

* **`make release-protocol` target** — Replaced by the unified `make release` + `make release-tag` workflow. The old target only handled protocol tag creation; the new workflow handles both binary and protocol tags in a single flow.
