## [2.1.0] - 2026-08-30

### Overview

v2.1.0 makes evaluation output and governance receipts independently auditable. It separates the evaluation harness into a locked standalone package, introduces explicit causal experiment arms and immutable evidence manifests, extends signed receipts with deterministic stage evidence and durable-persistence attestations, and adds matching Go/Python canonical verification. The release also tightens CLI, operator, and ensemble identity binding and fixes reliability issues discovered while exercising the full evidence pipeline.

### Added

* **Evidence-grade experiment arms** — Added typed `direct`, `ensemble_ungoverned`, `doctrine`, `consensus`, and `notary` arms so evaluations distinguish raw model behavior, ensemble orchestration, and incremental governance posture effects.
* **Immutable evaluation manifests and schemas** — Added versioned typed records for run configuration, source and dataset hashes, exact role-to-model mappings, sampling settings, stack metadata, independently observed posture, attempt outcomes, metrics, receipts, and evidence indexes. Invalid, incomplete, duplicated, cyclic, or unverifiable evidence fails closed.
* **Normalized stage telemetry** — Added per-stage observations across model inference, Tribunal generation and auditing, deterministic doctrine, protocol L2, L3 ceremony, L4 verification, L5 execution, receipt persistence, commitment append, and grading, with monotonic timing, provider usage, retries, model identities, artifact hashes, and usage reconciliation.
* **Encrypted restricted evidence** — Added AES-256-GCM envelopes for raw prompts and model outputs, authenticated immutable index metadata, owner-only key-file validation, content and ciphertext hashes, and explicit named-key-holder access policy.
* **Signed governance-stage evidence** — Extended `ActionReceipt` with typed deterministic stage evidence carrying transaction, identity, state, doctrine, signature-digest, commitment, audit-record, timing, and parent-stage bindings. Receipt signatures now bind the deterministic evidence hash.
* **Receipt persistence attestations** — Added a final Ed25519-signed attestation proving the receipt signature was durably associated with its audit record at a specific timestamp.
* **Cross-language receipt verification** — Added protocol-owned Python parsing, canonicalization, Ed25519 receipt verification, persistence-attestation verification, generated protobuf modules and `.pyi` stubs, and shared Go/Python canonicalization vectors.
* **Canonical CLI auth context** — Added `g8e auth context` to export the authenticated user, CLI session, operator, and operator session as typed JSON for eval and automation clients.
* **Gateway-authoritative operator binding validation** — Added `POST /api/v1/operators/validate`, which verifies the exact active operator-session, CLI-session, and user binding over app mTLS before g8ee accepts a request context.
* **Standalone eval quality gates** — Added separate locked dependencies, `make evals-test`, tier-specific eval test targets, `make evals-lint`, and a dedicated CI job for Ruff, Pyright, Tier 1, and Tier 2 tests.

### Changed

* **Production commitment pipeline** — L5 now builds and appends signed commitments against the current chain head under a SQLite write lock, records commitment linkage in receipt evidence, and fails closed when commitment or receipt persistence fails.
* **Canonical receipt storage and API output** — The audit store persists the complete protojson receipt in addition to searchable columns, migrates existing databases additively, and returns full canonical receipts through get, list, export, and since queries.
* **Evaluation benchmark provenance** — The IFEval subset now carries source provenance, deterministic verifier definitions, immutable input hashes, stage-normalized grading, and optional LLM-judge telemetry recorded separately from deterministic scores.
* **Model-provider evidence** — Anthropic, Gemini, Ollama, OpenAI, and fake providers now report normalized token usage, finish state, retries, monotonic timing, and canonical model-boundary hashes without fabricating unavailable usage.
* **Reputation event publication** — g8ee publishes typed reputation updates through the same authenticated session-event path used by the rest of the ensemble, preserving request context and protocol event names.
* **Evidence report verification** — Reporting now verifies commitment ordering and signatures, structured attestation columns, receipt signatures and persistence attestations, receipt-to-commitment cross-links, mutation linkage, and Git Merkle roots.
* **Headless full-stack runbook** — Expanded the UX smoke test with clean-state startup, container FIPS verification, direct service probes, governed file and document mutations, receipt export assertions, non-empty evidence checks, binary identity checks, and optional KSI/OSCAL evidence export.
* **Dependency and CI maintenance** — Updated pinned Python and dashboard dependencies, strengthened lint and CodeQL coverage, and moved generated Python protobuf checking into the protocol workflow.

### Fixed

* **Concurrent governance submissions** — Serialized g8ee envelope submission and state-root retry handling so concurrent application mutations do not race against stale Merkle roots.
* **Commitment-chain concurrency** — Replaced timestamp-based head selection with insertion-order chaining under an immediate SQLite transaction, preventing concurrent ledger instances from selecting the same prior commitment.
* **CLI refresh rebinding** — CLI session refresh now verifies that an inherited operator session is still active and rebinds to the user's current active operator instead of preserving a terminated session.
* **Certificate-backed CLI recovery** — CLI authentication accepts a refreshed session identifier only when the certificate fingerprint and embedded user identity still match, while retaining fail-closed session and expiry checks.
* **Duplicate operator sessions** — Operator-session validation rejects duplicate active matches instead of accepting the first database result.
* **Governed document updates** — Corrected partial document merge behavior and receipt correlation so governed updates preserve untouched fields and remain observable through audit queries.
* **Dashboard hardening** — Corrected documentation-route rate-limit classification, operator URL and slot handling, and markdown link sanitization.
* **Ensemble governance serialization** — Corrected protobuf-to-protojson conversion for governed submissions, normalized action mappings, and ensured typed receipt and reputation payloads are published without lossy ad hoc serialization.

### Tests

* Added canonical Go/Python receipt vectors and tests for receipt signatures, deterministic stage evidence, persistence attestations, audit-store round trips, commitment concurrency, report verification, and API serialization.
* Added standalone eval coverage for arm definitions, auth bridging, posture observation, encrypted evidence, immutable manifests, schema validation, receipt collection, stage normalization, provider telemetry, direct-provider isolation, and invalid-evidence rejection.
* Expanded gateway, CLI, ensemble, dashboard, and unified-stack tests for session binding, refresh behavior, governance identity, document updates, reputation publication, rate limiting, and full-stack configuration.
