## [2.1.6] - 2026-09-07

### Overview

v2.1.6 advances the bounded README evidence from Stage 1 to Stage 2 by retaining the complete v2.1.5 diagnostic as its original Stage 1 baseline and adding one fresh, separately invoked complete five-task reproduction. The reproduction is checksum-bound to a versioned campaign profile, deterministic source inclusion manifest and state hash, executable component digests, Docker image digests, and public runtime environment identities. The comparison includes both complete populations and makes no causal, statistical, governance, compliance, certification, or production-suitability claim.

### Added

* **Stage 2 publication schema** — Added publication schema `3.0.0` with typed, checksum-bound `campaign-profile.json`, `provenance.json`, and `comparison.json` artifacts plus explicit `stage1` and `stage2` run maturity labels.
* **Deterministic source and runtime provenance** — Added `scripts/collect_readme_provenance.py` to derive a canonical source inclusion manifest and root hash from an explicit relative-path scope and to bind component, image, operating system, architecture, hardware, Python, and container-runtime identities.
* **Complete-population reproduction comparison** — Added direct task-level bindings from both five-task populations to each run's terminal attempt and deterministic `ifeval_subset_verifier` metric.
* **Digest-bound promotion** — Added `scripts/promote_readme_evidence.py` to validate a candidate, require the exact release-owner-approved canonical tree SHA-256, verify staged and installed trees, and restore the prior snapshot if installation fails.
* **Stage 2 README rendering** — Added bounded provenance and comparison language, baseline and reproduction maturity labels, links to all Stage 2 source artifacts, complete-population results, and explicit same-local-environment and noncausal caveats.

### Changed

* **Two-run projection** — Extended `scripts/project_readme_evidence.py` to combine the promoted v2.1.5 Stage 1 baseline, one new immutable private report, and one deterministic provenance record without rewriting or relabeling the baseline artifacts.
* **Reproduction manifest binding** — Stage 2 reproduction manifests bind the campaign-profile digest, source-state digest, component digests, image digests, and complete public environment record to the fresh run.
* **Release process** — Added attended Stage 2 provenance collection, fresh-run, projection, review, exact-digest approval, promotion, and CI-separation instructions.
* **v2.1.6 installation guidance** — Updated current Go module and Python package installation callouts to v2.1.6 and synchronized the platform and protocol Python package versions.

### Security

* **Fail-closed provenance validation** — Stage 2 rejects absolute, escaping, duplicate, symlinked, empty, and malformed source inputs; inconsistent profile or source hashes; absent component or image evidence; incomplete environment identities; and reproduction-manifest provenance drift.
* **Fail-closed comparison validation** — Stage 2 rejects incomplete or selected-only populations, duplicate tasks, incorrect attempt or metric bindings, fake providers, baseline maturity relabeling, unsupported causal or statistical claims, invalid checksums, undeclared files, restricted fields, exact endpoints, private topology, and machine-specific absolute paths.
* **Exact review binding** — Candidate approval applies only to the canonical tree digest reviewed by the release owner. Projection refuses existing destinations, and promotion leaves the current snapshot unchanged when the approved digest does not match.

### Notes

* The original v2.1.5 run remains Stage 1. Stronger source, component, image, and environment provenance applies only to the fresh v2.1.6 reproduction.
* Separate invocation and run state establish independent execution state on the same local operator environment. They do not establish independent hardware, organizational control, trust roots, or external audit.
* Two complete five-task populations do not establish causal attribution, statistical significance, broad instruction-following quality, governance effectiveness, compliance, certification, or production suitability.
* Answer-only runs with zero receipts continue to support no receipt, mutation, persistence, state, governance, or compliance claim.
