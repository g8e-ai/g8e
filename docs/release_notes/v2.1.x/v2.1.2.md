## [2.1.2] - 2026-08-31

### Overview

v2.1.2 adds the `ratify` governance posture for deployments that require L1 doctrine and L3 human authorization while retaining L2 results as non-gating audit evidence. It also makes evaluation results authoritative against signed governance receipts and adds privacy-boundary, exact local rehydration, secret-detection, and independently observed state evidence. The evaluation evidence schema advances to 1.17.0 with typed expectations and source-bound observations.

### Added

* **Ratify governance posture** — Added `ratify` as a fourth gateway posture: L1 and L3 are enforced, while L2 is audited. The posture is supported by gateway startup and restart, persisted posture validation, the interactive configuration wizard, MCP and A2A approval responses, L4 verification, readiness checks, dependency construction, route registration, protocol references, and user documentation.
* **Capability-based posture requirements** — Centralized L2 and L3 requirements in `GovernancePostureRequirements` and added `GatewayPosture.RequiresL2`, `GatewayPosture.RequiresL3`, and `GovernancePostureMeetsFloor`. Lattice posture floors now compare required governance capabilities rather than assuming that all postures form a single linear rank.
* **Authoritative deterministic graders** — Added versioned graders for receipt integrity, deterministic protocol-chain validity, signed policy allow/block outcomes, precise L1-L4 rejection layers, receipt-bound final state, independently observed state, canary scrubbing, model-boundary raw-secret rates, secret-detection precision and recall, and exact local rehydration.
* **Receipt-bound final-state observations** — Added typed `FinalStateAssertion` and `FinalStateObservation` records for `state_root_changed` and `state_root_unchanged` predicates. Eval runs correlate receipts by transaction or investigation and action type, write `final-state-observations.jsonl`, and link every observation and grade back to its verified source receipt.
* **Privacy-safe model-boundary telemetry** — Model providers now record a hash-bound attestation containing scanner version, sensitive-occurrence counts, and detected types for each outbound model payload without retaining raw sensitive values in analytical telemetry.
* **Canary scrubbing evidence** — Added hash-only canary annotations and deterministic grading that binds expected occurrences and types to normalized scrubbing-stage input and output hashes.
* **Observer-backed evidence contracts** — Added typed state fixture, rehydration, and secret-detection assertions plus injectable `SUTConfig` observer protocols. Configured observers write `state-observations.jsonl`, `rehydration-observations.jsonl`, and `secret-detection-observations.jsonl`; deterministic graders bind observations to attempts, fixtures, hashes, execution boundaries, and restricted source evidence. The standard `g8e-evals run` command does not construct these integration-specific observers.
* **Policy expectation metadata** — IFEval task metadata now accepts typed expected action classes, final-state assertions, allow/block outcomes, rejection layers, canary annotations, state fixtures, rehydration assertions, and secret-detection assertions. Validation rejects duplicate assertion IDs and inconsistent expectations before a run begins.

### Changed

* **Evaluation evidence schema 1.17.0** — Advanced the schema from 1.10.0 to 1.17.0. `TaskDefinition` now carries typed receipt-bound and observer-backed expectations; `AttemptRecord` links multiple final-state, state, rehydration, and secret-detection observations; model stages carry privacy attestations; and policy outcomes and rejection layers are enums.
* **Authoritative governance rejection classification** — A verified primary receipt with a failed signed L4 stage now classifies the attempt as `governance_rejected`, even when transport-level response text is unavailable. Missing or inconsistent authoritative evidence produces failed verification rather than an inferred score.
* **Posture-aware consensus construction** — Consensus services, policy warnings, readiness requirements, and `/consensus/v1/deliberate` route registration are now driven by whether the posture requires L2. Doctrine and ratify do not require consensus construction or expose the deliberation route.
* **Posture-aware approval guidance** — CLI next-step output and MCP/A2A suspension messages identify the active L3-enforcing posture instead of describing all approval requests as notary-only.

### Fixed

* **Audited L2 failures no longer gate ratify** — Duplicate or otherwise invalid L2 evidence remains visible as a failed audit result when L2 is optional, but it no longer prevents valid L3 authorization from proceeding under ratify. L2 failures continue to reject transactions under consensus and notary.
* **Non-linear posture floor checks** — Ratify no longer incorrectly satisfies a consensus floor, and consensus no longer incorrectly satisfies a ratify floor. Notary satisfies both because it enforces both L2 and L3.
* **Documentation posture inventory** — Reconciled architecture, protocol, security, setup, troubleshooting, compliance, and glossary documentation with posture-dependent enforcement, optional audit evidence, and the four supported gateway postures.
* **CLI coverage threshold enforcement** — `g8e test coverage` now delegates to the canonical Makefile target so package and file exclusions remain single-sourced and the documented 75% threshold is enforced instead of reporting an unfiltered percentage and returning success unconditionally.

### Security

* **Fail-closed evidence grading** — Deterministic grades require unique, verified, internally consistent source evidence. Missing persistence evidence, posture mismatches, duplicated stages, invalid stage ordering, identity drift, state-root mismatches, ambiguous rejection layers, unsupported scanner or rehydrator versions, unbound source evidence, and inconsistent counts or hashes fail verification.

### Documentation

* **Dashboard documentation** — Added a component documentation set covering g8ed architecture, workload enrollment, browser authentication, gateway integration, operator surfaces, SSE behavior, development, and tests; reconciled the platform architecture and frontend guides with the independently enrolled dashboard identity.

### Migration Notes for Evaluation Consumers

* Consumers of evidence bundles must support schema `1.17.0`, read the four observation JSONL files, treat the corresponding `AttemptRecord` reference fields as lists, and parse typed policy, privacy, state, rehydration, and secret-detection expectations. Schema 1.10.0 through 1.16.0 readers must reject 1.17.0 bundles rather than partially interpreting them.
* Integrations using state, rehydration, or secret-detection assertions must inject the corresponding observer into `SUTConfig`; without an observer, the deterministic grader records failed verification instead of inferring evidence from the system under test.

### Tests

* Added comprehensive deterministic-grader tests covering verified and rejected protocol chains, signature and persistence failures, posture mismatches, stage identity and ordering errors, policy outcomes and rejection layers, receipt correlation, receipt-bound state roots, canary scrubbing, model-boundary privacy, independently observed state, secret-detection precision and recall, and exact local rehydration.
* Expanded Go tests for ratify posture parsing, wizard behavior, persisted posture handling, capability-based Lattice floors, L2-optional dependency construction, L4 acceptance of valid L3 authorization with absent or invalid audited L2 evidence, and coverage-command delegation and failure propagation.
