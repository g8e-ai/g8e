## [2.1.2] - 2026-08-31

### Overview

v2.1.2 adds the `ratify` governance posture for deployments that require L1 doctrine and L3 human authorization while retaining L2 results as non-gating audit evidence. It also makes evaluation results authoritative against signed governance receipts through deterministic receipt-integrity, protocol-chain, policy-outcome, rejection-layer, and final-state grading. The evaluation evidence schema advances to 1.12.0 with typed expectations and receipt-bound final-state observations.

### Added

* **Ratify governance posture** — Added `ratify` as a fourth gateway posture: L1 and L3 are enforced, while L2 is audited. The posture is supported by gateway startup and restart, persisted posture validation, the interactive configuration wizard, MCP and A2A approval responses, L4 verification, readiness checks, dependency construction, route registration, protocol references, and user documentation.
* **Capability-based posture requirements** — Centralized L2 and L3 requirements in `GovernancePostureRequirements` and added `GatewayPosture.RequiresL2`, `GatewayPosture.RequiresL3`, and `GovernancePostureMeetsFloor`. Lattice posture floors now compare required governance capabilities rather than assuming that all postures form a single linear rank.
* **Authoritative deterministic graders** — Added versioned graders for receipt integrity, deterministic protocol-chain validity, signed policy allow/block outcomes, precise L1-L4 rejection layers, and final-state assertions. Graders bind transaction IDs, action classes, identities, posture observations, stage ordering and parentage, execution status, state roots, receipt persistence, and cryptographic verification before evidence is eligible.
* **Receipt-bound final-state observations** — Added typed `FinalStateAssertion` and `FinalStateObservation` records for `state_root_changed` and `state_root_unchanged` predicates. Eval runs correlate receipts by transaction or investigation and action type, write `final-state-observations.jsonl`, and link every observation and grade back to its verified source receipt.
* **Policy expectation metadata** — IFEval task metadata now accepts typed expected action classes, final-state assertions, allow/block outcomes, and rejection layers. Validation rejects duplicate assertion IDs and inconsistent policy expectations before a run begins.

### Changed

* **Evaluation evidence schema 1.12.0** — Advanced the schema from 1.10.0 to 1.12.0. `TaskDefinition.expected_final_state_assertions` is now a list of typed assertions, policy outcomes and rejection layers are enums, and `AttemptRecord.final_state_observation_ref` is replaced by `final_state_observation_refs` to support multiple assertions.
* **Authoritative governance rejection classification** — A verified primary receipt with a failed signed L4 stage now classifies the attempt as `governance_rejected`, even when transport-level response text is unavailable. Missing or inconsistent authoritative evidence produces failed verification rather than an inferred score.
* **Posture-aware consensus construction** — Consensus services, policy warnings, readiness requirements, and `/consensus/v1/deliberate` route registration are now driven by whether the posture requires L2. Doctrine and ratify do not require consensus construction or expose the deliberation route.
* **Posture-aware approval guidance** — CLI next-step output and MCP/A2A suspension messages identify the active L3-enforcing posture instead of describing all approval requests as notary-only.

### Fixed

* **Audited L2 failures no longer gate ratify** — Duplicate or otherwise invalid L2 evidence remains visible as a failed audit result when L2 is optional, but it no longer prevents valid L3 authorization from proceeding under ratify. L2 failures continue to reject transactions under consensus and notary.
* **Non-linear posture floor checks** — Ratify no longer incorrectly satisfies a consensus floor, and consensus no longer incorrectly satisfies a ratify floor. Notary satisfies both because it enforces both L2 and L3.
* **Documentation posture inventory** — Reconciled architecture, protocol, security, setup, troubleshooting, compliance, and glossary documentation with posture-dependent enforcement, optional audit evidence, and the four supported gateway postures.

### Security

* **Fail-closed evidence grading** — Deterministic grades require a unique verified primary receipt and internally consistent signed stage evidence. Missing persistence evidence, posture mismatches, duplicated stages, invalid stage ordering, identity drift, state-root mismatches, ambiguous rejection layers, and unsupported grader versions fail verification.

### Migration Notes for Evaluation Consumers

* Consumers of evidence bundles must support schema `1.12.0`, read `final-state-observations.jsonl`, treat `AttemptRecord.final_state_observation_refs` as a list, and parse typed final-state assertions, policy outcomes, and rejection layers. Schema 1.10.0 readers must reject 1.12.0 bundles rather than partially interpreting them.

### Tests

* Added comprehensive deterministic-grader tests covering verified and rejected protocol chains, signature and persistence failures, posture mismatches, stage identity and ordering errors, policy outcomes and rejection layers, receipt correlation, and receipt-bound state-root assertions.
* Expanded Go tests for ratify posture parsing, wizard behavior, persisted posture handling, capability-based Lattice floors, L2-optional dependency construction, and L4 acceptance of valid L3 authorization with absent or invalid audited L2 evidence.
