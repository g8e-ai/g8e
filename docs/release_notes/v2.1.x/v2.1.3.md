## [2.1.3] - 2026-09-02

### Overview

v2.1.3 introduces the protocol-owned foundation for proof-backed compliance reporting and turns evidence-grade demo scenarios into persisted, independently verifiable evidence runs. Canonical compliance catalogs, typed assessment and evidence records, content-addressed artifacts, and fail-closed validation bind compliance claims to explicit scope, provenance, verifier identity, and framework controls. A new read-only CLI verifier checks persisted demo evidence without mutating assessed state.

### Added

* **Protocol-owned compliance evidence model** — Added typed protobuf records for control assertion and framework catalogs, crosswalks, assessment scope, content-addressed evidence references, assertion and framework-control assessments, report manifests, verification reports, demo manifests, scenario definitions, step results, and scenario results. Client-facing serialization uses canonical protojson.
* **Canonical compliance catalogs** — Added digest-verified control assertion, framework, crosswalk, and demo scenario catalogs with validation for versions, references, evidence levels, responsibilities, mappings, assessment semantics, and supported graders and verifiers.
* **Persisted demo evidence runs** — Evidence-grade demos now persist a typed manifest and canonical scenario results under the runtime compliance evidence tree. Run manifests bind scenario definitions, framework controls, supported execution lanes, required environment, and SHA-256 provenance for the demo compose file, doctrine, target data, and configuration.
* **Content-addressed demo artifacts** — Demo runs persist canonical action receipts, final-persistence attestations, and state observations under SHA-256-addressed paths. Scenario and step records carry resolvable references to those artifacts.
* **Independent demo-run verification** — Added `g8e compliance demo-run verify <run-id>` with an optional `--project-root` override. The command emits a typed `ComplianceVerificationReport` as canonical JSON and returns nonzero for an invalid report.

### Changed

* **Evidence-grade demo results** — Evidence-grade scenarios use protocol-owned `DemoScenarioResult` and `DemoStepResult` records that bind run, scope, scenario, transaction, receipt, protocol-chain, state-observation, assertion, and framework-control identities instead of relying only on terminal summaries.
* **Compliance evidence validation** — Compliance artifacts are validated against canonical catalogs and explicit assessment scope. Cross-scope references, unresolved or duplicate references, malformed digests and paths, unsupported verifier versions, invalid timestamps, stale or incomplete evidence, and inconsistent assessment outcomes are rejected.

### Security

* **Fail-closed evidence verification** — Demo-run verification independently checks manifest provenance, artifact checksums, canonical record structure, run and scope correlation, receipt and persistence signatures, deterministic-stage protocol chains, state-observation bindings, and artifact-directory integrity. Missing, malformed, duplicated, unexpected, or unresolvable evidence invalidates the report.

### Notes

* Full proof-backed compliance report bundle generation is not yet exposed through the CLI. The new verifier covers persisted demo evidence runs; the existing live KSI evaluation remains separate.
