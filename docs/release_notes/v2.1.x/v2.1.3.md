## [2.1.3] - 2026-09-02

### Overview

v2.1.3 introduces the protocol-owned foundation for proof-backed compliance reporting and turns evidence-grade demo scenarios into persisted, independently verifiable evidence runs. Canonical compliance catalogs, typed assessment and evidence records, content-addressed artifacts, and fail-closed validation bind compliance claims to explicit scope, provenance, verifier identity, and framework controls. A new read-only CLI verifier checks persisted demo evidence without mutating assessed state.

### Added

* **Protocol-owned compliance evidence model** — Added typed protobuf records for control assertion and framework catalogs, crosswalks, assessment scope, content-addressed evidence references, assertion and framework-control assessments, report manifests, verification reports, demo manifests, scenario definitions, step results, and scenario results. Client-facing serialization uses canonical protojson.
* **Canonical compliance catalogs** — Added digest-verified control assertion, framework, crosswalk, and demo scenario catalogs with validation for versions, references, evidence levels, responsibilities, mappings, assessment semantics, and supported graders and verifiers. The initial catalogs are versioned independently and shipped through the Go and Python protocol packages.
* **Persisted demo evidence runs** — Healthcare, finance, DHS, and FedRAMP demo runs now persist a typed manifest and canonical scenario results under `.g8e/data/compliance/demo-evidence/<run-id>/`. Run manifests bind scenario definitions, framework controls, automated and supported manual-notary execution lanes, required environment, and SHA-256 provenance for the demo compose file, doctrine, target data, and configuration.
* **Content-addressed demo artifacts** — Demo runs persist canonical action receipts, final-persistence attestations, state observations, and typed metric evidence under SHA-256-addressed paths. Scenario and step records carry resolvable references to those artifacts.
* **Typed metric evidence** — Healthcare gold-card and SLA scenarios persist protocol-owned threshold evaluations bound to the exact run, scope, scenario, source observation, subject, measured value, threshold, unit, registered `healthcare-threshold` grader, reproduced result, and evaluation time.
* **Independent demo-run verification** — Added `g8e compliance demo-run verify <run-id>` with an optional `--project-root <dir>` override for source-provenance lookup. The read-only command emits a typed `ComplianceVerificationReport` as canonical JSON and returns nonzero for an invalid report.
* **Sovereignty Gauntlet runbook** — Added a bounded evidence and publication runbook covering unified-stack proofs, FedRAMP and DHS demonstrations, eval evidence, artifact retention, claim gates, and the distinction between implemented demo verification and planned complete-bundle verification.

### Changed

* **Evidence-grade demo results** — Evidence-grade scenarios use protocol-owned `DemoScenarioResult` and `DemoStepResult` records that bind run, scope, scenario, attempt, execution, transaction, investigation, receipt, protocol-chain, state-observation, assertion, and framework-control identities instead of relying only on terminal summaries. Demo runs print the complete result set and exit nonzero when any scenario fails.
* **Governed MCP receipt correlation** — MCP `tools/call` accepts caller-supplied execution and investigation IDs, returns authoritative signed receipt references for completed calls and failed L1/L2 stages, and carries resumed receipt identity in human-approval completion events. The demo harness retains those identities, resolves canonical receipt and persistence bodies, and grades deterministic protocol chains without synthetic fallback references.
* **Demo target-state evidence** — Healthcare now uses a typed secure-network actuator for run-bound gold-card and SLA outcomes. Finance, DHS, and FedRAMP scenarios add independent target-state, persistence, network-membership, or protected-artifact collectors so terminal claims are measured rather than inferred from command output.
* **Multi-signer eval receipt verification** — `g8e-evals verify-receipts` loads all actuator public keys in the verifier PKI directory, derives their key IDs, selects the key matching each receipt, and fails when no key matches. This supports unified-stack reports containing Gateway- and Operator-signed receipts.
* **Operational status and TUI behavior** — `g8e gw status` reports both the localhost Gateway and Docker Compose stack. The TUI diagnoses Docker gateway state when its configured endpoint is unreachable, suppresses duplicate usage output on errors, and records machine-observable scenario success, failure, and cancellation checkpoints.
* **Compliance evidence validation** — Compliance artifacts are validated against canonical catalogs and explicit assessment scope. Cross-scope references, unresolved or duplicate references, malformed digests and paths, unsupported verifier versions, invalid timestamps, stale or incomplete evidence, and inconsistent assessment outcomes are rejected.

### Fixed

* **Platform enrollment under enforced consensus** — Bootstrap enrollment actions no longer require an L2 tribunal that does not yet exist. Supplied votes are still verified and audited, while non-bootstrap mutations continue to enforce the configured posture.
* **Trusted signer and receipt relay verification** — The signer lookup endpoint returns enabled keystore-backed signer material when a metadata document is absent, and the Gateway receipt relay now verifies both the canonical receipt signature and final persistence attestation before accepting a receipt.
* **Protocol package licensing** — Replaced the stale protocol license text with the repository's Business Source License 1.1 terms and Apache 2.0 change license.
* **Release version synchronization** — CI and `make release` now validate and synchronize the editable `g8e` entry in `protocol/python/uv.lock` alongside `VERSION`, `pyproject.toml`, and `g8e.__version__`, preserving locked Python environments during release preparation.

### Security

* **Fail-closed evidence verification** — Demo-run verification independently checks manifest provenance, artifact checksums, canonical record structure, run and scope correlation, receipt and persistence signatures, deterministic-stage protocol chains, state-observation bindings, metric source and grader bindings, reproduced threshold results, and artifact-directory integrity. Missing, malformed, duplicated, unexpected, or unresolvable evidence invalidates the report.

### Tests

* **Compliance contracts and tamper detection** — Added Go and Python canonicalization coverage, catalog digest and reference contracts, manifest and scenario persistence tests across all four demos, healthcare metric evidence tests, and verifier cases for malformed, missing, duplicated, cross-scope, stale, unsigned, checksum-mismatched, or unexpected artifacts.
* **Regression coverage** — Added coverage for multi-signer eval verification, authoritative MCP and approval receipt handoff, execution and investigation ID propagation, protocol-chain grading, bootstrap consensus behavior, Gateway relay verification, demo TUI completion, target-state collectors, and scenario failure exit status.

### Notes

* Full proof-backed compliance report bundle generation is not yet exposed through the CLI. The new verifier covers persisted demo evidence runs; the existing live KSI evaluation remains separate.
* The typed OSCAL model remains in the compliance package, but the superseded flat live-state OSCAL export command is not exposed by `g8e compliance`.
