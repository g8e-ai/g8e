## [2.1.12] - 2026-09-23

### Overview

v2.1.12 is an evaluation evidence, compliance reporting, public projection, workload lifecycle, runtime file ownership, and binary distribution release. It advances the Evaluation Explorer contract to schema 1.5.0 headline metrics with population-bound verification metadata, adds protected scope-driven compliance bundles with independent offline replay, introduces governed Operator stop and platform enrollment revocation, hardens the gateway-owned public spectator deployment, repairs organization-bound platform identities, makes size-ordered campaign inventory materialization deterministic and immutable, and adds provenance-bearing cross-platform binary manifests with checksum-verified bootstrap downloads. Live acceptance covers two fresh 75-assignment campaigns on the qualified four-Operator topology; it does not claim completion of the broader 45-model rollout or replace the separately required signed compliance bundle and release projections.

### Added

* **Typed Evaluation Explorer headline metrics** — Campaign summaries expose pass rate, latency p50, and output-throughput p50 with explicit units, applicability, observed/eligible/unavailable contributor counts, unavailable reasons, and population-bound verifier metadata under view schema 1.5.0.
* **Bound verification projection** — Passing and failing campaign reports bind report and population digests, verifier versions, and verification time into aggregate, completion, catch-up, export, bootstrap, history, snapshot, and SSE projections.
* **Organization-backed enrollment identity** — User creation persists the canonical single-user organization and membership, while Operator issuance resolves that membership and binds organization and user identities into Operator and companion CLI certificates, documents, and sessions.
* **Size-ordered rollout inventories** — `g8e eval rollout init` orders typed model variants by ascending parameter count with deterministic tag and variant tie-breakers and materializes immutable per-model inventory freezes.
* **Protected compliance assessment bundles** — Compliance report generation now admits sources through a canonical protected `AssessmentScope`, supports typed operational evidence packages, defaults to a restricted profile, and can produce a public profile only when every admitted source is explicitly public. Offline verification reproduces protected sources, analysis, and profile-aware renderers against report-signing trust supplied outside the bundle, plus distinct source-evidence trust when the represented sources require it.
* **Governed workload lifecycle controls** — `g8e operator stop <operator-session-id>` sends a session-bound governed shutdown and records `stopped` only after the correlated acknowledgement. `g8e auth enroll revoke <request-id>` permanently revokes a completed Operator, dashboard, or ensemble enrollment and invalidates its certificates, sessions or policy, and active pub/sub channels.
* **Operational evidence exchange** — `g8e compliance evidence export` emits bounded read-only operational source packages, and report generation accepts repeatable `--source` inputs admitted by the protected assessment scope.
* **Catalogued deployment binaries** — `make build-all` derives its seven supported targets from one typed catalog, emits portable SHA-256 sidecars, and publishes `g8e-binaries.json` only after the complete matrix validates. The Gateway serves only manifest-listed executables and sidecars from an explicitly validated artifact root.

### Changed

* **Campaign aggregate ownership** — `CollectRunAggregateState` derives all schema-1.5.0 metrics from canonical assignment results, and fresh campaign export persists the same projector-owned `evaluation_summary.json` used by publication instead of implementing a second aggregation path.
* **Verification monotonicity** — Later unverified aggregate revisions retain an applicable bound `passed` or `failed` state and metadata. Malformed or population-mismatched persisted reports fail closed instead of publishing a downgrade.
* **Public mirror topology** — Unified Compose binds private ingest, anonymous public read, and Evaluation Explorer host ports to loopback; trusts only the fixed Docker bridge gateway CIDR for a single valid unicast `CF-Connecting-IP`; raises the Gateway file-descriptor limit to 16,384; and uses `unless-stopped` recovery without deleting mirror state.
* **Public-feed reconstruction** — Gateway integration coverage compares canonical completion and verification projections with signed mirror history, bootstrap, snapshot, and SSE replay, while Explorer reconstruction preserves unavailable-only metrics without inventing numeric zeroes.
* **Campaign source discipline** — The recorded live campaign acceptance uses the fresh append-only `v2-1-12-size-ordered-20260923` publication generation. Interrupted runs from archived sources remain diagnostic evidence and are not relabeled or resumed. This publication source is separate from the compliance assessment scope.
* **Compliance decision model** — Assertion catalog v2.0.0 makes applicability, selected populations, evidence levels, specialized graders, trust, freshness, and unavailable outcomes explicit. The report bundle carries deterministic JSON, CSV, Markdown, HTML, OSCAL, and framework projections without treating a source import as assertion satisfaction.
* **Evaluation topology contracts** — Typed execution topologies describe Data, Inference, Observer, and Provenance formations and validate exact session capabilities before campaign work. The native boundary suite now names its ephemeral networkless fixture reader separately from the remote model-campaign Observer Operator.
* **Genesis program inventory** — The checked-in baseline expands from 35 to 45 model variants and the rollout queue preserves deterministic size ordering while keeping runtime provider freezes and rollout state under `.g8e/eval/`.
* **Tier 1 test delegation** — `./g8e test unit` delegates to `make test-unit`, aligning CLI and Makefile package selection and settings.
* **Runtime file ownership** — Gateway, reporting, evaluation, pub/sub, vault, keystore, consensus, governance, inference, storage, and CLI runtime paths now flow through explicitly injected `RuntimeFileService` instances and canonical relative constants. Source-tree, Docker, target-workspace, model-storage, and user-selected external paths remain explicit non-runtime boundaries.
* **Target-aware container builds** — The root Dockerfile builds only the selected Linux image target, stamps matching OCI provenance labels, and copies that executable to `/g8e`. Managed `docker init`, `docker build`, and `docker rebuild` publish the built image's runtime binary back to the repository root and fail before startup or success reporting when publication fails.

### Fixed

* **Malformed platform SPIFFE identities** — Platform enrollment no longer issues identities with an empty organization segment. Missing or inconsistent organization state now fails closed before certificate and session issuance.
* **Dry-run-to-start inventory conflict** — Campaign start accepts an identical existing read-only inventory freeze idempotently, atomically writes a missing freeze, and rejects differing immutable content with `ErrImmutableInventoryConflict`.
* **Stale producer schema** — The Go aggregate producer now emits the current schema 1.5.0 contract rather than schema 1.3.0 while historical schema versions remain readable.
* **Proxy identity spoofing** — Forwarded visitor identity is ignored unless the immediate peer is in an explicitly configured trusted CIDR and the request supplies exactly one valid unicast address.
* **Publication/export drift** — Verified catch-up and fresh export load the persisted bound report and preserve matching report digest, population digest, metric values, units, coverage, unavailable reasons, and verifier state.
* **Expired dashboard enrollment recovery** — The dashboard resumes only an unexpired persisted platform enrollment attempt and replaces expired state with a fresh key, CSR, request, and stable instance identity instead of entering a persistent restart loop.
* **Compliance replay and rendering** — Bundle verification rejects missing, orphaned, duplicated, transplanted, substituted, malformed, unsupported, or unassessed protected evidence and reproduces every protected renderer under the declared profile. OSCAL validation and framework grading preserve typed applicability and unverifiable outcomes rather than collapsing missing evidence into failure.
* **Escaped runtime state** — Evaluation inventory freezes, active-run state, queues, logs, and JSON, CSV, and SQLite exports resolve beneath the injected runtime root. Campaign export rejects absolute and parent-relative output directories, and SQLite no longer creates or changes permissions on caller-owned database paths.
* **Managed Docker runtime publication** — Runtime-binary export now extracts and validates the single regular `/g8e` entry from Docker's tar-stream `cp` output before atomic publication instead of writing the archive itself as the host executable.

### Security

* **Identity-bound platform issuance** — Operator certificate and session issuance requires a consistent persisted organization membership and fails closed before minting malformed SPIFFE identities.
* **Immediate workload revocation** — Completed platform enrollments can be revoked through an owner-authenticated governed action that closes authenticated pub/sub connections and prevents certificate or session reuse.
* **Public projection defense in depth** — Public-feed producers, disclosure validation, mirror ingest, browser validation, trusted-proxy handling, and profile-aware compliance rendering reject unknown or prohibited data at each boundary.
* **Binary bootstrap integrity** — Linux, macOS, and Windows deployment scripts download the selected executable and its manifest-catalogued SHA-256 sidecar, verify the temporary binary before replacement, and reject unsupported artifact names. The binary and checksum still share the unauthenticated HTTP bootstrap channel, so this detects corruption but does not provide remote authenticity.
