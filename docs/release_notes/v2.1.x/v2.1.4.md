## [2.1.4] - 2026-09-05

### Overview

v2.1.4 hardens gateway construction, JWT validation, and the compliance evidence pipeline, and adds the first governance, privacy, and utility evaluation benchmark suites alongside an offline deterministic README generator with a public proof snapshot. The release replaces late-bound `atomic.Pointer` dependency wiring with construction-phase injection, makes the gateway `Stores` aggregate unexported behind narrow typed accessors, and adds ESLint to the dashboard CI gate.

### Added

* **Governance evaluation benchmark suite** — Added `ensemble/evals/g8e_evals/benchmarks/governance/` with loaders, observers, and a simulator covering benign-overblock and policy-violating attack scenarios. Loaders produce typed scenario fixtures; observers record per-step governance outcomes; the simulator drives the governance pipeline against the configured gateway.
* **Privacy evaluation benchmark suite** — Added `ensemble/evals/g8e_evals/benchmarks/privacy/` with an encrypted token store, exfiltration-attempt simulator, artifact emitter, provenance recorder, and observers covering privacy-boundary leakage and token-persistence-failure scenarios. The token store encrypts and rehydrates session tokens under the eval harness key.
* **Utility evaluation benchmark suite** — Added `ensemble/evals/g8e_evals/benchmarks/utility/` with loaders and simulators for citation-backed answers, factual QA, partial-milestone completion, and tool-sequence scenarios. Each loader produces typed gold sets; each simulator drives the ensemble and records observable outcomes.
* **Typed grader registry** — Added `ensemble/evals/g8e_evals/graders/__init__.py` with typed grader references and a metric registry so eval scenarios resolve graders by typed identifier instead of stringly-typed names.
* **Evaluation metrics module** — Added `ensemble/evals/g8e_evals/metrics.py` with canonical metric computation helpers shared across the governance, privacy, and utility benchmark suites.
* **Offline deterministic README generator** — Added `scripts/generate_readme.py` and `docs/templates/README.md.tmpl` rendering the root `README.md` from a narrative template and a public proof snapshot under `docs/evidence/readme/current/`. The generator validates the selection manifest, verifies declared artifact SHA-256 checksums, rejects path traversal and undeclared files, scans declared content for forbidden private keys, credential fields, and raw canary values, aggregates eligible metric rows, projects receipt verification and canonical demo compliance reports, and renders the template. It is offline, deterministic, and credential-free.
* **README drift CI guard** — Added `make readme`, `make readme-check`, and `make readme-test` Makefile targets. The `build-and-test.yml` CI workflow runs `make readme-test` and `make readme-check` to prevent README drift.
* **Dashboard ESLint CI gate** — Added `dashboard/eslint.config.js` (flat config, `@eslint/js` recommended, Node and browser globals), a `lint` npm script, and a `make dashboard-lint` target. The `build-and-test.yml` CI workflow runs `npm run lint` before the vitest suite, and `ci-dashboard` now depends on `dashboard-lint` as well as `dashboard-test`.
* **JWT issued-in-future validation** — Added `ErrJWTIssuedInFuture` and `validateJWTTemporalClaims` in `internal/services/gateway/jwt_native.go` rejecting tokens whose `iat` claim is more than the clock-skew allowance in the future, alongside the existing `exp` and `nbf` checks.
* **Centralized JWT clock skew** — Added `constants.JWTClockSkew` (`time.Minute`) in `internal/constants/auth.go`, replacing the package-local `clockSkewAllowance` magic number in `jwt_native.go`.

### Changed

* **Construction-phase consensus wiring** — Replaced the late-bound `atomic.Pointer` consensus service cell with direct construction-phase injection through `GatewayModeDeps`. The `SetConsensusService` mutator is removed; consensus is injected once at gateway assembly and never reassigned. The compliance-alignment "Current Strengths" entry now describes construction-phase wiring instead of atomic-pointer adoption.
* **Unexported `Stores` aggregate with narrow typed accessors** — Renamed the exported `gateway.Stores` struct to the unexported `gateway.stores` aggregate, removed `CanonicalDBService.GetStores()`, and changed `OpenCanonicalDBService` to return only `*CanonicalDBService`. Consumers retrieve the specific store they use through the existing narrow typed accessors (`GetDocStore`, `GetSignerStore`, `GetConsensusStore`, `GetStateRootSvc`, `GetReplayStore`, `GetKVStore`, `GetSSEStore`, `GetBlobStore`, `GetAuditStore`, `GetSecretManager`). The aggregate never crosses the package boundary.
* **One-time MCP gateway binding** — Replaced `OperatorPubSubService.SetMCPGateway` (an `atomic.Pointer` setter) with `BindMCPGateway`, a one-time construction binding that fails closed on nil, double-bind, and bind-after-start. `GetMCPGateway` reads the immutable binding under a `sync.RWMutex`. Gateway-mode handler registration for MCP and A2A call requests is split into `buildGatewayHandlers`, registered only in gateway mode.
* **Posture-gated consensus deliberate route** — The `POST /consensus/v1/deliberate` route is registered only in `consensus` and `notary` postures. `doctrine` and `ratify` postures do not register the route, so requests return `404 Not Found`. The previous `503 Service Unavailable`-on-nil-consensus guard is removed; the handler is only reachable when consensus is non-nil.
* **Operator pub/sub client factory injection** — `services.NewG8eoService` now takes a `PubSubClientFactory` parameter and constructs the pub/sub client once in `Start()` after `ApplyBootstrapConfig` and before dependent services are built, instead of constructing it lazily inside `Start()` when the field was nil. `RunOperator` in `internal/cli/serve/operator.go` injects the canonical `pubsub.NewOperatorPubSubClient` factory.
* **Read-only release-evidence aggregation** — `collectReleaseEvidence` no longer persists a KSI history snapshot as a side effect; it is now strictly read-only aggregation. KSI history read errors are recorded in the report (`KSIHistoryErr`) and surfaced in `OverallPassing` and `FailClosedReason` instead of being silently logged. Demo-run enumeration errors are similarly recorded (`DemoEnumerationErr`). `OverallPassing` now requires at least one KSI result or demo run, and treats unknown KSI statuses as non-passing.
* **Compliance evidence CSV error handling** — `renderReleaseEvidenceCSV` now returns an `error` and propagates `csv.Writer` write and flush errors instead of discarding them.
* **Dashboard client surface cleanup** — Removed the unused `g8eg` client modules (`g8eg_client.js`, `g8eg_document_client.js`, `g8eg_http_client.js`, `g8eg_kv_cache_client.js`, `g8eg_pubsub_client.js`), the `app-identity.js` module-global holder, the `channels.js`, `kv_models.js`, `pubsub_models.js`, and `timestamp.js` helpers, and the `undici` and `ws` dependencies. `server.js` returns the resolved `AppIdentity` directly from `runStartupEnrollment` without storing module-global state. The dashboard remains a static SPA host with no backend gateway clients constructed.
* **Documentation cross-references** — Architecture, guide, reference, and developer docs now cross-link to the detailed `docs/ensemble/` and `docs/dashboard/` component documentation. The `codemap.md` dashboard section points to `docs/dashboard/index.md`, and the FIPS section points to `docs/reference/fips140-3.md` as the claim SSOT.

### Fixed

* **JWT temporal validation completeness** — The native JWT verifier now validates `iat` (issued-at) against the current time with clock skew, in addition to the existing `exp` and `nbf` checks. The previous implementation skipped `iat` validation entirely.
* **Release-evidence path traversal and semver validation** — `validateReleaseVersion` now requires the `--version` flag to match the full semantic versioning contract via a compiled regexp, and explicitly rejects path separators and parent-directory references. `writeReleaseEvidenceArtifacts` cleans the output directory and verifies that resolved markdown and CSV output paths do not escape it.
* **Release-evidence enumeration error propagation** — `enumerateDemoRunIDs` now returns real errors (other than `ErrNotFound`, which still means "no runs persisted") instead of swallowing all errors. KSI history read errors other than `ErrNotFound` are recorded in the report rather than silently logged.
* **Compliance-evidence fail-closed semantics** — `OverallPassing` now returns false when KSI history or demo enumeration errored, when both KSI results and demo reports are empty, and for any KSI status other than `Satisfied` or `NotApplicable`. `FailClosedReason` reports the first non-passing condition with a specific message.

### Security

* **MCP gateway binding fail-closed** — `BindMCPGateway` rejects nil gateways, double bindings, and bindings after `Start`, eliminating the window where the gateway could process egress dispatch against an unset or replaced MCP gateway.
* **Release-evidence path traversal rejection** — The release-evidence command rejects `--version` values containing path separators or `..`, and verifies that generated markdown and CSV paths stay within the cleaned output directory, preventing path-traversal writes from a crafted version string.
* **JWT issued-in-future rejection** — Tokens with an `iat` claim more than the clock-skew allowance in the future are now rejected, closing a gap where a token minted with a future issued-at time could pass validation.
