## [2.1.7] - 2026-09-08

### Overview

v2.1.7 closes the in-tree integrity boundary for signed compliance report bundles. Complete-bundle verification classifies every supported evidence artifact, independently replays protected demo, eval, KSI, commitment, customer and assessor attestation, audit, ledger, and build/configuration sources, compares reproduced evidence with signed canonical analysis, and fails closed for unsupported or inconsistent source evidence. The release keeps point-in-time report integrity separate from certification, recurring operating effectiveness, broad framework coverage, and eval-native release claims.

### Added

* **Complete protected-source replay** — The report verifier replays every represented source class through its registered verifier or importer using only bundle-confined bytes and deterministic signed bundle time.
* **Explicit standalone generation inputs** — `compliance report generate` accepts scope-bound KSI history and current results, commitment, customer or assessor attestation, audit, ledger, and build/configuration inputs and copies the exact source bytes into canonical protected paths.
* **Independent evidence trust** — Report verification and signed-source replay use distinct external protocol-owned trust policies. Assessed evidence keys are canonical-decoded and checked for identity, digest, scope, validity, revocation, duplication, and Ed25519 key shape.
* **Route completeness contract** — A verifier-owned classification covers every supported evidence artifact type and rejects unknown types without a complete-bundle route.

### Changed

* **Required CI timeout** — The required `Build & Test` job timeout is 30 minutes while retaining all existing unit, integration, lint, vulnerability, documentation, protocol, doctrine, cross-compilation, and static-linking checks.
* **Compliance documentation** — Public references and the release process describe signed report generation, dual-trust verification, protected-source replay, and the remaining bounded limitations as current behavior.
* **Installation versions** — Current Go and Python installation callouts and protocol package versions are synchronized to 2.1.7.

### Security

* **Fail-closed source inventory** — Missing, empty, orphaned, duplicated, transplanted, malformed, substituted, or unassessed protected evidence invalidates complete-bundle verification with deterministic typed failures.
* **Bundle-confined trust boundary** — Report trust and evidence trust remain external to the bundle and distinct from each other; packaged keys do not become trusted by inclusion.

### Deferred

* **Clean-environment acceptance** — A release owner or approved isolated environment records the required fresh network-disabled verification and mutation run before tagging. This release note does not imply that external lane has passed.
* **Hosted CI acceptance** — Pull-request-equivalent and merged-`main` green runs remain release-owner gates.
* **Eval-native release evidence** — Canonical eval analysis, paired statistics, practical eval gates, signed eval bundles, a complete eval verifier, and a frozen multi-model matrix remain a post-v2.1.7 milestone.
* **Operating effectiveness and framework expansion** — Recurring evidence history, bridge assessments, release-gate profiles, and additional reviewed framework catalogs and crosswalks remain deferred.

### Tests

* Added artifact-route completeness coverage, complete standalone-source collection and importer replay coverage, and production CLI dual-trust generation and verification coverage.
* Verified the candidate with platform unit tests and a vendored Go build during preparation. The final verification matrix and external acceptance results are recorded separately and must pass before release.
