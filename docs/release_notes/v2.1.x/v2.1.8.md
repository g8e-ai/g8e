## [2.1.8] - 2026-09-18

### Overview

v2.1.8 is a large release across three pillars: connecting a local browser frontend in one command, shipping a generator-neutral observability stack with a live evaluation explorer, and proving the full eval-native evidence pipeline end to end.

`./g8e gw connect <frontend-origin>` replaces the old multi-step `auth enroll gui` workflow. It validates the origin, configures WebAuthn and CORS, starts or restarts the Gateway, handles local certificate trust with explicit consent, verifies HTTPS and CORS against the running process, and prints a frontend handoff prompt. `gw restart` now restores the complete prior launch configuration through a versioned launch profile.

The observability work adds typed agent/run/eval state producers, a browser-scoped read-only observe API, an audited `g8e-adapter`, a deterministic contract pack for builder-generated SPAs, and the checked-in **Evaluation Explorer** — a live UI wired to Go-native campaign output. A separate **public spectator** mode publishes allowlisted, signed projections to an anonymous mirror so visitors can watch campaigns without Gateway credentials.

The eval work ships `g8e eval campaign` from spec through verify and publish, with provider-boundary hardware observation, storage-side model provenance attestation, and a bounded R0 pipeline-integrity campaign that completed with real Ollama inference and descriptive-only claims.

CLI operations gained persisted operator session binding (`g8e operator bind`) and parallel governed shell dispatch to multiple remote Operators (`g8e operator run ... --cmd`), so owner automation no longer depends on manual envelope construction for multi-host command execution.

### Added

* **`gw connect`** — Single guided workflow for connecting a local browser frontend to the Gateway. Flags: `--passkey-rp-id`, `--passkey-rp-name`, `--no-system-trust`, `--no-open`, `--yes`.
* **Evaluation Explorer** — Checked-in SPA at `dashboard/g8e-adapter/evaluation-explorer/` connected to Go-native campaign output: live event stream, run and assignment detail, model comparison, and campaign-aware bundle publication through the observe path.
* **Public spectator mode** — Outbound-only `g8e public` publisher and anonymous mirror read API for allowlisted campaign projections, canonical events, and proof artifacts. Distinct from credentialed owner-local observe; no shared credentials, endpoints, or state. See [Public Spectator Architecture](../../architecture/public_spectator.md).
* **Observe API and producers** — Typed agent, run, and eval state producers (mTLS) and browser-scoped read-only observe endpoints (web session). Cross-language models in Go and Python with strict unknown-field rejection.
* **Audited `g8e-adapter` and contract pack** — Generator-neutral runtime config, endpoint allowlist, WebAuthn, SSE, observe client, and typed stores under `dashboard/g8e-adapter/`. Contract pack plus reference UI for Lovable and other builder handoff.
* **`g8e eval campaign`** — Typed campaign spec, deterministic schedule, resume, budget enforcement, cohort-stratified canonical analysis, signed bundle verify/publish, and campaign-aware observe publication. Provider-boundary Observer and storage-side Provenance Operator sessions witness GPU/RAM telemetry and model weight digests independently of the Inference Operator.
* **Inference Operator** — Governed L4/L5 inference PEP in the unified Docker stack; scored campaigns route through production `POST /api/v1/chat` rather than direct Ollama calls from the CLI.
* **Observer `--ollama` flag** — Opt-in governed Ollama lifecycle commands on the provider-host Observer for campaign execution.
* **CLI operator session binding** — `g8e operator bind` pins the authenticated CLI session to a specific operator session (`bind <operator-session-id>`, `bind list`, `bind unbind`). Binding changes issue a replacement CLI session server-side and update local credentials. Gateway routes: `POST /api/v1/auth/cli/bind` and `POST /api/v1/auth/cli/unbind` (mTLS-only).
* **Parallel operator command dispatch** — `g8e operator run <operator-session-id> [operator-session-id...] --cmd "<shell command>"` fans out governed `EXECUTE_BASH` dispatches in parallel through `POST /api/v1/operators/commands`. Each target must belong to the authenticated user and be active; the gateway constructs the envelope, waits for a terminal result per target, and returns stdout, stderr, and exit code.
* **`g8e operator show`** — Operator detail and latest heartbeat snapshot by operator ID or session ID. `g8e operator list` adds a hostname column from heartbeat system identity.

### Changed

* **`gw restart`** — Restores the full launch profile instead of posture only. Re-runs network identity detection before start.
* **Origin and trust validation** — Centralized browser origin parsing and RP ID validation shared by `gw connect`, the gateway wizard, and enrollment trust discovery.
* **Gateway process lifecycle** — Resolved ports propagate to callers; failed starts clean up child processes and PID files; profile-write failures roll back or stop untracked gateways.
* **Event dashboard classification** — `g8e.v1.app.run` and `g8e.v1.ai.eval` reclassified to `produced_to_sse`; eval events marked dashboard-safe after campaign publication landed.
* **Documentation** — Frontend, observe, eval, and unified-stack guides updated for `gw connect`, contract-pack handoff, campaign operations, and the new observe/SSE architecture.

### Removed

* **`auth enroll gui` command family** — Replaced entirely by `gw connect`. No compatibility shim. Legacy `.g8e/gui_enrollments.json` files are inert until explicitly cleaned up.

### Security

* **Exact-origin CORS and exact-host RP ID by default** — No wildcard CORS; RP ID derived from the frontend hostname unless a validated parent-suffix override is supplied.
* **No insecure TLS bypass** — HTTPS/CORS verification uses the discovered g8e root; `InsecureSkipVerify` is never used on acceptance paths.
* **Fail-closed restart and trust** — Invalid launch profiles block restart. Trust installation and stale-anchor removal require separate consent; `--yes` auto-approves restart only.
* **Launch profiles contain no secrets** — Only validated Gateway configuration is persisted.
* **Observe and public isolation** — Cross-user producer writes and browser reads are denied at the Gateway. Public spectator projections are allowlist-bound; anonymous visitors cannot reach the private Gateway.
* **Independent witness evidence** — Provider-boundary hardware observation and storage-side model provenance attestation bind to `provider_attempt_id` separately from inference receipts.

### Deferred

* **Clipboard integration** — `--copy` deferred until terminal/desktop support is tested.
* **Owner-operated acceptance** — Real-browser WebAuthn, Local Network Access, cross-platform trust installation, builder-produced SPAs from the contract pack, and `./g8e test e2e` remain human gates; gaps are recorded honestly in release prep.
* **Init campaign matrix** — Multi-model `eval-init-*` qualification runs are in progress; the bounded R0 pipeline-integrity campaign in this release is the demonstrated evidence lane.

### Tests

* Broad automated coverage across `gw connect`, observe producers and endpoints, the adapter (445 passing unit tests including contract-pack drift check), ensemble lifecycle wiring, evaluation explorer views, public mirror lifecycle, and eval campaign execution.
* Platform `./g8e test unit`, `./g8e test integration`, and `./g8e test lint` pass on `draft/v2.1.8`. `./g8e test coverage` reports **73.5%** on the Makefile-filtered profile as of 2026-09-19 — below the **75%** release gate (~820 statements remain). Ensemble lint/test/build lanes pass. Adapter unit tests report 445/445 passing. Owner-operated browser, trust, and e2e gates remain outside automated CI.

### Eval campaign (R0)

* **Scope** — 2 model cohorts, 2 arms (direct + ensemble_ungoverned), 5-task `ifeval_subset`, 40 assignments, descriptive-only claim policy.
* **Result** — All assignments completed with real Ollama inference; signed bundle passed 12 offline verification layers; published through the campaign-aware observe path.
* **Claim boundary** — Proves campaign construction, bundling, verification, reproduction, disclosure control, and truthful publication. Does not claim model superiority, governance enforcement, certification, or broad model quality.
