## [2.1.8] - 2026-09-09

### Overview

v2.1.8 replaces the multi-command, multi-flag browser frontend setup with one guided Gateway workflow. `./g8e gw connect <frontend-origin>` validates and normalizes the origin, derives the safest WebAuthn configuration, starts or deliberately restarts the Gateway, establishes local certificate trust with explicit consent, verifies HTTPS and CORS against the running process, and prints a short frontend prompt. The obsolete `auth enroll gui` command family is removed. Restart preserves the complete prior launch configuration through a versioned launch profile rather than posture only.

### Added

* **`gw connect` guided command** — `./g8e gw connect <frontend-origin>` is the sole local browser connection workflow. It accepts one positional origin, validates it through the centralized browser origin parser, derives an exact-host RP ID, starts or restarts the Gateway with the correct CORS and passkey settings, installs local certificate trust with explicit consent, verifies HTTPS and CORS against the running process, and prints a concise frontend prompt. MVP flags: `--passkey-rp-id`, `--passkey-rp-name`, `--no-system-trust`, `--no-open`, `--yes`.
* **Centralized browser origin validation** — `internal/cli/browserorigin` provides a typed `Origin` struct and pure `Parse` and `ValidateRPID` functions. Both the gateway wizard and `gw connect` consume this implementation. `Parse` enforces HTTPS for non-loopback hosts, rejects paths, queries, fragments, userinfo, and non-loopback IP hosts, canonicalizes scheme and hostname to lowercase, canonicalizes Unicode hostnames to IDNA ASCII via `golang.org/x/net/idna`, strips trailing slashes, preserves explicit non-default ports, and derives the RP ID from `Hostname` never `Host`. `ValidateRPID` accepts an exact-host match or a registrable parent suffix, canonicalizes the override to IDNA ASCII + lowercase, returns the canonical form, and rejects public suffixes via `golang.org/x/net/publicsuffix`.
* **Versioned launch profile persistence** — `internal/cli/serve/launch_profile.go` persists the complete validated `GatewayConfig` to `.g8e/pids/operator-launch-profile.json` with private permissions through `RuntimeFileService`. `GatewayConfig` uses explicit snake-case JSON tags for a stable wire shape. `ReadLaunchProfile` uses `DisallowUnknownFields` and trailing-JSON detection so multiple concatenated JSON values are rejected as corrupted. `WriteLaunchProfile` calls `ValidateLaunchProfile` before serializing, so invalid configs are rejected at the write boundary without touching the filesystem. `ValidateLaunchProfile` checks posture, port range (0-65535), port collision, rate limits, network identity file, log level, certificate mode, browser origins, RP/origin relationships, and service URLs (public/consensus/mcp/a2a). Every successful background `gw start` writes the profile. `gw restart` reads and validates the complete profile and re-runs network identity detection before starting the child. Missing, malformed, unknown-version, or unsafe profiles fail closed.
* **Reusable trust discovery and inspection** — `internal/cli/auth/trust_discovery.go` extracts `ValidateTrustBundle` and `DiscoverLiveTrustBundle` from identity enrollment so both `gw connect` and identity enrollment use the same root selection, chain verification, and fingerprint formatting. `internal/cli/auth/trust_state.go` adds `InspectTrustState` for read-only trust-state inspection.
* **HTTPS and CORS verifier** — `internal/cli/frontendverify/verifier.go` is a read-only verifier with an injectable HTTP client factory. It builds a TLS client from the discovered and validated g8e root, never uses `InsecureSkipVerify`, and returns typed ordered verification results for HTTPS health, certificate chain, CORS origin, CORS credentials, CORS methods, CORS headers, and CORS Vary (requiring `Vary: Origin`).
* **Typed connection error constants** — `ErrLaunchProfileMissing`, `ErrLaunchProfileCorrupted`, `ErrLaunchProfileVersionUnsupported`, `ErrLaunchProfileInvalid`, `ErrHTTPSCertificateVerification`, `ErrCORSPreflightRejected`, `ErrManualBrowserTrustRequired`, `ErrGatewayReadinessTimeout`, `ErrGatewayConfigMismatch`, `ErrManagedRestartDeclined` added to `internal/constants/errors.go`.

### Changed

* **`gw restart` restores complete launch configuration** — Restart reads the complete launch profile, re-runs `detectIdentity` for fresh network identity state, and starts the child with the full persisted configuration. Posture-only persistence (`writePosture`/`readPosture`) is removed from `internal/cli/platform/process.go`. Missing or malformed profiles fail closed with typed errors instead of falling back to doctrine defaults.
* **Wizard and GUI origin validation migrated** — `internal/cli/wizard/validate.go` and the former `internal/cli/cmd/gui.go` delegate to `browserorigin.Parse` and `browserorigin.ValidateRPID`. The wizard now rejects non-loopback HTTP origins, non-loopback IP hosts, and public-suffix RP IDs the previous package-private implementation accepted.
* **`golang.org/x/net` promoted to direct dependency** — The module was already in the transitive closure; it was promoted from indirect to direct and vendored to provide `golang.org/x/net/publicsuffix` for registrable-domain validation.
* **Identity enrollment trust extraction** — `EnrollmentCoordinator.installSystemTrust` delegates to `ValidateTrustBundle` instead of calling `platform.ExtractRootAnchors`, `platform.VerifyRootUsable`, and `platform.CertFingerprint` directly. No enrollment behavior changes; the same validation runs in the same order with the same error constants.
* **Tunnel create next steps** — `internal/cli/cmd/tunnel.go` points users to `gw connect` instead of the removed `auth enroll gui` command.
* **Managed process start returns resolved configuration** — `StartOperator` takes a pointer to `OperatorStartOptions` and mutates resolved ports and paths in place. Callers that read `startOpts.GatewayConfig` after start see the resolved values. `gw start`, `gw restart`, `gw connect`, and the MCP auto-start path consume the resolved values. MCP auto-start now writes a launch profile and probes its resolved HTTP port rather than the global default.
* **Failed-start child termination and stale-PID removal** — `stopFailedStart` terminates and reaps the child on PID-write failure, log-close failure, and health-check timeout, joining kill+wait+deletePID errors via `errors.Join`. No failed-start path leaves a live child or stale PID file.
* **Profile-write failure stops untracked gateway** — When `WriteLaunchProfile` fails after a successful process start, `gw connect` stops the untracked gateway and reports both errors. Restart attempts rollback to the previous profile on start failure and on profile-write failure, reporting both the primary failure and rollback result.
* **Discovery and verification URLs use resolved ports** — `gw connect` constructs discovery and HTTPS verification URLs from the active launch profile's resolved `HTTPPort`/`HTTPSPort`, not from global CLI defaults. A Gateway shifted to another port starts successfully and verifies against the correct endpoint.

### Removed

* **`auth enroll gui` command family** — `guiEnrollCmd`, `guiShowCmd`, `guiVerifyCmd`, `guiRemoveCmd`, and all associated models, file I/O, snippet generation, and the broken plain-HTTP CORS checker are deleted. No compatibility alias or shim remains. Pre-existing `.g8e/gui_enrollments.json` files are inert and untouched; they persist until removed through the existing explicit runtime-tree cleanup workflow (`gw clean`).

### Security

* **Exact-origin CORS only** — No wildcard fallback. `Access-Control-Allow-Credentials` remains paired with an exact reflected origin.
* **Exact-host RP ID by default** — The CLI derives the exact frontend hostname as the RP ID, never the shared parent domain. An advanced `--passkey-rp-id` override is validated as either the exact origin hostname or a valid parent suffix; public suffixes and unrelated domains are rejected.
* **No insecure TLS bypass** — The HTTPS and CORS verifier builds a TLS client from the discovered and validated g8e root pool. `InsecureSkipVerify` is never used in production or test acceptance paths.
* **Fail-closed restart** — Missing, malformed, unknown-version, or unsafe launch profiles prevent restart. The CLI never stops a running Gateway when its complete launch configuration is unavailable.
* **Separate consent boundaries** — Trust installation and stale-anchor removal each require explicit consent. `--yes` auto-approves restart only; it does not suppress trust or stale-anchor consent.
* **Launch profiles contain no secrets** — No private keys, tokens, passwords, cookie values, or environment snapshots are persisted. Ephemeral `NetworkIdentityFile` is cleared before serialization and rejected on read.
* **Fail-closed unsupported trust** — Unsupported OS trust installation fails closed with `ErrManualBrowserTrustRequired` unless `--no-system-trust` was explicitly selected. The CLI never silently downgrades to manual trust.
* **Browser-restart gate enforced** — Declining the browser-restart gate after trust changes stops handoff. The CLI never proceeds past a blocking trust-change gate.
* **IDNA canonicalization** — Unicode hostnames and RP ID overrides are canonicalized to IDNA ASCII before persistence and validation, so `gw connect` stores `xn--caf-dma.lovable.app` rather than the caller's original mixed-case or Unicode form.
* **`Vary: Origin` required** — The verifier enforces `Vary: Origin` as a seventh CORS check, preventing cached responses from leaking across origins.

The work is split into automated evidence (verified by tests) and owner-operated gates (requiring real browsers, authenticators, and hosted origins).

### Eval Campaign and Pipeline Integrity

v2.1.8 ships a bounded pipeline-integrity eval campaign that proves the full eval-native evidence pipeline end-to-end. The campaign is a diagnostic, not a model leaderboard: it uses the five-task `ifeval_subset` development partition with a descriptive-only claim boundary.

**Campaign infrastructure:**

- `g8e-evals campaign` CLI command and `CampaignRunner` implement typed campaign contracts: frozen `CampaignSpec` with cohorts, task assignment, initial-state assignment, retry policy, randomization seed, and provider budget; Cartesian assignment product; deterministic Fisher-Yates schedule; typed campaign manifest binding every authority by content hash; resume support; budget enforcement with typed terminal outcomes; campaign status state machine; and canonical analysis output.
- Typed suite registry (`g8e_evals/suites.py`) classifies every suite by execution class (`REAL_MODEL`, `REAL_SYSTEM`, `DETERMINISTIC_SIMULATION`). The `run` and `campaign` commands reject deterministic-simulation suites from model comparisons; `bench-synthetic` rejects real-model suites.
- `RunManifest` carries optional `CampaignBinding` with `campaign_id`, `campaign_revision`, `assignment_id`, `model_variant_id`, `track`, `target_tier`, `repetition`, `BackendArtifactIdentity`, `TokenizerTemplateIdentity`, `reasoning_mode`, and effective `SamplingSettings`. Schema version bumped to `1.41.0`.
- Direct CLI decoupling: `--g8ee-url` and `--auth-project-root` are conditional requirements for ensemble and governed arms; the direct arm skips auth loading entirely.
- Canonical analysis is assignment-aware and cohort-stratified: `MetricAnalysisResult`, `PairedComparison`, `ConfusionMatrix`, `DomainStratifiedResult`, and `GateDecision` carry `model_cohort_id`; `PreregistrationConfig` carries `ClaimPolicy` (`DESCRIPTIVE_ONLY` or `SUPERIORITY`).

**R0 campaign execution:**

- Campaign spec: 2 cohorts (Qwen3-8B + Granite-3.3-8B-Instruct), 2 arms (direct + ensemble_ungoverned), 2 replicates, 40 assignments, descriptive-only claim policy.
- All 40 assignments completed with real Ollama inference. Direct arm: 20/20 (100%) pass rate. Ensemble_ungoverned arm: 19/20 (95%) pass rate.
- The signed bundle passed all 12 offline verification layers with zero failures.
- The bundle was published to the Gateway observe API through the campaign-aware mTLS publication path.

**Production bugs found and fixed during campaign execution:**

1. Circular import in `app.security.request_timestamp` (module-level `CacheAsideService` import moved under `TYPE_CHECKING`).
2. Broken model-tag derivation in the campaign CLI (`rpartition("-")` fix plus `--model-tags` JSON override).
3. Cohort drift false positive in `CampaignRunner` (`_model_matches` helper accepting `provider:model` prefix).
4. Session type conflation in evals transport (`G8E_WEB_SESSION_ID` env var read removed from `from_env()`).
5. Stale `g8e` protocol package install (reinstalled in editable mode).

**Claim boundary:**

The v2.1.8 campaign proves campaign construction, retention, canonical analysis, complete bundling, semantic verification, deterministic reproduction, disclosure control, and truthful publication. It does not claim model superiority, governance enforcement, state integrity, privacy, compliance, validation performance, holdout performance, certification, or broad model quality. Five task pairs are not enough for inferential model-performance claims.
