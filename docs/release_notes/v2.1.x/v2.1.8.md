## [2.1.8] - 2026-09-09

### Overview

v2.1.8 replaces the multi-command, multi-flag browser frontend setup with one guided Gateway workflow. `./g8e gw connect <frontend-origin>` validates and normalizes the origin, derives the safest WebAuthn configuration, starts or deliberately restarts the Gateway, establishes local certificate trust with explicit consent, verifies HTTPS and CORS against the running process, and prints a short frontend prompt. The obsolete `auth enroll gui` command family is removed. Restart preserves the complete prior launch configuration through a versioned launch profile rather than posture only.

### Added

* **`gw connect` guided command** — `./g8e gw connect <frontend-origin>` is the sole local browser connection workflow. It accepts one positional origin, validates it through the centralized browser origin parser, derives an exact-host RP ID, starts or restarts the Gateway with the correct CORS and passkey settings, installs local certificate trust with explicit consent, verifies HTTPS and CORS against the running process, and prints a concise frontend prompt. MVP flags: `--passkey-rp-id`, `--passkey-rp-name`, `--no-system-trust`, `--no-open`, `--yes`.
* **Centralized browser origin validation** — `internal/cli/browserorigin` provides a typed `Origin` struct and pure `Parse` and `ValidateRPID` functions. Both the gateway wizard and `gw connect` consume this implementation. `Parse` enforces HTTPS for non-loopback hosts, rejects paths, queries, fragments, userinfo, and non-loopback IP hosts, canonicalizes scheme and hostname to lowercase, strips trailing slashes, preserves explicit non-default ports, and derives the RP ID from `Hostname` never `Host`. `ValidateRPID` accepts an exact-host match or a registrable parent suffix and rejects public suffixes via `golang.org/x/net/publicsuffix`.
* **Versioned launch profile persistence** — `internal/cli/serve/launch_profile.go` persists the complete validated `GatewayConfig` to `.g8e/pids/operator-launch-profile.json` with private permissions through `RuntimeFileService`. Every successful background `gw start` writes the profile. `gw restart` reads and validates the complete profile and re-runs network identity detection before starting the child. Missing, malformed, unknown-version, or unsafe profiles fail closed.
* **Reusable trust discovery and inspection** — `internal/cli/auth/trust_discovery.go` extracts `ValidateTrustBundle` and `DiscoverLiveTrustBundle` from identity enrollment so both `gw connect` and identity enrollment use the same root selection, chain verification, and fingerprint formatting. `internal/cli/auth/trust_state.go` adds `InspectTrustState` for read-only trust-state inspection.
* **HTTPS and CORS verifier** — `internal/cli/frontendverify/verifier.go` is a read-only verifier with an injectable HTTP client factory. It builds a TLS client from the discovered and validated g8e root, never uses `InsecureSkipVerify`, and returns typed ordered verification results for HTTPS health, certificate chain, CORS origin, CORS credentials, CORS methods, and CORS headers.
* **Typed connection error constants** — `ErrLaunchProfileMissing`, `ErrLaunchProfileCorrupted`, `ErrLaunchProfileVersionUnsupported`, `ErrLaunchProfileInvalid`, `ErrHTTPSCertificateVerification`, `ErrCORSPreflightRejected`, `ErrManualBrowserTrustRequired`, `ErrGatewayReadinessTimeout`, `ErrGatewayConfigMismatch`, `ErrManagedRestartDeclined` added to `internal/constants/errors.go`.

### Changed

* **`gw restart` restores complete launch configuration** — Restart reads the complete launch profile, re-runs `detectIdentity` for fresh network identity state, and starts the child with the full persisted configuration. Posture-only persistence (`writePosture`/`readPosture`) is removed from `internal/cli/platform/process.go`. Missing or malformed profiles fail closed with typed errors instead of falling back to doctrine defaults.
* **Wizard and GUI origin validation migrated** — `internal/cli/wizard/validate.go` and the former `internal/cli/cmd/gui.go` delegate to `browserorigin.Parse` and `browserorigin.ValidateRPID`. The wizard now rejects non-loopback HTTP origins, non-loopback IP hosts, and public-suffix RP IDs the previous package-private implementation accepted.
* **`golang.org/x/net` promoted to direct dependency** — The module was already in the transitive closure; it was promoted from indirect to direct and vendored to provide `golang.org/x/net/publicsuffix` for registrable-domain validation.
* **Identity enrollment trust extraction** — `EnrollmentCoordinator.installSystemTrust` delegates to `ValidateTrustBundle` instead of calling `platform.ExtractRootAnchors`, `platform.VerifyRootUsable`, and `platform.CertFingerprint` directly. No enrollment behavior changes; the same validation runs in the same order with the same error constants.
* **Tunnel create next steps** — `internal/cli/cmd/tunnel.go` points users to `gw connect` instead of the removed `auth enroll gui` command.

### Removed

* **`auth enroll gui` command family** — `guiEnrollCmd`, `guiShowCmd`, `guiVerifyCmd`, `guiRemoveCmd`, and all associated models, file I/O, snippet generation, and the broken plain-HTTP CORS checker are deleted. No compatibility alias or shim remains. Pre-existing `.g8e/gui_enrollments.json` files are inert and untouched; they persist until removed through the existing explicit runtime-tree cleanup workflow (`gw clean`).

### Security

* **Exact-origin CORS only** — No wildcard fallback. `Access-Control-Allow-Credentials` remains paired with an exact reflected origin.
* **Exact-host RP ID by default** — The CLI derives the exact frontend hostname as the RP ID, never the shared parent domain. An advanced `--passkey-rp-id` override is validated as either the exact origin hostname or a valid parent suffix; public suffixes and unrelated domains are rejected.
* **No insecure TLS bypass** — The HTTPS and CORS verifier builds a TLS client from the discovered and validated g8e root pool. `InsecureSkipVerify` is never used in production or test acceptance paths.
* **Fail-closed restart** — Missing, malformed, unknown-version, or unsafe launch profiles prevent restart. The CLI never stops a running Gateway when its complete launch configuration is unavailable.
* **Separate consent boundaries** — Trust installation and stale-anchor removal each require explicit consent. `--yes` auto-approves restart only; it does not suppress trust or stale-anchor consent.
* **Launch profiles contain no secrets** — No private keys, tokens, passwords, cookie values, or environment snapshots are persisted. Ephemeral `NetworkIdentityFile` is cleared before serialization and rejected on read.

### Documentation

* `docs/guides/lovable.md` rewritten to the one-command `gw connect` journey with the paste prompt, top-level-tab guidance, browser limitation documentation (Local Network Access and third-party cookies), and troubleshooting keyed to `gw connect` output.
* `docs/guides/build_frontend.md`, `docs/guides/connect_frontend_to_gateway.md`, and `docs/guides/connect_apps_to_gateway.md` updated to remove all `auth enroll gui` references, point to `gw connect` for the local case, retain advanced `gw start` flags for multi-origin and public deployments, and document third-party-cookie limitations.
* `docs/guides/cloudflare_tunnel.md` points to `gw connect` for the local case and retains tunnel-specific configuration for public access.
* `demos/README.md` adds a Browser Frontend Connection section pointing to `gw connect` for same-host browser frontend connection.

### Tests

* Phase 0 regression tests documented four root UX failures (GUI origin validator accepts paths and derives port-bearing RP IDs, CORS checker probes plain HTTP, `gw restart` loses non-posture settings, `gw start` returns success when already running without applying new flags).
* `internal/cli/browserorigin/origin_test.go` — 28 table-driven tests covering HTTPS, loopback HTTP, ports, trailing slash, mixed-case, paths, queries, fragments, userinfo, IPv4/IPv6, RP ID exact match, parent suffix, public suffix rejection.
* `internal/cli/serve/launch_profile_test.go` — 16 table-driven tests covering round-trip, permissions, missing, corrupted, unknown version, invalid posture, negative ports, negative rate limits, stale network identity, delete, exists, valid postures, zero ports.
* `internal/cli/auth/trust_discovery_test.go` — 12 tests covering valid bundle, empty, malformed, expired, no root, no chain, fingerprint, live discovery, network failure, invalid content, root-only, chain failure.
* `internal/cli/auth/trust_state_test.go` — 6 tests covering trusted, not trusted, unsupported platform, real errors.
* `internal/cli/frontendverify/verifier_test.go` — 13 tests with real temporary PKI and HTTPS, never `InsecureSkipVerify`.
* `internal/cli/cmd/gateway_connect_*_test.go` — 28 tests covering config match, rendering, state machine, factory error, and a Tier 2 integration restart test.
* `./g8e test unit`, `./g8e test integration`, and `./g8e test lint` pass.

### Deferred

* **Clipboard integration** — The prompt is always printed. An explicit `--copy` option is deferred until supported terminals and desktop environments are tested.
* **Browser and OS acceptance evidence** — Real Chromium top-level-tab behavior, Local Network Access allow/deny, WebAuthn, cookies, SSE, and Linux/macOS/Windows trust installation remain explicit human acceptance evidence.
* **Compliance evidence** — Per-release compliance evidence generation is a release-owner step that requires a running deployment with current demo evidence.
