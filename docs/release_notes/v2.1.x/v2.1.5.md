## [2.1.5] - 2026-09-06

### Overview

v2.1.5 publishes the first bounded real-agent README evidence stage: one complete five-task `ifeval_subset` diagnostic through the `doctrine` arm with real local Ollama models, typed task outcomes, configured-versus-observed role reporting, checksum-bound public projections, and a portable attended reproduction method. Stage 1 demonstrates only that the declared model configuration executed the fixed diagnostic through g8ee and produced the published deterministic outcomes. It does not establish receipt coverage, governed mutation, persistence, complete bundle verification, broad model quality, statistical significance, compliance, certification, or production suitability.

### Added

* **Stage 1 README evidence projection** — Added `scripts/project_readme_evidence.py`, an attended utility that projects one immutable private eval report into a new public candidate directory. The projector emits only the Stage 1 allowlist, removes restricted fields and exact private topology, computes deterministic artifact checksums, refuses to replace an existing candidate, and validates the completed candidate through the offline README reader.
* **Typed Stage 1 public artifacts** — Added publication schema `2.0.0` validation for checksum-bound `tasks.jsonl`, `summary.json`, `evidence-index.jsonl`, and `reproduction-manifest.json` projections. Cross-checks bind the public projections to the manifest, attempts, stages, metrics, receipts, platform version, fixed task population, role mapping, timeout, and portable endpoint variable.
* **Portable attended collection method** — Added the fixed v2.1.5 five-task profile and release-owner Ollama role mapping to the release process, eval documentation, and sovereignty runbook. Reproducing operators provide their own endpoint and may record model substitutions without representing different tags or revisions as byte-identical reproductions.
* **Stage 1 README rendering** — Added a bounded evidence-stage statement, source links for task and attempt outcomes, stage telemetry, summary, evidence index, and reproduction artifacts, plus explicit unavailable states for receipt, governance, persistence, state, and compliance evidence not supplied by the answer-only campaign.

### Changed

* **Current eval schema support** — The offline README reader accepts the explicitly supported eval schemas `1.33.0` and `1.40.0` and continues to reject unknown schemas.
* **Complete-population eligibility** — Schema `1.40.0` Stage 1 evidence requires the single `doctrine` arm, task IDs `1001`, `1019`, `1051`, `1072`, and `1075`, exactly one terminal attempt per task, real configured primary, assistant, and lite identities, real model-call telemetry for every attempt, and one bound deterministic `ifeval_subset_verifier` metric per attempt. Failures, errors, and timeouts remain in the denominator.
* **Configured-versus-observed model reporting** — Public role observations derive from provider-boundary stage telemetry matched to configured provider and model identities. Roles without matching telemetry render as `Configured but unobserved` rather than being described as used.
* **Eval orchestrator provenance** — The eval runner records the installed `g8e_evals` package version in `RunManifest.orchestrator_version` instead of a separately maintained value.
* **v2.1.5 installation guidance** — Updated current Go module and Python package installation callouts to v2.1.5 and synchronized the platform and protocol Python package versions.

### Security

* **Fail-closed public evidence validation** — Stage 1 publication rejects fake providers, fake models, fake provider-boundary telemetry, incomplete or selected-only task populations, inconsistent summaries, foreign attempt references, mismatched reproduction profiles, missing projection references, invalid checksums, and undeclared artifacts.
* **Restricted-material scanning** — Public-artifact checks scan `index.json` and declared artifacts for raw prompt or output fields, credentials, private keys, raw canary values, machine-specific absolute paths, exact provider endpoints, and exact private-network topology.
* **Immutable candidate boundary** — Projection writes into a new candidate directory and refuses to overwrite an existing candidate. Candidate review and promotion remain explicit release-owner actions separate from collection and offline validation.

### Tests

* **README reader and renderer regressions** — Expanded the offline README suite to cover schema `1.40.0`, fake configured providers and provider stages, incomplete task populations, configured-versus-observed roles, zero-receipt wording, Stage 1 source links, private endpoints and topology, raw prompt fields, absolute paths, projection cross-references, summary consistency, reproduction profiles, deterministic projection, existing-candidate refusal, and restricted index values.
* **Eval manifest provenance regression** — Added coverage asserting that new run manifests carry the actual `g8e_evals` package version as orchestrator provenance.

The report records the live KSI evaluation as 0 of 31 satisfied, no prior KSI history snapshots, and successful independent verification of both persisted demo runs; it makes no certification, accreditation, authorization, or legal-compliance claim.

### Notes

* Stage 1 is intentionally limited to the repository-pinned five-task `ifeval_subset`; it does not represent complete IFEval coverage or a statistically meaningful model comparison.
* The answer-only diagnostic may produce zero receipts. Zero receipts render receipt and governance evidence unavailable and support no mutation, persistence, or state claim.
* Raw prompts, model outputs, exact private endpoints, local paths, credentials, evidence keys, and encrypted restricted payload locations remain outside the public snapshot.
* Later evidence stages add reproduction provenance, governed action proof, broader analytical coverage, complete bundle verification, and compliance depth without relabeling Stage 1 claims.
