## [2.1.10] - 2026-09-20

### Overview

v2.1.10 adds an opt-in, governed Ollama provider reset between evaluation assignments. The reset runs through the provider-host Observer Operator rather than a direct campaign-host process, preserving the Gateway/Operator execution boundary while recycling provider state between model attempts. The release also refreshes the g8ee dependency manifests and `uv.lock` resolution used by the unified stack.

### Added

* **Governed Ollama provider reset** — Evaluation campaigns can dispatch a platform-aware reset sequence through an Observer Operator enrolled with `--provider-boundary-observer-enabled --ollama`. Unix hosts use `ollama stop`, daemon restart with a `systemctl`/process fallback, readiness settling, and `ollama ps`; Windows hosts use the corresponding `taskkill`/background-start sequence. The sequence runs before each assignment and remains skipped when the Observer has not explicitly opted in.
* **Ollama lifecycle capability enforcement** — Gateway and Operator validation reject Ollama service lifecycle commands unless the target Observer session was enrolled with the `--ollama` capability. Queue preflight reports the active Ollama-capable Observer count and warns when resets will be skipped.

### Changed

* **Evaluation dispatch identity and evidence** — Provider reset commands use the campaign's authenticated CLI and Data Operator context, target the exact Observer session, and carry campaign, investigation, task, and execution identifiers through the governed command relay.
* **g8ee dependency pins** — Refreshes the ensemble's direct runtime and test dependency pins and regenerates its `uv.lock` resolution.

### Fixed

* **Provider state leakage between assignments** — Opted-in evaluation runs now quiesce and restart the remote Ollama service between assignments, reducing cross-assignment model residency and stale provider state while retaining the separate `--wait-for-provider-idle` HTTP readiness check.

### Deferred

* **Live provider-host acceptance** — Cross-platform provider-host execution, browser/WebAuthn, trust installation, and `./g8e test e2e` remain release-owner gates unless demonstrated against the target deployment. This release does not claim completion of the outstanding Tier-A campaign matrix.

### Tests

* Unit tests cover platform-specific restart command sequences, tolerated lifecycle exit codes, capability rejection, skip behavior without `--ollama`, governed dispatcher request construction, and decoded command results.
