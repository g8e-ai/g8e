## [1.0.3] - 2026-05-29

### Overview

v1.0.3 completes the substrate-only architecture by removing all remaining g8ee application-layer coupling from the Gateway and protocol definitions. The Gateway routing layer is significantly refactored with dedicated controllers for admin and operator lifecycle, and a new CLI approval command enables out-of-band L3 transaction authorization. Security hardening includes fixes for outbound L3 notary verification and JIT user lockout prevention.

### Breaking Changes

* **g8ee API paths removed** - All g8ee-specific API paths removed from `protocol/constants/api_paths.json` and `internal/constants/api_paths.go`. The `g8ee` and `g8ee_full` path groups are deleted along with the `GetG8eePath()` helper function.
* **Device-link CLI commands removed** - The `g8e data device-links` command group (create, delete, list) is removed. Device-link token management is no longer exposed via CLI.
* **g8ee environment variables removed** - All g8ee-related environment variables and configuration entries removed from substrate code.
* **Public endpoint renaming** - Gateway public endpoints renamed for clarity. Documentation and tests updated to reflect new endpoint names.
* **Protocol model cleanup** - Protocol models (agent_activity_metadata, case, conversation, investigation, operator_document, reputation_commitment, reputation_state, security_constraints, stake_resolution, tool_results, user, user_settings) updated to remove g8ee-specific field references.

### Added

* **CLI approval command** - New `./g8e approve <transaction_hash>` command enables out-of-band L3 transaction approval. Users can sign suspended transaction hashes with their CLI private key and submit cryptographic proofs to the Gateway for authorization.
* **PublicRouteRegistry** - Centralized public route registry in `gateway_auth.go` eliminates fragile `HasPrefix` duplication across middleware. Exact paths and prefixes are registered in one location for maintainability.
* **AdminController** - New dedicated controller for admin-only endpoints, including app policy management. Separates admin concerns from auth and operator controllers.
* **OperatorController** - New dedicated controller for operator lifecycle endpoints (registration, binding, session management). Provides clear separation of operator management concerns.
* **JIT user lockout defense** - Added one-time valid JWT mechanism to prevent JIT user lockout during enrollment. Users receive a temporary valid JWT if enrollment fails, ensuring they can recover access.
* **Enhanced gateway security** - Multiple security hardening improvements including stricter request validation, improved error handling, and enhanced authentication checks.

### Changed

* **Gateway routing refactor** - Gateway HTTP routing significantly refactored to use dedicated controllers. Admin, auth, and operator concerns are now separated into distinct controller packages with clear responsibilities.
* **L3 notary outbound fix** - Fixed L3 notary verification for outbound transactions. Suspended transaction handling and receipt generation now correctly handle outbound mutation flows.
* **Test coverage expansion** - Extensive test coverage improvements across gateway services. Added comprehensive integration tests for JWT authentication, CLI approval, public route registry, and controller endpoints.
* **Build process simplification** - Removed `cp` command from build process in Makefile. Binary compilation streamlined to eliminate unnecessary file operations.
* **Documentation updates** - Updated CLI documentation, architecture docs, and guides to reflect substrate-only architecture. Removed g8ee-specific references and device-link command documentation.
* **Protocol constants regeneration** - Protocol constants regenerated after g8ee path removal. Generated Go constants updated to match protocol JSON definitions.

### Fixed

* **Outbound L3 notary bug** - Fixed L3 notary to correctly verify and sign outbound transactions. Previous implementation did not properly handle suspended transaction states for outbound mutations.
* **Gateway security vulnerabilities** - Fixed multiple security issues in gateway authentication and request handling. Improved validation of user inputs, session tokens, and request boundaries.
* **CLI approval integration** - Fixed CLI approval command integration with Gateway JWT authentication. Approval flow now correctly validates CLI signatures and updates suspended transaction state.
* **Test isolation issues** - Fixed test isolation problems in gateway integration tests. Tests now properly clean up database state and avoid cross-test contamination.
* **Public route matching** - Fixed public route matching logic to correctly handle both exact paths and prefixes. Previous implementation had edge cases where authenticated routes were incorrectly exposed.

### Security

* **JIT user lockout prevention** - One-time valid JWT mechanism prevents users from being locked out during JIT enrollment failures. Ensures recovery path for authentication errors.
* **L3 notary hardening** - Outbound transaction verification now strictly enforces L3 signature requirements. Suspended transactions cannot bypass L3 checks.
* **Gateway request validation** - Enhanced request validation prevents malformed or malicious requests from reaching internal services. Stricter bounds checking on payload sizes and field values.
* **Public route registry** - Centralized public route definition eliminates accidental exposure of authenticated endpoints. All public routes are explicitly registered and auditable.
