## [2.0.1] - 2026-08-19

### Overview

CLI command-surface split: `auth enroll` becomes a parent command with three subcommands (`user`, `operator`, `gui`), `security pki enroll` is removed and re-surfaced as `auth enroll operator`, and the top-level `gui` command moves under `auth enroll` as `auth enroll gui`. The two distinct enrollment code paths (local human CLI/user enrollment vs. remote operator/device enrollment) are now explicitly separated at the command surface, and all frontend-origin enrollment is grouped under the same `auth enroll` namespace. This is a user-visible breaking change to the command surface; no enrollment behavior, flags, file formats, or gateway-side endpoints change.

### Changed

* **`auth enroll` split into `auth enroll user` + `auth enroll operator` + `auth enroll gui`** — The previous `auth enroll` command (local human CLI/user enrollment via the `EnrollmentCoordinator` state machine, browser passkey ceremony, and OS trust installation) is now `auth enroll user`. The previous `security pki enroll` command (remote operator/device CSR enrollment via `EnrollRemoteOperator`, headless and operator-only) is now `auth enroll operator`. The previous top-level `gui` command (frontend origin enrollment with `enroll`/`show`/`verify`/`remove` subcommands) is now `auth enroll gui`. Bare `auth enroll` (no subcommand) prints help and exits non-zero, forcing explicit session-type selection. The `enrollCmd()` constructor is now the parent; the previous `enrollCmd()` is renamed `enrollUserCmd()` and the previous `enrollCmdWithConfig(...)` is renamed `enrollUserCmdWithConfig(...)` (signature and body unchanged). The operator command body moves verbatim from `internal/cli/cmd/security.go` to a new file `internal/cli/cmd/auth_enroll_operator.go` with `Use: "operator"` and error-wrap prefixes updated from `"security: ..."` to `"auth enroll operator: ..."`.
* **`security pki enroll` removed** — The `securityPKICmd`, `securityPKIEnrollCmd`, `securityPKIEnrollCmdWithConfig`, `remoteOperatorEnroller`, and `defaultRemoteOperatorEnroller` symbols are deleted from `internal/cli/cmd/security.go`. `securityCmd` now registers only `security validate`. The `pki` subcommand is gone. No compatibility shim is added (rip and replace, per the global rules).
* **`gui` re-parented from root to `auth enroll`** — `guiCmd()` is removed from `rootCmd.AddCommand(...)` in `internal/cli/cmd/main.go` (root subcommand count drops from 14 to 13) and added to `enrollCmd().AddCommand(...)` in `internal/cli/cmd/auth.go` alongside `enrollUserCmd()` and `enrollOperatorCmd()`. The `gui` command's internal behavior, subcommands, flags, and enrollment file format are unchanged; only the parent registration moves. User-facing strings inside `gui.go` and `tunnel.go` that referenced `g8e gui enroll` are updated to `g8e auth enroll gui enroll`.
* **User-facing stdout and help strings updated** — `gwstdout.go`, `gateway.go`, `tui.go`, `operator.go`, `mcp.go`, and `approve_recovery.go` replace `auth enroll` with `auth enroll user` in next-step guidance, help text, and error messages. Code comments in `internal/cli/auth/*` and `internal/services/gateway/*` that referenced the old command names are updated for accuracy.

### Removed

* **`security pki` subcommand group** — The `pki` subcommand of `security` is removed entirely. `security` now has only `validate`. Operator/device enrollment is at `auth enroll operator`.

### Breaking Changes

* **`g8e auth enroll`** → **`g8e auth enroll user`**. Scripts and docs that run `g8e auth enroll` must update to `g8e auth enroll user`. Bare `auth enroll` now prints help and exits non-zero.
* **`g8e security pki enroll`** → **`g8e auth enroll operator`**. Scripts and docs that run `g8e security pki enroll` must update to `g8e auth enroll operator`. The `security pki` command group is removed.
* **`g8e gui`** → **`g8e auth enroll gui`**. Scripts and docs that run `g8e gui <subcommand>` must update to `g8e auth enroll gui <subcommand>`. The `gui` command is no longer at the root level.
