## [2.0.1] - 2026-08-25

### Overview

v2.0.1 migrates the Go module path from `github.com/g8e-ai/g8e` to `github.com/g8e-ai/g8e/v2`, bringing the module path into compliance with the Go module versioning convention for v2 and later releases. Per [Go's major version suffix rule](https://go.dev/doc/modules/versioning#major-version), a module whose version is v2.0.0 or higher must include a `/v2` suffix in its module path. The v2.0.0 release bumped the version to `v2.0.0` without updating the module path; v2.0.1 corrects that omission so external Go consumers can resolve the module correctly via the Go module proxy.

This is a breaking change for external Go consumers: all import paths and `go get` commands must include the `/v2` suffix. The Python protocol package, the platform binary, the wire protocol, and all on-disk formats are unchanged. The migration is mechanical — every `github.com/g8e-ai/g8e` import path in the Go source, generated protobuf code, `.proto` `go_package` options, Makefile, and CI workflow is rewritten to `github.com/g8e-ai/g8e/v2`.

### Breaking Changes

* **Go module path changed from `github.com/g8e-ai/g8e` to `github.com/g8e-ai/g8e/v2`** — External Go consumers must update all import paths from `github.com/g8e-ai/g8e/...` to `github.com/g8e-ai/g8e/v2/...` and update `go get` commands to `go get github.com/g8e-ai/g8e/v2@vX.Y.Z`. The Go module proxy cannot resolve v2.0.0+ tags against a module path without the `/v2` suffix; this release fixes that. The migration path is mechanical: add `/v2` after the module root in every import and `go get` invocation. See the migration notes below.

### Changed

* **`go.mod` module path rewritten to `github.com/g8e-ai/g8e/v2`** — The root module declaration changes from `module github.com/g8e-ai/g8e` to `module github.com/g8e-ai/g8e/v2`, the canonical Go module path for v2+ releases.
* **All Go import paths updated to include `/v2`** — Every `import "github.com/g8e-ai/g8e/..."` statement across the Go source tree (`cmd/`, `internal/`, `protocol/proto/`, `protocol/examples/`, `internal/tools/`, `test/`) is rewritten to `import "github.com/g8e-ai/g8e/v2/..."`. Generated protobuf Go code (`*.pb.go`) and the Lattice adapter generated stubs (`internal/adapters/lattice/gen/`) are regenerated with the new `go_package` options.
* **All `.proto` `go_package` options updated** — The `option go_package = "github.com/g8e-ai/g8e/..."` declarations in `protocol/proto/g8e/` and `third_party/anduril/anduril/` are rewritten to `option go_package = "github.com/g8e-ai/g8e/v2/..."` so regenerated code lands in the correct package path.
* **`Makefile` swagger generation and release comments updated** — The `packagePrefix` argument to `swag init` and the release-workflow comments referencing the Go module path are updated to `github.com/g8e-ai/g8e/v2`.
* **`.github/workflows/release-binary.yml` fresh `go install` verification updated** — The post-release verification step that runs `go install github.com/g8e-ai/g8e/cmd/g8e@vX.Y.Z` is updated to `go install github.com/g8e-ai/g8e/v2/cmd/g8e@vX.Y.Z` so the verification resolves against the correct module path.
* **`protocol/docs/mcp_tool_template.go` import updated** — The example MCP tool template's import of `internal/constants` is updated to the `/v2` path.
* **Documentation reconciled with the new module path** — All guide, architecture, reference, and developer docs that reference the Go module path or `go get` commands are updated to the `/v2` path: `docs/guides/getting_started.md`, `docs/guides/build_gateway.md`, `docs/guides/build_operator.md`, `docs/guides/build_apps.md`, `docs/guides/connect_apps_to_gateway.md`, `docs/guides/connect_operator_to_gateway.md`, `docs/guides/air_gap.md`, `docs/architecture/protocol.md`, `docs/devs/release_process.md`, `README.md`, `protocol/README.md`, and `third_party/anduril/anduril/README.md`. GitHub repository URLs (`https://github.com/g8e-ai/g8e`) are unchanged — only Go module paths and `go get` commands carry the `/v2` suffix.

### Fixed

* **Go module path compliance with the major version suffix rule** — The v2.0.0 release declared `VERSION = v2.0.0` and created the `v2.0.0` git tag, but the `go.mod` module path remained `github.com/g8e-ai/g8e` without the `/v2` suffix. The Go module proxy cannot resolve a v2.0.0+ tag against a module path that lacks the major version suffix; external consumers running `go get github.com/g8e-ai/g8e@v2.0.0` would resolve to v1.7.8 (the highest v1 tag) or fail. v2.0.1 fixes this by migrating the module path to `github.com/g8e-ai/g8e/v2`, the canonical path for v2+ releases.

### Migration Notes for External Consumers

External Go consumers importing the g8e protocol or internal packages must update their imports and `go get` commands:

Before (v2.0.0 and earlier):

```bash
go get github.com/g8e-ai/g8e@v2.0.0
```

```go
import (
    "github.com/g8e-ai/g8e/protocol"
    "github.com/g8e-ai/g8e/protocol/proto/g8e/common/v1"
)
```

After (v2.0.1):

```bash
go get github.com/g8e-ai/g8e/v2@v2.0.1
```

```go
import (
    "github.com/g8e-ai/g8e/v2/protocol"
    "github.com/g8e-ai/g8e/v2/protocol/proto/g8e/common/v1"
)
```

The change is mechanical: insert `/v2` after the module root (`github.com/g8e-ai/g8e`) in every import path and `go get` command. The Python protocol package (`pip install g8e`), the platform binary, the wire protocol, and all on-disk formats are unchanged. The GitHub repository URL (`https://github.com/g8e-ai/g8e`) is unchanged — only the Go module path carries the `/v2` suffix.

### Out of Scope

* **No wire protocol, on-disk format, CLI surface, or Python package changes** — This release is a pure Go module path migration. The `GovernanceEnvelope` wire format, the `.g8e/` runtime tree layout, the `g8e` CLI command surface, and the `g8e` Python package on PyPI are all unchanged. The Python package version is bumped to `2.0.1` to keep the protocol and platform version numbers in sync, but no Python source changes are made.
* **No new features, bug fixes beyond the module path, or test changes** — The single commit in this release is the module path migration. Generated protobuf byte offsets shift slightly due to the longer `go_package` string in the serialized file descriptors, but the wire format is unchanged.
