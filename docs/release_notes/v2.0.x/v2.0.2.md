## [2.0.2] - 2026-08-26

### Overview

v2.0.2 fixes two operational gaps that surfaced when running the gateway in Docker: the serving certificate did not cover the host's real IPs and hostname (the container's loopback identity was used instead), and the serving certificate was not regenerated when new IPs or DNS names appeared on the host after the initial issuance. The release also adds a `.dockerignore` to keep secrets and local runtime state out of the image build context, changes the bare `g8e` invocation to print usage instead of launching the TUI, and bumps several dependencies.

### Changed

* **Network identity detector reads host-mounted `/etc/hosts.host` and `/etc/hostname.host`** — When the gateway runs in a Docker container, the root `docker-compose.yml` and each demo's `compose.yml` now bind-mount the host's `/etc/hosts` and `/etc/hostname` read-only into the container at `/etc/hosts.host` and `/etc/hostname.host`. `network.Detector.detectIPs` and `detectHostnames` read these host-mounted files before the container's own `/etc/hosts` and `/etc/hostname`, and `detectEtcHosts` merges aliases from both sources with de-duplication. `NetworkIdentity.GetAllIPs` de-duplicates IPs by string value. This ensures the serving certificate's SANs cover the host's real IPs and hostname rather than the container's loopback identity. New path constants `PathEtcHostsHost` and `PathEtcHostnameHost` are defined in `internal/constants/paths.go`.
* **Bare `g8e` invocation prints usage instead of launching the TUI** — `internal/cli/cmd/main.go` removes the root command's `RunE` handler that launched the Tactical Governance Console on a bare `g8e` invocation. Running `g8e` with no subcommand now prints help/usage. The TUI is still available via `g8e tui`. The root command's long description is updated to direct users to `g8e tui`.
* **Dependency version bumps** — `github.com/fxamacker/cbor/v2` v2.9.2 → v2.9.3, `github.com/stretchr/testify` v1.11.1 → v1.12.1, `golang.org/x/crypto` v0.54.0 → v0.55.0, `golang.org/x/net` v0.56.0 → v0.57.0, `golang.org/x/text` v0.40.0 → v0.41.0, `google.golang.org/grpc` v1.83.0 → v1.83.1, `google.golang.org/protobuf` v1.36.11 → v1.36.12. The indirect `go.yaml.in/yaml/v3 v3.0.5` is added as a testify v1.12.1 dependency; the now-indirect `github.com/davecgh/go-spew` and `github.com/pmezard/go-difflib` are removed from the direct require block.

### Added

* **`.dockerignore`** — A new `.dockerignore` at the repository root excludes git metadata, IDE/agent tooling, OS artifacts, local development scratch, secrets, local `.g8e/` runtime state, build outputs, and documentation from the Docker build context. The polyglot services (ensemble, dashboard) carry their own per-Dockerfile ignore files which take precedence under BuildKit. `.gitignore` no longer ignores `.dockerignore` so the file is tracked.
* **Service certificate SAN drift detection** — `internal/services/gateway/gateway_certs.go` adds `detectServiceCertDrift`, which compares the SANs in an existing service certificate against the expected IPs and DNS names and returns any that are missing (additive drift). `loadOrGenerateServiceCertWithNames` now regenerates the serving certificate at startup when drift is detected, logging the missing names. Removal of a name from the host does not trigger regeneration. Covered by `internal/services/gateway/gateway_certs_drift_test.go`.

### Fixed

* **Gateway serving certificate did not cover host identity in Docker** — When the gateway ran in a container, the network identity detector only saw the container's network interfaces and `/etc/hosts`, so the serving certificate's SANs covered the container's loopback and bridge IPs rather than the host's real IPs and hostname. The host-mounted `/etc/hosts.host` and `/etc/hostname.host` bind mounts and the updated detector ensure the host's real identity is included.
* **Serving certificate was not regenerated when host IPs or DNS names changed** — The serving certificate was regenerated only when missing or expiring within 30 days. If new IPs or DNS names appeared on the host after the initial issuance (for example, a new network interface or hosts-file alias), the certificate was not updated until expiry. SAN drift detection at startup now regenerates the certificate when expected IPs or DNS names are missing.
