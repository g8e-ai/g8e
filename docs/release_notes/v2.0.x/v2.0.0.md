## [2.0.0] - 2026-08-19

### Overview

DropOps is re-unified as the complete g8e platform. The repository grows from a single-language Go platform into a polyglot monorepo that ships the entire product end to end: the g8e wire protocol, the gateway/operator Go binary, the first g8e-compatible agentic ensemble (g8ee, Python/FastAPI), and the operator dashboard (g8ed, Node.js/Express). The ensemble and dashboard stop being external consumers of g8e and become fully supported, in-tree components. The whole stack — gateway, operator, ensemble, and dashboard — runs end to end in Docker from the repo-root `docker-compose.yml`, the same end-to-end behavior the `sauvren` scratch-pad repo carried as a first pass, now on the hardened g8e core.

This is a major version bump (v1.7.8 to v2.0.0) because it changes the shape of the repository and the product: the repo grows from a Go platform into a polyglot monorepo (Go platform + Python ensemble + Node.js dashboard), and the platform gains a first-party ensemble and dashboard as supported components. It is also the release that closes the loop on the DropOps split: g8ee and g8ed were ripped out of the g8e repo so that g8e core could be hardened in isolation, and are now brought back home.

The ensemble and dashboard are imported as raw source from the `sauvren` scratch-pad fork and brought up to g8e's bar. sauvren's Go platform fork is ignored entirely — its manual modifications were already re-implemented, in different ways, here in the g8e repo (g8e is at v1.7.8, ahead of sauvren's v1.7.7). What is mined from sauvren is exactly two source trees (`ensemble/` and `frontend/`, the latter renamed to `dashboard/`) and the Docker compose wiring proven to bring the unified stack up end to end. Nothing else from sauvren is imported: no Go fork, no root Dockerfile, no root compose, no `deploy/Dockerfile.gateway`, no `sauvren.py`, no uv workspace.

### Added

* **`ensemble/` — g8ee, the first g8e-compatible agentic ensemble** — Python 3.12 / FastAPI application imported as a first-party component. Depends on the in-tree `protocol/python/` package via a path dependency in `pyproject.toml` (editable install in Docker, no PyPI dependency on the published `g8e` package). Ships `ensemble/Dockerfile` rooted at the g8e repo root so it can `COPY protocol/python` and `COPY ensemble`. Tests stay co-located under `ensemble/tests/` and `ensemble/evals/` (Tier 1 unit, in-component). BSL 1.1 headers and metadata applied across all source; the sauvren Apache 2.0 LICENSE is replaced.
* **`dashboard/` — g8ed, the operator dashboard** — Node.js 22 / Express application imported as a first-party component (renamed from sauvren's `frontend/` to `dashboard/` to describe what it is, not where it runs). Ships `dashboard/Dockerfile` rooted at the g8e repo root and a newly created `dashboard/LICENSE` (sauvren's `frontend/` had no LICENSE file at all). Tests stay co-located under `dashboard/test/` (Tier 1 unit, in-component). BSL 1.1 headers and metadata applied across all source.
* **`ensemble` and `dashboard` services in the repo-root `docker-compose.yml`** — The existing gateway + operator compose is extended (not replaced) with `ensemble` and `dashboard` services modeled on sauvren's `deploy/docker-compose.yml`. The env-var wiring (`G8E_GATEWAY_URL`, `G8E_OPERATOR_URL`, `G8E_OPERATOR_PUBSUB_URL`, `G8E_RUNTIME_DIR`, `G8E_PKI_DIR`, `G8E_CA_CERT_PATH`) is carried over but re-derived for g8e's layout: g8e's gateway runs with `working_dir: /root` and the volume at `/root/.g8e`, so the ensemble's runtime/PKI/CA paths point at `/root/.g8e` and `/root/.g8e/pki/trust/g8eg-ca-bundle.pem`, not sauvren's `/home/g8e/.g8e` paths. The dashboard reuses sauvren's `GATEWAY_HEALTH_URL`/`GATEWAY_HEALTH_PATH` pattern, pointed at the g8e gateway's network alias. `docker compose up` from the repo root now brings up gateway, operator, ensemble, and dashboard as a healthy stack.
* **`document_id(name)` accessor in `protocol/python/g8e/constants.py`** — g8e loaded `DOCUMENT_IDS` from `document_ids.json` but shipped no accessor for it, while providing accessors for every other loaded JSON constant (`collection`, `channel`, `intent`, `prompt`, `kv_key`, `kv_session_type`). The ensemble depends on this helper. Ported from sauvren's protocol copy as a legitimate protocol gap fix (placed after `channel()` to match the grouping of simple accessors) with `test_document_id_accessor` and `test_document_id_invalid_key_raises` added to `TestAccessorFunctions` in `protocol/python/tests/test_constants.py`.
* **`docs/architecture/ensemble.md`** — Describes g8ee as the first g8e-compatible ensemble, its role in the platform, and how it connects to the gateway over mTLS.
* **`docs/architecture/dashboard.md`** — Describes g8ed and its relationship to the gateway.
* **Makefile targets for the ensemble and dashboard builds** — `make ensemble` and `make dashboard` build the respective Docker images from their in-tree Dockerfiles; `make build-all` builds the Go binary plus both images.
* **CI jobs for the polyglot matrix** — Python (ensemble: ruff, pyright, pytest) and Node.js (dashboard: vitest, lint) jobs alongside the existing Go CI. Ported from sauvren's workflow definitions for the ensemble and dashboard jobs only; the sauvren Go CI is not ported.
* **Tier 3 E2E for the unified compose** — A new end-to-end test brings up the unified `docker-compose.yml` and exercises the ensemble to gateway to operator path end to end.

### Changed

* **`VERSION` bumped from `v1.7.8` to `v2.0.0`** — Major version bump reflecting the polyglot monorepo shape and the first-party ensemble/dashboard.
* **`README.md` presents the platform as protocol + gateway/operator + ensemble + dashboard** — Product description and badges updated to reflect that the repo now ships the ensemble and dashboard as first-party components.
* **`docs/architecture/overview.md` includes the ensemble and dashboard in the platform map** — The single-page architecture overview now describes all four components.
* **`docs/guides/` getting-started guide for the unified Docker stack** — Documents that `docker compose up` brings up the whole platform.
* **`.gitignore` and `.dockerignore` cover polyglot artifacts** — `node_modules/`, `coverage/` (Node), and `*.egg-info/` added so the ensemble and dashboard build contexts stay small and no build artifacts are committed. The existing Python entries (`.venv/`, `__pycache__/`) already covered the ensemble context.
* **`make ci` runs the polyglot lint/test matrix** — Go, Python, and Node.js lint and test jobs run in the single `make ci` target.

### License

* **All ensemble and dashboard source is BSL 1.1** — Everything brought in from sauvren becomes Business Source License 1.1, matching the g8e platform license (changed in v1.7.7). The sauvren ensemble was Apache 2.0; the sauvren frontend had no LICENSE file at all. All source headers, package metadata (`pyproject.toml`, `package.json`), LICENSE files, and CI license-compliance checks are updated to BSL 1.1 with the same Change Date (2030-08-18) as the rest of the platform. No Apache 2.0 artifacts remain in-tree after the reunification.

### Release Model

* **`make release` is unchanged for v2.0.0** — The Go binary remains the only `make release` artifact. The ensemble and dashboard ship as Docker images built from their in-tree Dockerfiles, but tagging and shipping those images through the release pipeline is deferred to the next release after v2.0.0. The ensemble and dashboard Docker images are build-only this release.

### Out of Scope

* Rewriting the ensemble or dashboard. This is a reunification/import + license + build/CI alignment, not a rewrite.
* Changing the g8e protocol or gateway/operator binary behavior. The ensemble and dashboard are consumers of the existing platform surface.
* Merging the sauvren git history into the g8e git history. The components are imported as a snapshot; sauvren remains a scratch pad.
* Importing any part of sauvren's Go platform fork, root Dockerfile, root compose, `deploy/Dockerfile.gateway`, `sauvren.py`, or the root uv workspace.
