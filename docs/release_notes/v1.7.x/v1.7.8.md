## [1.7.8] - 2026-08-19

### Overview

Platform logging consolidation and pub/sub pattern subscriptions. The scattered logger configuration code in `internal/cli/serve/logger.go` is replaced by a dedicated `internal/services/logging` package that owns the `.g8e/logs/g8e.log` file lifecycle and slog handler for all daemon-mode callers, and the log filename is renamed from `operator.log` to `g8e.log` to reflect that it is the single platform log shared by gateway and operator daemons. The gateway pub/sub broker gains Redis-compatible `PSUBSCRIBE` glob-pattern subscriptions with fail-closed topic ACLs that confine the wildcard to the subscriber's own operator_id segment, preventing cross-operator heartbeat interception. Several MCP native tools are refactored to use typed request/result structs instead of ad-hoc anonymous structs and `map[string]interface{}` payloads, and a new `docs/architecture/overview.md` provides a single-page map of the platform that cross-links into the existing architecture docs.

### Added

* **`internal/services/logging` package** — Centralized platform logging. `LogService` owns the `.g8e/logs/g8e.log` file lifecycle (path resolution, open via `RuntimeFileService`, logger wiring) for daemon-mode callers (`RunGateway`, `StartOperator`). The slog handler (`logHandler`), level parsing (`parseLogLevel`), and logger constructors (`NewLogger`, `NewStdoutLogger`) live here so that `LogService` is the single owner of all logging concerns. CLI client commands use `NewStdoutLogger` directly and do not construct a `LogService`. Files: `handler.go` (slog handler and level parsing), `logger.go` (`NewLogger`, `NewStdoutLogger`), `log_service.go` (`LogService`, `ConfigureFileLogger`, `OpenLogForAppend`, `OpenLogForRead`, `LogFileExists`, `LogFilePath`).
* **`RuntimeFileService.OpenForAppend` and `OpenForRead`** — `OpenForAppend` opens a file for streaming append (`O_CREATE|O_WRONLY|O_APPEND`), creates parent directories, and returns the raw `*os.File` for the caller to close. Used for log files where `WriteFile`'s atomic tmp+rename is wrong. `OpenForRead` opens an existing file for streaming read (tail/follow) and returns `constants.ErrNotFound` if the file does not exist. Implemented in `internal/services/fs/file_service_append.go`.
* **`PSUBSCRIBE` pattern subscriptions on the gateway pub/sub broker** — `GatewayWebSocketHandler` now registers glob-pattern subscribers in a parallel `patternSubscribers` map keyed by glob pattern. `Publish` matches the published channel against each registered pattern with `path.Match` (same glob semantics as Redis `PSUBSCRIBE` and the mock gateway's `fnmatch`) and delivers a `pmessage` event (`PubSubEventPMessage`) to every matching subscriber. The Python client sends `UNSUBSCRIBE` for both exact and pattern subscriptions (there is no separate `PUNSUBSCRIBE` action on the wire); the broker evicts from both maps on unsubscribe. The `PubSubActionPSubscribe` and `PubSubEventPMessage` constants and the `pattern` field on `PubSubEvent` were already defined in `protocol/constants/channels.json` and the protobuf; this release wires the broker-side implementation.
* **`verifyPatternACL` topic ACL for pattern subscriptions** — Mirrors `verifyChannelACL` but permits the wildcard `*` only at the operator_id segment position (parts[1]) of the pattern. Cross-operator patterns such as `heartbeat:op-other:*` are rejected so a subscriber cannot `PSUBSCRIBE heartbeat:*` and receive every operator's heartbeats. A pattern with a concrete operator_id that does not match the subscriber's own is rejected. Enforced before the pattern is registered.
* **`docs/architecture/overview.md`** — New single-page architecture overview that describes what g8e is, the five-layer governance pipeline, governance postures, the intent-to-execution flow, identity and enrollment, encryption, storage and audit, the SSE event bridge, the protocol library, scripts and tooling, key design principles, and an index into the rest of the architecture docs. Cross-links to the existing per-topic architecture docs instead of duplicating their content.
* **Typed request/result structs for MCP native tools** — `SysEnvVarsRequest`/`SysEnvVarsResult`, `ProcTreeRequest`, `TLSCertInspectRequest`, `SysContainerStatusRequest`, `GitOpsRequest`, `DBDiscoverTopologyRequest`/`DBDiscoverTopologyResult`, `DBIsolatedReadRequest`, `DBQueryValidateRequest`, `ProcSignalSafeRequest`, `SysOOMDetectRequest` in `internal/services/mcp/models.go`. The corresponding tool `Execute` methods unmarshal into these typed structs instead of ad-hoc anonymous structs, and the tools that previously returned `map[string]interface{}` (`sys_env_vars`, `db_discover_topology`) now return their typed result struct.

### Changed

* **Log filename renamed from `operator.log` to `g8e.log`** — `constants.OperatorLogFilename` is replaced with `constants.G8eLogFilename` in `internal/constants/paths.go`. `internal/paths/paths.go` renames the `Infra.OperatorLogFile` field to `Infra.G8eLogFile` (both struct types), the default value, `InitWithBase`, and the package-level `OperatorLogPath` var to `G8eLogPath`. `protocol/docs/constants.md` updates the component filenames list. The file is the single platform log shared by gateway and operator daemons, so the `g8e` name is accurate; the old `operator` name was a leftover from when the operator was the only daemon that wrote to it.
* **`RunGateway` and `StartOperator` log through `LogService`** — `internal/cli/serve/gateway.go` constructs a `LogService` and calls `ConfigureFileLogger` instead of manually creating the log directory, opening the log file with `os.OpenFile`, and calling `ConfigureLoggerWithOutput`. `internal/cli/serve/operator.go` calls `logging.NewStdoutLogger` instead of `serve.ConfigureLogger`. `internal/cli/platform/process.go` constructs a `LogService` in `NewProcessManager`, exposes it via `pm.LogService()`, and `StartOperator` opens the log handle via `logSvc.OpenLogForAppend`. `GetLogPath` delegates to `logSvc.LogFilePath`.
* **`g8e logs` command uses `LogService`** — `internal/cli/cmd/gateway.go` checks log file existence via `logSvc.LogFileExists`, opens the log for read via `logSvc.OpenLogForRead`, and passes the handle to `platform.TailLog`. The nonexistent-file case is now handled by the caller through `LogFileExists` / `OpenLogForRead` returning `constants.ErrNotFound` instead of `TailLog` handling `os.Open` errors.
* **`platform.TailLog` signature changed to `io.ReadSeeker`** — `TailLog(logPath string, follow bool)` is now `TailLog(r io.ReadSeeker, follow bool)`. The caller opens the file via the file service and passes the handle; `TailLog` no longer handles `os.Open` errors. The nonexistent-file case is handled by the caller.
* **`internal/cli/serve/logger.go` deleted** — The logger configuration code (`ConfigureLogger`, `ConfigureLoggerWithOutput`, `operatorHandler`, `parseLogLevel`) moves to `internal/services/logging`. The old `logger_test.go` moves to `internal/services/logging/handler_test.go` with updated function references (`ConfigureLogger` → `NewStdoutLogger`, `ConfigureLoggerWithOutput` → `NewLogger`, `newOperatorHandler` → `newLogHandler`, `operatorHandler` → `logHandler`).
* **`docs/devs/codemap.md` updated** — The `internal/cli/serve/logger.go` entry is replaced with an `internal/services/logging/` entry describing `LogService`, the slog handler, and the logger constructors. The `RuntimeFileService` interface method list adds `OpenForAppend` and `OpenForRead`.
* **Swagger annotations use typed response objects** — `HandleMCP` and `HandleA2aCall` in `internal/services/mcp/` now annotate `@Success 200 {object} response.JSONRPCResponse` and `@Success 200 {object} mcp.A2ASuccessResponse,mcp.A2ASuspensionResponse` respectively, instead of `map[string]interface{}`, so the generated OpenAPI schema describes the actual response shapes.

### Fixed

* **Demo observability containers tail the correct log file** — The `healthcare`, `finance`, `dhs`, and `frontend` demo `compose.yml` files and the `healthcare` and top-level `demos` READMEs referenced `/data/gateway/logs/operator.log`, which no longer exists after the rename to `g8e.log`. Updated all four compose files and both READMEs to reference `/data/gateway/logs/g8e.log` so the observability containers tail the platform log instead of waiting forever for a file that never appears.
* **`convertToFieldValue` schema-less passthrough documented** — `internal/services/mcp/field_parser.go` `convertToFieldValue` adds a doc comment explaining that the `[]interface{}` and `map[string]interface{}` type-switch cases walk arbitrary JSON decoded from external sources (document store fields, cloud metadata, command outputs) where the schema is unknown by design. This is the same schema-less passthrough exception as `ScrubMap`/`scrubSlice`/`RehydratePayload` in `internal/services/scrubbing/boundary.go`; the output is the typed `FieldValue`, so callers receive a typed model regardless of input.

### Security

* **`PSUBSCRIBE` pattern ACL is fail-closed** — `verifyPatternACL` runs before a pattern is registered. A pattern with no operator_id segment (`len(parts) < 2`) is rejected with `ErrPubSubInvalidChannelFormat`. A pattern whose operator_id segment is neither `*` nor the subscriber's own operator_id is rejected. The wildcard is permitted only at the operator_id segment position (parts[1]); cross-operator patterns are rejected so a subscriber cannot `PSUBSCRIBE heartbeat:*` and receive every operator's heartbeats. An empty operator_id (missing from the certificate) is rejected with `ErrPubSubCertificateMissingOperatorID`.
