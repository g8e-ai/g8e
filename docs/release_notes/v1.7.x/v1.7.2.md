## [1.7.2] - 2026-08-12

### Overview

CLI enrollment refactor. This release replaces the scattered, multi-function
CLI enrollment path (`BootstrapWithURL`/`CLIEnroll`/`ReEnroll`/
`EnrollWithGateway`/`AutoRenewCertificate`) with a single
`EnrollmentCoordinator` that owns the enrollment state machine, adds a
human-approved CLI recovery flow for new CLIs against an existing gateway,
adds an mTLS-protected CLI certificate rotation endpoint, builds in OS trust
installation before browser launch, removes the `--tpm` flag (file-backed
EC P-256 keys on all platforms), and removes the legacy per-platform
trust-install script routes. This is a **breaking change** for any client
that called the removed `/api/v1/auth/cli/enroll` endpoint or fetched the
removed trust-install scripts.

### Breaking

* **`/api/v1/auth/cli/enroll` (`handleCLIEnrollment`) removed** — The
  legacy CLI enrollment endpoint is gone. CLI enrollment is now driven
  client-side by the `EnrollmentCoordinator`, which calls the bootstrap,
  recovery, and rotation endpoints as needed. The `constants.APIPaths.
  AuthCLIEnroll` constant is removed. External clients that called this
  endpoint must migrate to the recovery flow (for new CLIs against an
  existing gateway) or the bootstrap endpoint (for the first CLI on a
  fresh gateway).
* **Per-platform trust-install script routes removed** —
  `/web-cert.sh`, `/web-cert.ps1`, and
  `/.well-known/g8e/pki/trust-windows` are gone. OS trust installation
  is now performed client-side by the `EnrollmentCoordinator` via
  `platform.SystemTrustInstaller` before browser launch. The
  `constants.APIPaths` constants for these routes are removed.
* **`--tpm` flag removed** — All platforms now use file-backed EC P-256
  CLI keys. The `--tpm` flag and its associated `KeyProvider` build-tag
  machinery are removed. The `KeyProvider` interface remains as the
  extension point for future non-exportable platform keys (TPM/CNG).

### Added

* **`EnrollmentCoordinator`** (`internal/cli/auth/enrollment.go`) —
  Single owner of the CLI enrollment state machine. Decides whether to
  bootstrap, recover, rotate, or reuse the local CLI identity based on
  `CredentialStore.Inspect` classification (absent/complete/partial/
  corrupt). Never writes to stdout/stderr directly (uses `OutputFunc`),
  never opens a browser except via `BrowserOpener`/`PasskeyRegistrar`,
  never invokes sudo except via `SystemTrustInstaller`. Injectable
  dependencies via `EnrollmentCoordinatorDeps` (nil fields get
  production defaults). The command layer's `enrollCoordinatorFactory`
  package-level var returns an `Enroller` interface for test mocking.
* **`CredentialStore`** (`internal/cli/auth/credential_store.go`) —
  Typed API over local CLI identity files. `Inspect` classifies local
  state as a set. `Stage`/`Commit` write a new identity atomically
  (credentials last). `Rollback` releases staged state. `Clear` removes
  local credentials for logout/recovery but retains the shared OS root
  CA (§4.3 ownership). Concurrent-safe via `sync.Mutex`.
* **CLI recovery flow** — New human-approved recovery for enrolling a
  new CLI against an already-bootstrapped gateway. Endpoints:
  `POST /api/v1/auth/cli/recovery/request` (public, CSR is
  proof-of-possession anchor),
  `GET /api/v1/auth/cli/recovery/status` (public, opaque token lookup),
  `POST /api/v1/auth/cli/recovery/approve` (web-session protected,
  existing user authorizes),
  `POST /api/v1/auth/cli/recovery/complete` (public, requires token +
  CSR private-key signature). Gateway-side:
  `CLIRecoveryController` (`cli_recovery_controller.go`),
  `CLIRecoveryService` (`cli_recovery_service.go`). Token is hashed
  (SHA-256) at rest; state transitions are atomic via
  `DocConditionalUpdate`; request is bound to CSR public-key
  fingerprint.
* **CLI rotation endpoint** — `POST /api/v1/auth/cli/rotate`
  (mTLS-protected, `RouteAuthMTLS`). Identity derived from verified
  mTLS certificate URI SAN — request body fields are NOT trusted.
  Single transactional replacement: new cert signed before old session
  deactivated, old cert revoked after session replacement commits.
  Gateway-side: `CLIRotationController`
  (`cli_rotation_controller.go`). Registered on `buildPublicRouter`
  only, never on plain HTTP.
* **Built-in OS trust installation** — `auth enroll` installs the
  gateway root CA into the OS trust store before opening the browser
  for the passkey ceremony. `--no-system-trust` skips this step
  (administrator-managed trust opt-out, NOT a passkey bypass). System
  trust failure stops before browser launch. Browser-restart guidance
  printed after installation.
* **`EnrollmentClient`** (`internal/cli/auth/enrollment_client.go`) —
  Gateway enrollment transport. HTTP I/O only: receives
  `context.Context`, returns typed `EnrollmentArtifacts`, writes no
  files, performs no UI/platform work. Satisfies `EnrollmentGateway`
  interface. Replaces the old transport slices.
* **`FileKeyProvider`** (`internal/cli/auth/key_provider.go`) —
  File-backed EC P-256 key generation on all platforms. Implements
  `KeyProvider` interface.
* **`PasskeyRegistrar` interface + hardened `passkeyRegistrar`** —
  Browser-based passkey registration ceremony. Prepares SSE listener
  before browser launch, uses `since_id=0` cursor for live-only
  events, filters by type/user/session, surfaces browser-open errors,
  propagates context cancellation.
* **`CLIRecoveryControllerDeps` / `CLIRotationControllerDeps`** —
  Per-controller `Deps` structs for the two new gateway controllers,
  following the v1.7.1 decomposition pattern.

### Changed

* **`auth enroll` behavior** — Re-running `auth enroll` with a
  healthy identity now reuses it (no new certificate, no privilege
  prompt). Use `--rotate-cli` to force rotation. Partial/corrupt
  local state triggers the recovery flow, not a silent overwrite.
  Expiring certificates (within 24h of expiry) are auto-rotated.
* **`auth logout` behavior** — Removes local CLI credential material
  (CLI cert, CLI key, credentials JSON) but does NOT remove the
  shared OS root CA. `CredentialStore.Clear` no longer calls
  `DeleteCredentials` (which removed the trust bundle). This was a
  real bug caught by `TestLogoutCmd_OSRootCARetained`.
* **`mcp stdio` vs `mcp agent run`** — `mcp stdio` is a credential
  consumer only; it loads credentials and builds the mTLS connection,
  never invoking the enrollment coordinator. `mcp agent run` runs the
  interactive `EnrollmentCoordinator` with default
  `EnrollmentOptions{}`.
* **`gwstdout.go`** — `auth enroll` blurb updated to mention built-in
  OS trust installation and `--no-system-trust`.
* **`HTTPHandler` controller count** — Now 18 controller fields (was
  16 in v1.7.1): added `CLIRecoveryController` and
  `CLIRotationController`.

### Removed

* **`handleCLIEnrollment` route/handler/constant** — Replaced by the
  client-side `EnrollmentCoordinator` + recovery/rotation endpoints.
* **`/web-cert.sh`, `/web-cert.ps1`, `/.well-known/g8e/pki/trust-windows`
  routes** — Replaced by client-side `SystemTrustInstaller`.
* **`BootstrapWithURL`, `CLIEnroll`, `ReEnroll`, `EnrollWithGateway`,
  `AutoRenewCertificate`, `CheckBootstrapStatus` (enrollment transport
  functions)** — Replaced by `EnrollmentClient` methods.
* **`--tpm` flag** — File-backed EC P-256 keys on all platforms.
* **`auth_integration_test.go`** — Deleted (stale `ReEnroll` comments,
  skipped test asserting nothing at runtime).
