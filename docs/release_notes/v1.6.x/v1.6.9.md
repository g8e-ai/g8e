## [1.6.9] - 2026-08-02

### Overview

FedRAMP 20x (CR26) compliance release. g8e now derives binary Key Security Indicator (KSI) status from live audit state and exports machine-readable OSCAL evidence artifacts for the FedRAMP 20x Class C certification path. A new `g8e compliance` CLI command exposes KSI evaluation, OSCAL export, historical snapshot retention, and COSAiS overlay ingestion. L1 doctrine detectors carry typed `ksi_ids`/`control_ids`/`overlay_ids` fields that project into emitted `ThreatSignal` values, providing traceability from governance enforcement to compliance evidence. The release also refines the FIPS `g8e version --fips` self-check to distinguish approved mode from enforcement, renames the `commitment_ledger` column to lowercase for naming consistency, and adds a CI guard for COSAiS overlay detector coverage.

### Added

* **`g8e compliance` command** — New top-level command (FedRAMP 20x KSI evaluation and OSCAL export) with four subcommands. Affected files: `internal/cli/cmd/compliance.go`, `internal/cli/cmd/main.go`.
  - `g8e compliance export --format oscal --class C` — generates OSCAL `component-definition` and `assessment-results` JSON artifacts from the KSI catalog and g8e's live evaluation state. Both artifacts are always emitted; the command fails if the audit store or ledger are unavailable. Output defaults to `.g8e/data/compliance/`. Flags: `--format` (only `oscal`), `--class` (A/B/C/D, default C), `--out`, `--catalog`.
  - `g8e compliance ksi --class C` — evaluates KSIs against live state and prints the result set as JSON. Flags: `--class`, `--catalog`.
  - `g8e compliance ksi-history [--ksi <id>]` — reads persisted KSI evaluation snapshots from `.g8e/data/compliance/ksi-history/`, optionally filtered by KSI ID. Flag: `--ksi`.
  - `g8e compliance overlay --overlay-dir <dir>` — loads and validates COSAiS overlay catalogs, detecting dangling KSI references and duplicate IDs. Flags: `--overlay-dir`, `--catalog`.
* **Compliance package (`internal/services/compliance/`)** — New package with typed KSI/OSCAL/COSAiS tooling (92.8% coverage):
  - `ksi.go` — typed KSI model (`KSI`, `KSIMethod`, `KSIResult`, `KSIResultSet`, `KSICatalog`) with typed enums for `KSICategory`, `KSIStatus`, `CertificationClass`, `ValidationCycle`, `EvidenceType`. No raw maps.
  - `ksi_evaluator.go` — `KSIEvaluator` with `RegisterMethods`/`RegisterDefaultMethods`/`Evaluate`. Derives binary KSI status from live g8e state via `EvaluatorDeps` (audit store, ledger, commitment ledger). Enforces minimum method counts per certification class (fail-closed for Class C: at least 2). `DefaultMethods` provides 8 reusable method closures bound to automatable KSIs.
  - `oscal.go` — `OSCALExporter` with `GenerateComponentDefinition` and `GenerateAssessmentResults`. Typed OSCAL structs; evidence anchors link to receipt IDs, ledger commit hashes, and LFAA execution IDs.
  - `ksi_history.go` — `KSIHistoryStore` with `SaveSnapshot`/`ListSnapshots`/`GetHistoryForKSI`/`PruneOlderThan`. Persists `KSIResultSet` snapshots to `.g8e/data/compliance/ksi-history/` via `RuntimeFileService`; 90-day retention pruning.
  - `overlay_loader.go` — `Overlay`/`OverlayCatalog`/`OverlayStatus` types with `LoadOverlayCatalog`, `LoadOverlaysFromDir`, `Validate`, `FindOverlay`/`HasOverlay`, `ValidateOverlayRefs`, and `CheckFinalizedOverlayCoverage` (Phase 8 CI guard).
* **KSI catalog (`docs/reference/ksi-catalog.json`)** — Typed per-KSI catalog defining 31 KSIs across 10 categories (CED, CMT, CNA, IAM, INR, MLA, PIY, RCP, SVC, TPR), seeded from the CR26 reference and cross-checked against RFC-0006 and RFC-0014. Each KSI binds to automated methods, control refs, applicable certification classes, and a validation cycle.
* **COSAiS overlay catalog (`docs/reference/cosais-overlays.json`)** — Placeholder catalog seeding 5 overlay entries from the NIST COSAiS concept paper use cases, all with `status: draft` until NIST finalizes.
* **`make validate-cosais` target and CI guard** — `scripts/validate-cosais-overlays.sh` checks that finalized COSAiS overlays have detector `overlay_ids` coverage. Added to `make lint` and as a CI workflow step in `build-and-test.yml`. Affected files: `Makefile`, `scripts/validate-cosais-overlays.sh`, `.github/workflows/build-and-test.yml`.
* **Container compliance support** — `Dockerfile` now copies `docs/reference` into the runtime image (`/docs/reference`) so `g8e compliance ksi/export` works in containers. `docker-compose.yml` sets `working_dir: /root` on both services so named volumes at `/root/.g8e` are used correctly. Affected files: `Dockerfile`, `docker-compose.yml`.
* **Doctrine KSI/control/overlay linkage** — L1 doctrine entries now carry typed `ksi_ids`, `control_ids`, and `overlay_ids` fields that project into emitted `ThreatSignal` values, providing traceability from governance enforcement to compliance evidence. The FedRAMP demo doctrine maps all 5 detectors to specific KSI IDs and NIST 800-53 controls. Affected files: `internal/services/governance/l1_doctrine.go`, `demos/fedramp/doctrine/fedramp_doctrine.json`.
* **Compliance error and path constants** — `ErrKSICatalogInvalid`, `ErrOverlayCatalogInvalid`, `ErrOverlayReadFailed`, `ErrOverlayParseFailed`, `ErrKSIHistoryWriteFailed`, `ErrKSIHistoryReadFailed`, `ErrKSIHistoryParseFailed`, `ErrKSIHistoryEmpty` in `internal/constants/errors.go`. `ComplianceDirname`, `KSICatalogFilename`, `COSAiSOverlaysFilename`, `OSCALAssessmentResultsFilename`, `OSCALComponentDefFilename`, `KSIHistoryDirname`, `KSIHistoryFilenamePrefix`, `DefaultKSICatalogPath`, `DefaultOverlayDirPath`, `KSIHistoryRetentionDays`, `ContainerKSICatalog` in `internal/constants/paths.go`.

### Changed

* **`g8e version --fips` distinguishes approved mode from enforcement** — The command now exits non-zero only if FIPS approved mode is NOT active. If approved mode is active but enforcement is off (the common production posture when non-approved primitives such as ChaCha20-Poly1305 SSH are required), it prints a warning and exits 0 — informational for operators, not a failure. CI/release gates that require the strict posture run under `GODEBUG=fips140=only`. Affected files: `internal/cli/cmd/version.go`, `internal/cli/cmd/version_test.go`.
* **`make verify-fips` runs under `GODEBUG=fips140=only`** — `GOFIPS140` alone only enables approved mode (`GODEBUG` defaults to `fips140=on`); the verify target now sets `GODEBUG=fips140=only` at runtime to switch the module into enforcement mode (rejecting non-approved primitives), confirming both approved mode AND enforcement are active. Affected files: `Makefile`.
* **`commitment_ledger` column renamed to lowercase** — `Actuator_intent_signature_digest` renamed to `actuator_intent_signature_digest` in the schema DDL, the `ListCommitments` query, and the `AppendCommitmentJSON` attestation struct/insert. SQLite is case-insensitive for column names so this is cosmetic; a migration `ALTER TABLE ... RENAME COLUMN` runs on existing databases (skipped as a no-op on new databases or already-migrated tables). Affected files: `internal/services/storage/audit_store.go`, `internal/services/storage/commitment_ledger.go`.
* **FedRAMP demo emits KSI evidence** — `demos scenarios run` for the FedRAMP org now runs a KSI Evidence Export step after all scenarios: emits KSI result snapshots via `g8e compliance ksi --class C` inside the gateway container, then verifies them via `verify_ops.py --ksi-result`. The demo README documents the typed KSI mapping per category. Affected files: `internal/cli/cmd/demo_fedramp.go`, `internal/cli/cmd/demos.go`, `demos/fedramp/README.md`, `demos/fedramp/verify_ops.py`, `demos/fedramp/target-data/ksi_categories.json`.
* **Documentation reconciliation** — `docs/reference/compliance-alignment.md` gained a FedRAMP 20x (CR26) Alignment section (certification classes, KSI model, OSCAL export, historical metrics, COSAiS overlays, doctrine/detector KSI linkage, demo KSI mapping) and an evidence repository table for the compliance package. `docs/architecture/operator.md` audit trail section now documents the `g8e compliance` command family. `docs/devs/codemap.md` updated with the compliance package, its files, coverage, error/path constants, CI guard, and container support. `docs/devs/devs.md` notes that `TestSQLAuditStore` satisfies `compliance.AuditEvidenceReader`. Affected files: `docs/reference/compliance-alignment.md`, `docs/architecture/operator.md`, `docs/devs/codemap.md`, `docs/devs/devs.md`.
