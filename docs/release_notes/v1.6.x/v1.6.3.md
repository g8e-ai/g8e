## [1.6.3] - 2026-07-25

### Overview

AuthController decomposition, PasskeyOrchestrator extraction, L1 doctrine threat detector expansion, and MCP gateway threat scanning delegation. This release continues the gateway HTTP handler decomposition started in v1.6.1 by splitting the monolithic `AuthController` into four focused sub-controllers (`BootstrapController`, `EnrollmentTokenController`, `UserController`, `SessionController`). The `PasskeyHandler` is further refactored by extracting business orchestration (MCP service calls, suspended transaction management, SSE/WebSocket event publishing) into a new `PasskeyOrchestrator`, leaving the handler with only HTTP-layer concerns. The L1 doctrine threat detection system is expanded with six new credential leak and privilege escalation detectors mapped to MITRE ATT&CK T1552 and T1548.003. The MCP gateway's `scanForForbiddenPatterns` now delegates to a `ThreatScanner` interface backed by `L1Doctrine` instead of using hardcoded substring matching, and request body reading is unified into a shared `readRequestBody` helper with proper limit enforcement.

### Added

* **L1 doctrine credential leak detectors** — `internal/services/governance/l1_doctrine.go`: Five new `InputThreatDetector` entries in `initializeInputThreatDetectors`:
  - `cred_leak_password_assignment` — detects `password=<value>` patterns (high severity, T1552)
  - `cred_leak_api_key_assignment` — detects `api_key=<value>` patterns (high severity, T1552)
  - `cred_leak_secret_assignment` — detects `secret=<value>` patterns (high severity, T1552)
  - `cred_leak_token_assignment` — detects access/refresh/auth/bearer/session/api token assignments (high severity, T1552)
  - `cred_leak_private_key_block` — detects PEM private key blocks (critical severity, T1552.004)
* **L1 doctrine privilege escalation detector** — `internal/services/governance/l1_doctrine.go`: `privesc_su_command` detector for `su` command usage with login/command flags (high severity, T1548.003).
* **`PasskeyOrchestrator`** — `internal/services/gateway/passkey_orchestrator.go` (new, 147 lines): Encapsulates cross-cutting business concerns of the passkey approval flow — MCP service provision (`GetSuspendedTransaction`, `ResumeWithL3Proof`), suspended transaction listing (`ListSuspendedTransactions`), and SSE event publishing (`EmitApprovalCompletedSSE`, `EmitPasskeyRegisteredSSE`). `PasskeyHandler` delegates to this orchestrator, retaining only HTTP-layer concerns.
* **`ThreatScanner` interface** — `internal/services/mcp/gateway.go`: New interface implemented by `governance.L1Doctrine` that exposes `AnalyzeCommand` for regex-based threat detection. Added to `Dependencies` struct and wired in `gateway_service.go` via `governance.NewL1Doctrine()`.
* **`FieldPathRegistryFactory`** — `internal/services/mcp/gateway.go`: Optional dependency injection field on `Dependencies` that overrides the default `NewFieldPathRegistry` constructor, allowing tests to inject a failing factory to verify error handling.
* **`BootstrapController`** — `internal/services/gateway/bootstrap_controller.go` (renamed from `auth_controller_bootstrap.go`): Handles bootstrap endpoints (local bootstrap, bootstrap status, CLI enrollment, device enrollment) with a typed `BootstrapControllerDeps` struct.
* **`EnrollmentTokenController`** — `internal/services/gateway/enrollment_token_controller.go` (new): Handles enrollment token generation and validation with a typed `EnrollmentTokenControllerDeps` struct.
* **`UserController`** — `internal/services/gateway/user_controller.go` (renamed from `auth_controller_session.go`): Handles user management endpoints (`handleUsers`, `handleUserMe`) with a typed `UserControllerDeps` struct.
* **`SessionController`** — `internal/services/gateway/session_controller.go` (new): Handles web session lifecycle (logout, session info) with a typed `SessionControllerDeps` struct.
* **`DBControllerDeps` struct** — `internal/services/gateway/db_controller.go`: Typed dependency struct replacing positional constructor parameters for `DBController`.
* **`readRequestBody` helper** — `internal/services/gateway/gateway_http.go`: Shared request body reader using `io.LimitReader` with explicit size check, returning `constants.ErrPayloadExceedsLimit` when the limit is exceeded. Replaces incorrect `http.MaxBytesReader(nil, ...)` calls that passed a nil `ResponseWriter`.

### Changed

* **AuthController decomposed** — `internal/services/gateway/auth_controller.go` (deleted): The monolithic `AuthController` and its `AuthControllerDeps` struct are removed. Its responsibilities are split across `BootstrapController`, `EnrollmentTokenController`, `UserController`, and `SessionController`. `HTTPHandler` now holds references to all four sub-controllers instead of a single `authController`.
* **Router updated for sub-controllers** — `internal/services/gateway/gateway_http_router.go`: All routes previously dispatched to `authController` now dispatch to the appropriate sub-controller (`bootstrapController`, `enrollmentTokenController`, `userController`, `sessionController`).
* **PasskeyHandler simplified** — `internal/services/gateway/passkey_service.go`: `PasskeyHandler` struct fields reduced from `mcpSvc`, `suspendedStore`, `sseStore`, `pubsub` to a single `orchestrator *PasskeyOrchestrator`. `PasskeyHandlerDeps` updated accordingly. SSE emission methods (`emitApprovalCompletedSSE`, `emitPasskeyRegisteredSSE`) removed from `PasskeyHandler` and moved to `PasskeyOrchestrator`.
* **Passkey approval handlers delegate to orchestrator** — `internal/services/gateway/passkey_service_approvals.go`: `handleApprovalChallenge`, `handleApprovalVerify`, and related methods now call `h.orchestrator.*` instead of `h.mcpSvc.*` / `h.sseStore.*` / `h.pubsub.*`.
* **Passkey registration SSE delegation** — `internal/services/gateway/passkey_service_http.go`: `RegisterVerify` handler now calls `h.orchestrator.EmitPasskeyRegisteredSSE` instead of inline `h.emitPasskeyRegisteredSSE`. The inline method is removed.
* **MCP gateway threat scanning delegated** — `internal/services/mcp/gateway.go`: `scanForForbiddenPatterns` now calls `g.threatScanner.AnalyzeCommand` and checks `sig.BlockRecommended` instead of iterating hardcoded substring patterns. The former pattern list (`sudo`, `su `, `rm -rf /`, `://`, `password`, `api_key`, `secret`, `token`, `private_key`) is replaced by the full L1 doctrine detector suite with regex-based word-boundary matching.
* **FieldPathRegistry init errors now fatal** — `internal/services/mcp/gateway.go`: `NewGatewayService` now returns an error if `FieldPathRegistry` initialization fails, instead of logging and continuing without it. This prevents silent degradation of `read_field` capability.
* **GatewayService suspended tx field cleanup** — `internal/services/gateway/gateway_service.go`: Removed redundant `suspendedTxCloser` field; `Stop` now calls `suspendedTxService.Close()` directly. `PasskeyOrchestrator` is constructed in `build()` and passed to `NewPasskeyHandler`.
* **DBController and OperatorController use shared `readRequestBody`** — `internal/services/gateway/db_controller.go`, `operator_controller.go`: Both controllers now call the shared `readRequestBody` helper instead of their respective `http.MaxBytesReader` calls.
* **Developer codemap updated** — `docs/devs/codemap.md`: Updated to reflect the AuthController decomposition, new sub-controllers, `PasskeyOrchestrator`, and `readRequestBody` helper.

### Fixed

* **Request body limit enforcement** — `internal/services/gateway/gateway_http.go`, `db_controller.go`, `operator_controller.go`: The previous `http.MaxBytesReader(nil, r.Body, limit)` call passed a nil `http.ResponseWriter`, which meant the `MaxBytesReader` could not set HTTP error headers on overflow — it would silently truncate or panic depending on the reader state. Replaced with `io.LimitReader` + explicit size check returning `constants.ErrPayloadExceedsLimit`, ensuring consistent limit enforcement across all controllers.
