# Release Notes — v1.3.10

**Date:** 2026-07-10

## Overview

v1.3.10 is a CORS support, build hardening, and protocol cleanup release. This version adds configurable cross-origin browser access via `--cors-origin` flags with proper SameSite cookie handling, unifies all build targets with `-trimpath` and reproducible build tags, adds a `build-compressed` target with UPX, cleans up committed protocol binaries, and fixes the WebAuthn assertion response model to match the nested JSON format expected by go-webauthn.

## Added

* **CORS Middleware** — New `corsMiddleware` on `HTTPHandler` in `internal/services/gateway/gateway_http_cors.go` validates request origins against a configurable allowlist, sets `Vary: Origin` and `Access-Control-Allow-Origin` headers, and handles OPTIONS preflight with proper `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, and `Access-Control-Max-Age` headers. Disallowed origins are silently rejected (no CORS headers set). Origin matching is case-insensitive and trailing-slash tolerant. The middleware wraps the public router via `h.corsMiddleware(h.pathTraversalGuard(h.auth.Middleware(mux)))` in `buildPublicRouter`.
* **`--cors-origin` Flag** — New repeatable gateway flag (`--cors-origin`) configures allowed CORS origins for cross-origin browser access (e.g., `--cors-origin https://lovable.dev`). Plumbed through `GatewayFlags` in `internal/cli/cmd/gateway.go`, `GatewayConfig` in `internal/cli/serve/gateway.go`, `BuildReExecArgs` in `internal/cli/platform/process.go`, `config.GatewayConfig` and `config.GatewayOptions` in `internal/config/config.go`. When origins are configured, the gateway sets `CrossOrigin: true` on `PasskeyHandler` and `AuthController` via `PasskeyHandlerDeps.CrossOrigin` and `AuthControllerDeps.CrossOrigin`.
* **`build-compressed` Makefile Target** — New `make build-compressed` target runs `make build` then compresses the binary with UPX (`--best --lzma`). Includes install instructions for Debian/Ubuntu, macOS, and Arch Linux. Checks for UPX availability before attempting compression.
* **CORS HTTP Header Constants** — Added `HeaderAccessControlAllowHeaders`, `HeaderAccessControlAllowMethods`, `HeaderAccessControlMaxAge`, `HeaderConnection`, `HeaderVary`, and `HeaderValueCORSPreflightMaxAge` (`"3600"`) in `internal/constants/auth.go`.
* **`ParsedAssertionResponse` Models** — Added `ParsedAssertionResponse` and `ParsedAssertionResponseBody` in `internal/models/webauthn.go` to represent the nested JSON format expected by go-webauthn during assertion verification. Fields: `ID`, `RawID`, `Type`, and nested `Response` with `ClientDataJSON`, `AuthenticatorData`, `Signature`.
* **`AuthControllerDeps` Struct** — Extracted `AuthControllerDeps` in `auth_controller.go` to group all `AuthController` constructor parameters (14 fields), including a new `CrossOrigin` field for SameSite cookie mode selection. `newAuthController` now accepts `AuthControllerDeps` instead of individual parameters.

## Changed

* **Unified Build Flags** — All Makefile build targets (`build`, `build-all`, `build-darwin`, `build-windows`, `build-docker`, `build-linux-docker`, `build-windows-docker`, `build-darwin-docker`, `build-all-docker`) now use `-trimpath`, `-tags netgo,osusergo`, and `-s -w` strip flags consistently. Introduced `TRIMPATH`, `BUILD_TAGS`, and `STRIP_FLAGS` Makefile variables. Eliminated the previous Windows-only special-casing for strip flags (`WINDOWS_EXTRA_FLAGS`).
* **Cross-Origin Cookie Handling** — `setWebSessionCookie` in `passkey_service_http.go` and `handlePublicAuthLogout` in `auth_controller_session.go` now set `SameSite=None` when cross-origin origins are configured (`h.crossOrigin == true`), instead of always using `SameSite=Lax`. This enables browser sessions to work across origins (e.g., `https://lovable.dev` accessing `https://demo.g8e.ai`).
* **SSE CORS Headers Centralized** — `handleInternalSSEStream` in `gateway_http_sse.go` no longer sets inline `Access-Control-Allow-Origin` / `Access-Control-Allow-Credentials` headers. CORS is now handled uniformly by the CORS middleware on the public router. SSE header constants replaced with `constants.HeaderContentType`, `constants.HeaderCacheControl`, `constants.HeaderConnection`, and `constants.HeaderXAccelBuffering`.
* **WebAuthn Assertion Verification** — `VerifyL3Proof` in `passkey_service.go` now uses `models.ParsedAssertionResponse` instead of an inline `map[string]interface{}` for the assertion response, matching the nested JSON format expected by go-webauthn's `webauthn.ParseCredentialRequestResponse`.
* **Dockerfile Base Image** — Switched from pinned digest (`golang@sha256:f96cc555eb8db430159a3aa6797cd5bae561945b7b0fe7d0e284c63a3b291609`) to `golang:1.26.5` tag for the builder stage, matching the Go version used in CI.
* **Protocol Makefile** — Simplified Go version detection in `protocol/Makefile` to use `go` directly instead of probing for `go1.24` via complex shell logic.
* **Protocol Spec Version** — Updated `protocol/docs/spec.md` version header to v1.3.10 and date to 2026-07-10.
* **Protocol Python Version** — Updated `protocol/python/pyproject.toml` and `protocol/python/g8e/__init__.py` to v1.3.10.
* **Gateway Guide** — Added `--public-base-url` and `--cors-origin` flags to the Gateway Mode Flags section in `docs/guides/build_gateway.md`. Updated version header to v1.3.10.

## Removed

* **Go Report Card Badge** — Removed from `README.md` badge row. The service was unreliable and provided no actionable feedback beyond what `golangci-lint` already covers in CI.
* **Committed Protocol Binaries** — Removed `protocol/governance_envelope` (16 MB) and `protocol/workload_identity` (2.7 MB) compiled binaries from the repository. These were accidentally committed build artifacts. Added `protocol/governance_envelope` and `protocol/workload_identity` to `.gitignore`.
* **Unused Python Imports** — Removed unused `uuid4` import from `protocol/python/g8e/models/base.py`, unused `typing.Any` from `protocol/python/g8e/models/context.py` and `protocol/python/g8e/models/settings.py`.

## Fixed

* **Protocol Example Constants** — `protocol/python/examples/constants_example.py` now references `STATUS['status']` instead of `STATUS['operator']` to match the actual JSON structure in `protocol/constants/status.json`.
* **Protocol Governance Envelope Example** — Updated `protocol/examples/governance_envelope/main.go` to use `"hash-123"` as the transaction ID (was `"txn-abc-123"`) and removed deprecated `MtlsCertFingerprint` and `CliSignature` fields from the L3 proof, matching the current protobuf schema.
* **Python Constants Encoding** — `protocol/python/g8e/constants.py` now opens JSON files with `encoding="utf-8"` explicitly in `_load_protocol_json`.

## Tests

* Added `internal/services/gateway/gateway_http_cors_test.go` (172 lines) — comprehensive CORS middleware tests:
  - `TestCORSMiddleware_AllowedOriginSetsAllowOrigin` — allowed origin gets CORS headers
  - `TestCORSMiddleware_DisallowedOriginDoesNotSetAllowOrigin` — disallowed origin gets no CORS headers, `Vary: Origin` still set
  - `TestCORSMiddleware_NoOriginHeaderDoesNotSetAllowOrigin` — no Origin header means no CORS headers
  - `TestCORSMiddleware_PreflightAllowedOriginReturns204` — OPTIONS preflight from allowed origin returns 204 with full preflight headers
  - `TestCORSMiddleware_PreflightDisallowedOriginDoesNotShortCircuit` — OPTIONS from disallowed origin falls through to next handler
  - `TestCORSMiddleware_OriginMatchingIsCaseInsensitive` — case-insensitive origin matching
  - `TestCORSMiddleware_OriginMatchingTrimsTrailingSlash` — trailing slash tolerance in origin matching
* Added `TestPasskeyCookieCrossOriginSameSiteNone` in `passkey_service_http_test.go` — verifies `SameSite=None` and `Secure=true` cookie attributes when `crossOrigin` is set.
* Updated `gateway_http_sse_test.go` — `TestHandleInternalSSEStream_SSEHeadersSet` no longer asserts inline CORS headers (handled by middleware). `TestHandleInternalSSEStream_SSEHeadersWildcardOrigin` renamed to `TestHandleInternalSSEStream_SSEHeadersNoOrigin` and updated to assert no `Access-Control-Allow-Origin` header when no Origin is present.
* Updated `auth_controller_test.go` — added `CrossOrigin` field to `AuthControllerDeps` in test setup.
* Updated `gateway_test.go` — added `AllowedOrigins` field to `GatewayFlags` in test setup.
