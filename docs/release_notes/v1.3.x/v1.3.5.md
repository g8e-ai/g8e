## [1.3.5] - 2026-07-02

### Overview

v1.3.5 is an air-gap readiness and demo integrity release. This version completes the air-gap initiative: the Dockerfile now builds with vendored Go modules (`-mod=vendor`) requiring zero network access during compilation, all external Docker images are pinned to sha256 digests, a new `demos/Dockerfile` copies the pre-built binary instead of compiling inside containers, and a `demos/airgap.sh` helper script automates image export/import for disconnected environments. Demo cleanup includes removing the `demos audit` subcommand and `printDataDump` function, adding `forceRemoveLeftovers` for thorough teardown, and rewriting `setup_metabase.py` to use stdlib `urllib` instead of the `requests` dependency. Documentation across all guides and references now clarifies "zero runtime dependencies" (build-time only) rather than the previous "zero external dependencies" phrasing.

### Added

* **Air-Gap Image Manifest** — Added `demos/images.json` listing all external Docker images used across all demo environments with pinned sha256 digests and per-demo usage mapping. Images include `alpine`, `python:3.11-slim`, `nginx:alpine`, `node:20-alpine`, `rabbitmq:3-management`, `postgres:15`, `metabase/metabase`, `golang:1.26`, and `debian:bookworm`.

* **`g8e demos pull` Command** — Added `demosPullCmd` in `demos.go` that reads `demos/images.json` and pulls each image by its pinned digest. This is the first step for air-gapped deployment — run on a connected machine before exporting.

* **Air-Gap Helper Script** — Added `demos/airgap.sh` (executable) with three subcommands: `export` (pull and save all manifest images to `.tar` files), `import` (load `.tar` files into local Docker daemon), and `list` (show all images in the manifest). Uses `python3` for JSON parsing (available in all demo environments).

* **`demos/Dockerfile`** — New dedicated Dockerfile for demo containers that copies the pre-built binary from `demos/bin/g8e` into a minimal pinned Debian image. No compilation happens inside the container. All demo compose files now reference `build: context: ..` with this Dockerfile instead of `context: ../..` with the root Dockerfile.

* **`make test-airgap` Target** — Added Makefile target that verifies air-gap readiness: checks `vendor/` and `protocol/vendor/` directories exist, builds with `-mod=vendor`, verifies `demos/images.json` is present, checks no unpinned image references (`:latest`, `:alpine`, `:slim`, `:bookworm`) remain in compose files, verifies no `pip install` or `import requests` in demo Python files, and confirms `demos/airgap.sh` is executable.

* **`forceRemoveLeftovers` Helper** — Added in `demos.go` — after `docker compose down`, force-removes any leftover volumes and networks matching the project prefix, preventing stale state from interfering with subsequent demo runs.

* **Air-Gap Documentation** — Added comprehensive air-gapped deployment section to `demos/README.md` covering the full workflow: pre-pull, export, transfer, import, build, and verify. Updated `docs/guides/air_gap.md` with vendored build details, image pinning workflow, and `make test-airgap` verification step.

### Changed

* **Dockerfile Uses Vendored Modules** — Root `Dockerfile` now copies `vendor/` and `protocol/vendor/` directories and sets `GOFLAGS=-mod=vendor`, eliminating `go mod download` during container builds. Base images pinned to sha256 digests (`golang@sha256:...`, `debian@sha256:...`). Runtime stage comments clarify that installed packages (curl, CA certs) are container conveniences, not binary dependencies.

* **Demo Build Context Simplified** — All demo compose files (`gov`, `finance`, `healthcare`, `secure-data`, `dow`, `dhs`, `swarm`) changed from `build: context: ../..` (compiling from source inside container) to `build: context: ..` (copying pre-built binary via `demos/Dockerfile`). Operator commands updated from `["-e", "10.32.0.10"]` to `["operator", "run", "-e", "10.32.0.10"]` across all swarm operators.

* **All Docker Images Pinned** — Every `image:` reference in all demo compose files replaced with sha256-digest-pinned references (e.g., `alpine:latest` → `alpine@sha256:28bd5fe8...`).

* **`make build` Copies to Demos** — The `build` target now automatically copies the compiled binary to `demos/bin/g8e`, eliminating the manual `cp g8e demos/bin/g8e` step.

* **`demos clean` Improved** — `--yes` flag default changed to `true` (skip confirmation by default). `docker compose down` now uses `--remove-orphans -t 0` flags. Compose down errors are treated as warnings rather than failures, followed by `forceRemoveLeftovers` for thorough cleanup.

* **`setup_metabase.py` Rewritten** — Replaced `requests` library with stdlib `urllib.request` and `json` modules, eliminating the `pip install requests` runtime dependency. All HTTP calls (`_http_get`, `_http_post`) use `urllib.request.urlopen` with proper error handling via `urllib.error.HTTPError`.

* **Documentation Clarified** — Updated `README.md`, `docs/core/about.md`, `docs/guides/build_gateway.md`, `docs/guides/build_operator.md`, `docs/guides/getting_started.md`, and `docs/reference/compliance-alignment.md` to clarify that g8e has "zero runtime dependencies" with "all dependencies resolved at build time" rather than the previous "zero external dependencies" phrasing. Removed OpenSSL from runtime prerequisite lists.

* **Air-Gap Guide Updated** — `docs/guides/air_gap.md` updated to v1.3.5. Build phase description changed from "external network access required" to "network access only needed for initial `go mod vendor`". Added details about vendored build with `-mod=vendor` and `GOFLAGS=-mod=vendor`. Added step 4 (pre-pull Docker images) and step 5 (verify air-gap readiness) to the deployment workflow.

### Removed

* **`demos audit` Subcommand** — Removed the `demosAuditCmd` command and all related functions: `runDemosAudit`, `runDockerComposeExec`, `runDockerComposeLogs`, `runG8EAuditCmd`. The `g8e audit` CLI command (run inside the operator container) remains the canonical way to inspect audit data.

* **`printDataDump` Function** — Removed the `printDataDump` function and its call from `runAllScenarios`. The platform data dump was redundant with the `g8e audit` CLI commands.

* **`captureCommand` Function** — Removed from `demos.go` (no longer used after `printDataDump` removal).

### Fixed

* **Healthcare Scenario 4 Error Tracking** — Scenario 4 (Bad Actor PHI Exfiltration Blocked) now properly tracks errors from the network isolation check and `healthcare-phi-blocked` harness scenario. Previously, errors were silently discarded with `_ =`; now they set `hasErrors = true` and the scenario reports `FAIL` status when any step fails.

* **`.gitignore` Vendor Exception** — Added exception to `.gitignore` to not ignore the vendored operator proto package (`!vendor/github.com/g8e-ai/g8e/protocol/proto/g8e/operator/`), ensuring it's tracked in git for air-gapped builds.

### Tests

* Added `TestDemosPullCmd` in `demos_test.go` covering pull subcommand registration, metadata, and `imageManifestEntry` struct JSON tags.
* Removed `TestDemosAuditCmd`, `TestSqliteOnlyInAuditCmdVaultAction`, `TestCaptureCommand`, `TestRunG8EAuditCmd`, and `TestPrintDataDump` tests for deleted functions.
* Removed `audit` from the expected subcommands list in `TestDemos`.
