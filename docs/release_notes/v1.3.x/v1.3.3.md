## [1.3.3] - 2026-06-29

### Overview

v1.3.3 is a demos infrastructure and passkey configuration release. This version adds injectable WebAuthn RP origins for Docker deployments with remapped host ports, introduces a dedicated mTLS endpoint for pending approvals, refactors demo scenarios into a reusable two-layer pattern, and improves gateway startup output with posture-aware guidance. Demo READMEs are added for all demo environments, and PKI trust/deploy scripts now use the configured HTTP port instead of a hardcoded default.

### Added

* **Injectable Passkey RP Origins** — Added `--passkey-rp-origin` flag (repeatable) to `gw start`/`gw serve` that appends additional origins to the WebAuthn allowlist via `PasskeyConfig.RpOrigins`. The `buildRPOrigins` pure function (`internal/services/gateway/passkey_service.go`) constructs the full origin list: localhost defaults (HTTP/HTTPS on both `localhost` and `127.0.0.1` at configured ports) or a single `https://<custom-rp-id>` for custom RP IDs, followed by any injected origins. This enables demos that publish the gateway on remapped host ports (e.g. `http://localhost:8087`) to accept WebAuthn ceremonies from the browser without cert changes — TLS cert validity is not port-sensitive and `http://localhost:<port>` is a secure context. The flag propagates through `GatewayConfig` → `OperatorStartOptions` → `BuildReExecArgs` for re-exec persistence.

* **CLI Pending Approvals Endpoint** — Added `handleCLIListSuspended` (`GET /api/v1/approvals/pending`, mTLS-protected) that returns only non-approved suspended transactions. The existing `handleListSuspendedTransactions` (`GET /api/v1/approvals`, WebSession-protected) continues to return all transactions including approved ones. Added `ApprovalsCLIList` constant to `internal/constants/api_paths.go` and synced to `protocol/constants/api_paths.json`. Registered route in `gateway_http_router.go` and added excluded prefix in `PublicRouteRegistry` (`gateway_auth.go`) to prevent the mTLS endpoint from being bypassed by the WebSessionAuth public prefix for `/api/v1/approvals`.

* **Posture-Aware Gateway Startup Guidance** — Added `printNextSteps` in `internal/cli/cmd/gwstdout.go` that outputs posture-specific next steps after gateway start:
  - Step 1: CLI credential enrollment (all postures)
  - Step 2: Posture-specific governance setup (doctrine: no additional setup; consensus: tribunal configuration; notary: tribunal + passkey enrollment)
  - Step 3: Remote operator deployment options (deploy, stream, PKI enroll, remote script with `curl`/`irm`)
  - Step 4: AI agent connection (`mcp show`, `mcp stdio`)
  - Console UI URL and management/monitoring commands

* **Docker Pre-Flight Check** — Added `checkDockerAvailable` helper in `demos.go` that verifies Docker is running before executing any demo subcommand (start, stop, status, clean, rebuild), providing a clear error message instead of a confusing Docker failure.

* **Gov/Finance Agent Harness Scenarios** — Added `govFinanceScenarios` in `internal/tools/agent_harness/scenarios/gov_finance.go` with two doctrine-enforcement scenarios:
  - `gov-cui-exfil-block` — CUI exfiltration attempt blocked by L1 doctrine (`cui_exfil_attempt` at confidence 0.95)
  - `finance-unauthorized-trade` — Unauthorized trade execution blocked by L1 doctrine

* **Two-Layer Demo Scenario Pattern** — Added `runTwoLayerScenario` helper and `twoLayerScenarioConfig` struct in `internal/cli/cmd/demos.go` for reusable demo scenario orchestration. Refactored gov and finance demo scenarios to use this pattern, replacing inline scripted theater with structured scenario execution.

* **Demo READMEs** — Added comprehensive READMEs for `demos/finance/`, `demos/gov/`, `demos/healthcare/`, and `demos/secure-data/`. Updated `demos/swarm/README.md`.

* **Console URLs in Demo Endpoints** — `printDemoEndpoints` now prints the console URL for all demos (healthcare, gov, finance, secure-data, dow, dhs). Added swarm demo endpoints (`localhost:8085`/`8448`).

### Changed

* **PasskeyConfig Expanded** — Added `RpOrigins`, `HTTPPort`, and `HTTPSPort` fields to `PasskeyConfig`. `buildRPOrigins` uses configurable ports (defaulting to `constants.Ports.OperatorHttp`/`OperatorHttps`) instead of hardcoded 8080/8443, supporting non-default port configurations.

* **PKI Trust/Deploy Scripts Use Configured Port** — `PKIController` now uses `gatewayHTTPPort()` helper instead of hardcoded `constants.Ports.OperatorHttp` in all trust script handlers (Linux, macOS, Windows) and deploy script handlers (Linux, Windows). The helper reads `cfg.Gateway.HTTPPort` and falls back to the default constant.

* **DHS Demo Harness URLs** — Changed DHS demo harness URLs from IP-based (`10.62.0.10:8443`) to hostname-based (`g8e.local:8443`). Removed `--insecure` flag from DHS harness run command.

* **Agent Harness Default Public URL** — Changed `Default()` in `internal/tools/agent_harness/config/config.go` to use `LocalhostHTTPURL` for `PublicBaseURL` instead of HTTPS, matching the HTTP bootstrap port.

* **Windows Script Commands** — Changed Windows deploy script from `Invoke-WebRequest` to `Invoke-RestMethod` in `internal/services/gateway/scripts/g8e-deploy.ps1`. Updated `docs/architecture/auth.md` and `docs/guides/connect_operator_to_gateway.md` to use `irm` instead of `iwr -UseBasicParsing` for trust scripts.

* **Swagger Command Port** — `internal/cli/cmd/swagger.go` now uses `constants.Ports.OperatorHttps` instead of hardcoded `8443`.

* **Demos Start Command Cleanup** — Removed debug `fmt.Printf` for compose path. Added Windows-specific binary copy instructions.

* **Config Struct Equality Tests** — Replaced `require.True/False` with `assert.Equal/NotEqual` for struct equality in `TestGatewayConfig_Equality` for better failure diagnostics.

### Fixed

* **mTLS Approvals Pending List** — `handleListSuspendedTransactions` split into `listSuspendedTransactions(w, r, filterApproved)` with a `filterApproved` parameter. The CLI endpoint (`handleCLIListSuspended`) filters out already-approved transactions, preventing the CLI from displaying stale approved items as pending. The WebSession endpoint continues to return all transactions.

* **PublicRouteRegistry Exclusion for Pending Endpoint** — Added `/api/v1/approvals/pending` to `PublicRouteRegistry` excluded prefixes in `gateway_auth.go`, ensuring the mTLS-protected CLI endpoint is not bypassed by the WebSessionAuth public prefix for `/api/v1/approvals`.
