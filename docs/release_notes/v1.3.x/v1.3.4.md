## [1.3.4] - 2026-06-30

### Overview

v1.3.4 is a TUI, onboarding UX, and demo integrity release. This version introduces a real-time Tactical Governance Console TUI built with Bubble Tea/Lipgloss, replaces passkey enrollment polling with SSE-based real-time notification, unifies the gateway auth middleware into a typed `RouteAuthRegistry` with four auth modes, consolidates Windows enrollment into the standard `auth enroll` command, and completes the demo integrity initiative — all demo scenarios now submit real GovernanceEnvelopes through the gateway via a shared `harnessRun` helper with no backdoors. Additional work includes a `paths.go` reorganization, keystore error wrapping fixes, `insecure_skip_verify` removal from the TLS cert inspect MCP tool, cross-platform setup script improvements, and new agent-harness scenarios for secure-data and swarm demos.

### Added

* **Tactical Governance Console (TUI)** — Added `g8e tui` command that launches a real-time terminal UI connecting to a running gateway via SSE. Built with Bubble Tea and Lipgloss, the TUI visualizes the execution pipeline (L1–L5), Sovereign Audit Ledger, and L2 Tribunal Consensus. Includes keyboard navigation (j/k scroll, G/g jump, q/Ctrl+C quit). The TUI command uses dependency injection (`tuiDeps`) for Tier 1 testability. New packages: `internal/cli/tui/` (adapter, messages, model, run, styles, update, view) and `internal/cli/cmd/tui.go`.

* **SSE Client Package** — Added `internal/cli/sse/client.go` — a reusable SSE client that connects to an SSE endpoint, parses frames, and dispatches events to a handler. Supports reconnection with 3-second backoff, custom headers (e.g., `X-G8E-CLI-Session-ID` for mTLS), and context-controlled cancellation. Used by both the passkey enrollment TUI and the governance TUI.

* **Passkey Enrollment via SSE** — `RegisterPasskeyViaBrowser` now subscribes to an SSE stream (`passkey.registered` event) scoped to the CLI session via mTLS, replacing the legacy 3-second polling loop. The gateway emits the SSE event from `PasskeyHandler.RegisterVerify` when a browser completes WebAuthn registration, using `emitPasskeyRegisteredSSE` in `passkey_service_http.go`. The enrollment UI is rendered as a Bubble Tea program (`passkey_enroll_tui.go`) with a 5-minute timeout. The console SPA now reads `user_id` and `cli_session_id` from URL hash parameters and auto-triggers registration.

* **Shared mTLS Client Builder** — Added `BuildMTLSClient` in `internal/cli/auth/tls.go` — a reusable helper that creates an `*http.Client` configured with CLI mTLS certificates and the gateway CA bundle. Supports configurable timeout (pass 0 for context-controlled cancellation). Used by the TUI, SSE client, and passkey enrollment.

* **RouteAuthRegistry** — Replaced `PublicRouteRegistry` (exact/prefix/excluded-prefix) with `RouteAuthRegistry` in `gateway_auth.go`. Every route is explicitly classified into one of four `RouteAuthMode` values: `RouteAuthNone` (truly public), `RouteAuthMTLS` (mTLS only), `RouteAuthWebSession` (cookie only), `RouteAuthDual` (mTLS or cookie). The `AuthMode(path)` method checks exact paths first, then prefix matches (longest prefix wins). Eliminates the excluded-prefixes hack. The unified `Middleware` dispatcher stamps request context with the appropriate identity keys for each mode.

* **Dual-Auth SSE Stream** — SSE stream (`GET /api/v1/sse/stream`) and events endpoint now support dual authentication: mTLS for CLI/operator clients, web session cookie for browser clients. The `authorizeSSERoute` helper reads identity from request context (stamped by the unified middleware) and enforces ownership for both auth paths. CLI mTLS path stamps `ContextKeyUserID` without `ContextKeyOperatorSessionID`; cookie path stamps `ContextKeyWebSessionID` + `ContextKeyUserID`.

* **Swarm Demo** — Added `demo_swarm.go` with 3 real scenarios using `harnessRun`: `swarm-recon-mission` (consensus: governed drone deployment), `swarm-weapon-release-block` (doctrine: unauthorized weapon release blocked by L1), and `swarm-restricted-airspace-block` (doctrine: restricted airspace navigation blocked by L1). Added `swarmScenarios` in `internal/tools/agent_harness/scenarios/swarm.go` and registered in `scenario.go`. Updated `demos/swarm/compose.yml` with `agent-runtime` container using Python stdlib `http.server`.

* **Secure-Data Agent-Harness Scenarios** — Added `secureDataScenarios` in `internal/tools/agent_harness/scenarios/secure_data.go` with three scenarios: `secure-data-migration` (consensus: governed migration with chain-of-custody receipt), `secure-data-bypass-attempt` (doctrine: direct transfer without GovernanceEnvelope blocked by L1), and `secure-data-cross-tenant` (doctrine: unauthorized tenant envelope rejected by L1).

* **Healthcare Agent-Harness Scenarios** — Added `healthcare-gold-card` and `healthcare-sla-breach` scenarios in `mcp_a2a.go` for gold-card PA approval and SLA breach reporting through the gateway via mTLS.

* **Typed Audit Models** — Added `internal/models/audit.go` with typed response structs: `AuditReceiptsResponse`, `AuditEventsResponse`, `AuditReportResponse`, `AuditSummaryResponse`. Replaced inline anonymous structs in `audit.go`, `approve.go`, and `data.go` with these shared types.

* **Demo Verbose Flag** — Added `-v` / `--verbose` flag to `g8e demos run`. In default (non-verbose) mode, step-by-step command output is suppressed; scenario result lines, results table, and data dump are always shown.

* **Demo Data Dump** — Added `printDataDump(demoDir)` in `demos.go` that queries the gateway's mTLS API after all scenarios complete and prints receipts, audit events, summary, ledger files, and gateway logs in tabbed tables. Each section gracefully degrades to `(unavailable)` on error.

* **Demo Helper Functions** — Added `captureCommand` (runs a command and returns stdout as string), `demoPrintln`/`demoPrintf` (verbose-aware print helpers), and `runG8EAuditCmd` (runs `g8e audit <subcommand>` inside the operator container) in `demos.go`.

* **Gateway Startup Trust Scripts** — `printNextSteps` in `gwstdout.go` now includes Step 1: trust the gateway CA for HTTPS via `curl | sh` (Linux/macOS) or `irm | iex` (Windows), using the configured HTTP port and external IP.

* **New Error Sentinels** — Added `ErrNotEnrolled`, `ErrGatewayNotReachable`, `ErrKeyStorePurgeFailed`, `ErrPayloadExceedsLimit`, `ErrVaultStdinReadFailed`, `ErrHarnessNoScenarios`, `ErrTestKeystoreNil` to `internal/constants/errors.go`.

* **New Path Constants** — Added `PkiSubdirHub`, `PkiSubdirGatewayPeer`, `PkiSubdirApps`, `PkiSubdirTrustedSigners`, `BinDirname`, `LogDirname`, `ReceiptsExportFilename` to `paths.go`. Derived `DefaultVaultDirDesc`, `DefaultVaultKeyDesc`, `DefaultOperatorKeyDesc`, `DefaultClientKeyDesc`, `DefaultOperatorCertDesc`, `DefaultClientCertDesc` from path primitives instead of hardcoding strings.

### Changed

* **Unified Windows Enrollment** — `g8e auth enroll` now auto-detects Windows and uses the Windows Certificate Store via `GenerateWindowsCSR` with optional `--tpm` flag for TPM-backed keys. The signed certificate is imported via `ImportCertificateToWindowsStore`. Removed the separate `g8e auth enroll-windows` subcommand. `EnrollCLI` now accepts a `useTPM` parameter.

* **Shared `harnessConfig` / `harnessRun` Helper** — Extracted shared `harnessConfig` struct, `defaultHarnessConfig()`, and `harnessRun()` into `demos.go`. All demos (gov, finance, healthcare, secure-data, DoW, DHS) now use the shared helper. DoW uses `UseRun: true` for `docker compose run --rm` mode. DHS `dhsHarnessConfig`/`dhsHarnessRun` are thin aliases delegating to the shared helpers.

* **Healthcare Demo Rewritten** — Scenarios 2–3 now run `healthcare-gold-card` and `healthcare-sla-breach` agent-harness scenarios through the gateway via mTLS. Scenario 1 fallback backdoor removed. `agent-runtime` in `healthcare/compose.yml` builds from root Dockerfile (no bind-mounted host binary). Runtime `pip install requests` removed.

* **Secure-Data Demo Rewritten** — `connector-rclone` and `connector-sharepoint` containers replaced with a single `agent-runtime` container built from root Dockerfile. All 3 scenarios use `harnessRun` to submit real GovernanceEnvelopes via mTLS. Raw `curl -X POST` backdoor removed from scenario 3.

* **DoW Demo Rewritten** — Scenario 2 now runs `dow-bft-veto` agent-harness scenario via `harnessRun` with `UseRun: true`. Scenarios 1 & 3 converted from inline `docker compose run` to shared `harnessRun` helper.

* **DHS Scenario 2 — SQLite Backdoor Removed** — Replaced direct `docker compose exec sqlite3` query with `GET /api/v1/approvals/pending` gateway API call (mTLS-authenticated). Added `extractFirstTxHash` helper to parse JSON response.

* **Demo Output Redesigned** — `demoStep` now suppresses stdout/stderr when `!demoVerbose`. `fmt.Println`/`fmt.Printf` calls for step descriptions replaced with `demoPrintln`/`demoPrintf` across all scenario files. In non-verbose mode, output is: scenario number + name + PASS/FAIL, followed by results table and data dump.

* **Copy-Paste Inspection Blocks Replaced** — All "Copy-paste to inspect..." blocks replaced with `g8e audit receipts | g8e audit events | g8e audit summary` references (shown only in verbose mode).

* **`demosAuditCmd` Updated** — `gateway-db` and `operator-db` actions replaced with `receipts`, `events`, `summary` actions that run `g8e audit <subcommand>` inside the operator container via `runG8EAuditCmd`. `ledger-*` and `vault` actions retained.

* **Removed Unused llm-backend Containers** — Removed the placeholder `llm-backend` service from `demos/gov/compose.yml`, `demos/finance/compose.yml`, and `demos/healthcare/compose.yml`.

* **`paths.go` Reorganized** — Regrouped all constants into logical `const()` blocks: Unix system paths, Windows system paths, SSH paths, environment variables, PKI constants, runtime directory constants, SSH config constants, agent config constants, API path constants, CLI default paths, file permission modes, test-specific constants, operational limits, file suffixes, and reporting constants. Removed unused constants (`PathDevNull`, `PathDevZero`, `PathVarLib`, `PathVarLog`, `PathVarWWW`, `PathOpt`, `PathProcSelfCgroup`, `PathProcSelfMountinfo`, `PeerChainFilename`, `PeerSubdir`, test-specific DB filenames, storage DB full-path constants).

* **Keystore Error Wrapping** — Changed all `%v` format verbs to `%w` in `keystore.go` error wrapping for proper `errors.Is`/`errors.As` chain support. Moved `keyring_memory.go` → `keystoretest/keyring.go` with updated package name.

* **Gateway Router Simplified** — Removed separate `authedMux` and `WebSessionAuth` wrapper in `buildPublicRouter`. Browser-facing routes (`/api/v1/users/me`, `/api/v1/auth/sessions/me`, `/api/v1/approvals`, `/api/v1/auth/passkeys`) are now registered directly on the main mux with `RouteAuthWebSession` classification enforced by the unified `Middleware`.

* **`classifyEnvelopeError` Cleanup** — Replaced string-matching `containsAny`/`indexOf` helpers with `errors.Is` checks against `ErrPubSubEmptyPayload` and `ErrPayloadExceedsLimit` for 400 status mapping. Removed the helper functions.

* **Heartbeat Publishing Uses Protojson** — `handleHeartbeatPublish` in `gateway_service.go` now unmarshals heartbeat payloads as `commonv1.GovernanceEnvelope` via `protojson.Unmarshal` instead of anonymous JSON structs, using `env.GetOperatorId()` and typed snapshot extraction.

* **`approve` Command Context-Aware** — `approve.go` now respects `cmd.Context()` for cancellation, using `select` on `ctx.Done()` and `ticker.C`. Replaced inline `statusResponse` struct with `models.ApprovalStatusResponse`. Uses `constants.SuspendedTxStatus*` string constants instead of hardcoded strings.

* **Audit CLI Error Wrapping** — Replaced sentinel-error-prefix patterns (`%w: failed to...`) with descriptive-context patterns (`audit: create API client: %w`) throughout `audit.go` for clearer error chains. Replaced inline anonymous structs with `models.Audit*Response` types. Default output paths now use `constants.ReceiptsExportFilename` and `constants.ReportsDirname`.

* **Setup Script Improvements** — `scripts/linux-setup.sh` and `scripts/macos-setup.sh` now check for `make` in addition to `go`, offer to install missing dependencies interactively (via `apt-get` or `brew`), and always run `make build` instead of skipping when a binary exists. `scripts/windows-setup.ps1` restructured with similar dependency checking.

* **`security validate` Error Handling** — Now distinguishes `os.IsNotExist` from other `os.Stat` errors, reporting the actual error for non-existence failures. Trust bundle read errors are surfaced instead of silently ignored.

* **`vault` Command Error Wrapping** — Replaced `ErrStatFailed` with `ErrWorkingDirFailed` for `os.Getwd` errors. Used `constants.PermDirPrivate`/`PermFilePrivate` instead of hardcoded octal modes.

* **`encrypted_kv_adapter` Sentinel Errors** — Vault-locked and key-not-found errors now wrap `constants.ErrVaultLocked` and `constants.ErrKeyNotFound` sentinels instead of using ad-hoc `fmt.Errorf` strings.

* **`gateway_db.go` Error Wrapping** — All bare `return err` statements in `initTestSchema`, `initStateRoot`, and `initSchema` now wrap errors with descriptive context (e.g., `canonicalDB: init schema: %w`). Test mode requires a non-nil `testKeystore` (returns `ErrTestKeystoreNil`).

* **MCP Command Guidance** — Gateway startup output now shows `g8e mcp agent show <agent>` and `g8e mcp agent list` instead of `g8e mcp show`.

* **Console SPA Registration Flow** — Console now reads `register`, `user_id`, and `cli_session_id` from URL hash parameters on load, auto-triggering passkey registration when `register=1` and `user_id` are present. Added hidden `regUserId` and `regCliSessionId` inputs to the registration form.

### Fixed

* **TLS Cert Inspect — `insecure_skip_verify` Removed** — Removed the user-controllable `insecure_skip_verify` parameter from the `tls_cert_inspect` MCP tool input schema. The tool now always sets `InsecureSkipVerify: true` internally (with `//nolint:gosec` annotation) since it must bypass verification to inspect invalid/expired certs. This prevents agents from disabling verification on other tools.

* **SSE Authorization for CLI mTLS** — `authorizeSSERoute` now correctly handles CLI mTLS authentication (user ID in context, no operator session, no app ID) by verifying `cliSess.UserID == userID` from context, enabling the TUI and passkey enrollment SSE clients to access their event streams.

* **CanonicalDB Test Schema Keystore** — `initTestSchema` no longer silently creates a fallback keystore when `testKeystore` is nil; it returns `ErrTestKeystoreNil` instead, preventing test isolation issues.
