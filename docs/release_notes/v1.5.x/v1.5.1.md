## [1.5.1] - 2026-07-14

### Overview

Internal refactoring release introducing a `RuntimeFileService` abstraction (`internal/services/fs`) that replaces direct `os.*` filesystem calls across the gateway, keystore, PKI authority, secret manager, storage services, and CLI. All file I/O within the `.g8e/` runtime tree now flows through a single service with relative path resolution, atomic writes, and centralized permission enforcement. Also fixes a duplicate GitHub Release step in the Python protocol workflow and bumps three vendored dependencies.

### Changed

* **`RuntimeFileService` abstraction** — New `internal/services/fs` package (`file_service.go`, `atomic.go`, `bootstrap.go`, `permissions.go`) provides `RuntimeFileService` with `ReadFile`, `WriteFile`, `Remove`, `MkdirAll`, `Stat`, `Resolve`, `Rel`, `RelFromAbs`, `EnforceFilePermissions`, `EnforceDirPermissions`, and `CreateRuntimeTree` methods. All file operations use relative paths constructed from `constants.*` directory/filename constants. The service handles atomic writes (temp file + rename), permission enforcement, and path validation. Direct `os.ReadFile`, `os.WriteFile`, `os.MkdirAll`, and `os.Remove` calls have been replaced throughout the codebase.
* **`Keystore` constructor refactor** — `NewWithKeyring(secretsDir, logger, keyring)` renamed to `NewWithKeyringAndFS(logger, keyring, fileSvc)`. `New(secretsDir, logger)` replaced by `NewWithFS(fileSvc, logger)`. The `secretsDir` field is removed; file operations now use `fileSvc.ReadFile`/`fileSvc.WriteFile` with `constants.SecretsDirname`-relative paths. `EncryptSecret` no longer manually performs temp-file rename (handled by `fileSvc.WriteFile`).
* **`SecretManager` constructor refactor** — `NewSecretManager(db, secretsDir, logger)` changed to `NewSecretManager(db, fileSvc, logger)`. `NewSecretManagerWithKeystore(db, secretsDir, logger, ks)` changed to `NewSecretManagerWithKeystore(db, fileSvc, logger, ks)`. Removed `secretsDir` and `bootstrapDigestPath` fields; secret file paths are now resolved via `fileSvc`.
* **`PKIController` file operations** — `handlePKIFingerprint` now calls `pki.RootCAPEM()` instead of `os.ReadFile(rootCAPath)`. `newPKIAuthority(dataDir, pkiDir, db, sm, logger)` changed to `newPKIAuthority(fileSvc, db, sm, logger)`.
* **`GatewayModeService` / `gatewayServiceBuilder`** — Both now carry a `fileSvc fs.RuntimeFileService` field. `newGatewayServiceBuilder(cfg, logger)` changed to `newGatewayServiceBuilder(cfg, fileSvc, logger)`. `OpenCanonicalDBService` signature updated to accept `fileSvc` instead of `secretsDir`.
* **`CanonicalDBService`** — `initSchema(secretsDir)` changed to `initSchema(fileSvc)`. `initTestSchema(secretsDir, testKeystore)` changed to `initTestSchema(fileSvc, testKeystore)`.
* **`GitLedgerService`** — File removal and path resolution now use `fileSvc.Remove` and `fileSvc.Resolve` instead of `os.Remove` and `filepath.Join(config.BaseDir, ...)`.
* **`ActuatorPubExport`** — PEM and JSON export now uses `fileSvc.WriteFile` with `constants.PkiDirname`-relative paths instead of `os.MkdirAll` + `os.WriteFile`.
* **CLI serve commands** — `gatewayServeCmd` and `operatorServeCmd` now instantiate `RuntimeFileService` and pass it through to the gateway builder and operator service. TLS certificate resolution (`resolveKeyPath`, `resolveCertPath`) updated to accept `fileSvc` instead of relying on `paths.InitWithBase`.
* **CLI auth commands** — `agent_enroll.go`, `passkey_bootstrap.go`, and TLS client (`client.go`, `tls.go`) updated to use `fileSvc` for cert/key path resolution and file reads.
* **CLI commands** — `audit.go`, `vault.go`, `data.go`, `mcp.go`, `mcp_backup.go`, `security.go`, `test.go`, `tui.go`, `operator.go`, `gateway.go`, `demos.go`, `filesvc.go`, `approve.go`, `auth.go` updated to use `fileSvc` and `testutil.TempDir` instead of `paths.InitWithBase` and `t.TempDir`.
* **Test infrastructure** — `internal/testutil/paths.go` and `test_infrastructure.go` updated. New `testfs.go` in `internal/services/keystore/keystoretest/` provides a test `RuntimeFileService`. New `test_setup_test.go` in `internal/cli/serve/` provides `newTestFileSvc` helper. Tests across gateway, keystore, CLI, storage, and MCP services updated to construct and use `RuntimeFileService` instances.

### Fixed

* **Duplicate GitHub Release in Python protocol workflow** — Removed the `softprops/action-gh-release` step and `contents: write` permission from `.github/workflows/release-python-protocol.yml`. The `protocol/v*` tag now only publishes to PyPI and verifies the install; GitHub releases are handled exclusively by the `v*` tag via `release-binary.yml`.

### Security

* **Centralized permission enforcement** — File and directory permissions are now enforced through `RuntimeFileService` methods using `constants.PermFilePrivate`, `constants.PermDirPrivate`, and `constants.PermDirStandard` constants, replacing ad-hoc `0600`/`0700` literals scattered across the codebase. `EnforceFilePermissions` and `EnforceDirPermissions` (recursive) provide explicit permission hardening capabilities.

### Dependencies

* **`golang.org/x/crypto`** — Bumped from 0.53.0 to 0.54.0
* **`golang.org/x/sys`** — Bumped from 0.46.0 to 0.47.0
* **`github.com/pkg/sftp`** — Bumped from 1.13.10 to 1.13.11

### Tests

* Test helpers across the codebase updated to use `testutil.TempDir` (which wraps `t.TempDir()` with consistent cleanup) and `RuntimeFileService` instances instead of `paths.InitWithBase` with manual base directory management. New `newTestFileSvc` helpers in `internal/cli/serve/` and `internal/services/keystore/keystoretest/` provide ready-made test file service instances with the full `.g8e/` runtime tree created.

---

### Migration Notes for External Consumers

No API surface changes affect external consumers of the Go module or Python package. The `RuntimeFileService` refactor is entirely internal. Import paths and public protocol types are unchanged.

**Internal callers** who directly instantiate `SecretManager`, `Keystore`, or `PKIAuthority` (e.g., in custom integrations or forks) must update constructor calls to pass a `RuntimeFileService` instead of directory paths. See `internal/services/fs/file_service.go` for the `NewRuntimeFileService` constructor.
