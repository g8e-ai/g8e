## [1.5.8] - 2026-07-19

### Overview

Protocol constant additions, enum fixes, and wire-format documentation. Restores 8 intent `EventType` members, adds `SessionOperator` KV key template, expands `InfrastructureStatus` and `AuthMethod` enums, adds `grant_intent`/`revoke_intent` API paths, fixes `SessionType.CLI` Python enum generation, fixes `SectionVaultMode` JSON SSOT value mismatch, and strengthens `_SSEEventBody.type` type safety. Documents wire-format changes for `EventType`, `AgentMode`, and `SessionEventWire.user_id`.

### Added

* **Intent `EventType` members restored** — 8 operator intent event types added to `protocol/constants/events.json` and `internal/constants/events.go`: `OperatorIntentRequested`, `OperatorIntentRevokeRequested`, `OperatorIntentApprovalRequested`, `OperatorIntentDenied`, `OperatorIntentGranted`, `OperatorIntentRevoked`, `OperatorIntentApprovalRejected`, `OperatorIntentApprovalGranted`. Values follow the `g8e.v1.operator.intent.*` namespace. Go constants wired into `_EventOperatorIntent` struct and accessible via `Event.Operator.Intent.*`.
* **`SessionOperator` KV key template** — Added `KVKeySessionOperator` (`g8e:sessions:operator:{operator.session.id}`) to `protocol/constants/kv_keys.json` and `internal/constants/kv_keys.go`. Provides a semantically correct key template for operator session KV entries, replacing the `SessionWeb` workaround.
* **`InfrastructureStatus` enum expanded** — Added `OPERATIONAL` (`"operational"`) and `DOWN` (`"down"`) to `protocol/constants/status.json` and `internal/constants/status.go`. New `InfrastructureStatus` typed string with 7 constants in Go.
* **`AuthMethod` enum expanded** — Added `PROXY` (`"proxy"`), `OPERATOR_SESSION` (`"operator_session"`), and `TEST` (`"test"`) to `protocol/constants/status.json` and `internal/constants/status.go`. New `AuthMethod` typed string with 5 constants in Go.
* **`grant_intent`/`revoke_intent` API paths** — Added `GrantIntent` (`/api/v1/operators/{operator_id}/intents/grant`) and `RevokeIntent` (`/api/v1/operators/{operator_id}/intents/revoke`) to `protocol/constants/api_paths.json` and `internal/constants/api_paths.go` struct and initializer.
* **`_SSEEventBody.type` type safety** — Changed `_SSEEventBody.type` field from `str` to `EventType` in `protocol/python/g8e/models/events.py`. Pydantic now validates that SSE event body types are valid `EventType` members, rejecting invalid strings at parse time.

### Fixed

* **`SessionType.CLI` Python enum generation** — Removed `SessionType` from `_EXTRA_ENUMS` in `protocol/python/g8e/enums.py`. The enum now generates from `STATUS["status"]["session_type"]` via dynamic dispatch, which includes all 3 members (`CLI`, `OPERATOR`, `WEB`). Previously, `SessionType` was sourced from `KV["session_types"]` which only had `Web` and `Operator`, causing `CLI` to be missing from the Python enum.
* **`SectionVaultMode` JSON SSOT value mismatch** — Fixed `protocol/constants/prompts.json` value from `"vault_mode"` to `"sentinel_mode"` to match the Go constant `PromptSectionVaultMode` in `internal/constants/prompts.go`. The JSON SSOT and Go code now agree on `"sentinel_mode"` as the canonical wire value.

### Wire-Format Changes (Documented)

* **`EventType` value format** — `EventType` values changed from simple strings (e.g., `"operator_command_requested"`) to dotted namespaced format (e.g., `"g8e.v1.operator.command.requested"`). All 300+ event types follow the `g8e.v1.*` namespace convention. Consumers using `EventType.MEMBER` references are unaffected; persisted data with old-format values requires migration.
* **`AgentMode` value format** — `AgentMode` values changed: `G8E_BOUND` from `"operator_bound"` to `"g8e.bound"`, `G8E_NOT_BOUND` from `"operator_not_bound"` to `"g8e.not.bound"`, `CLOUD_OPERATOR_BOUND` from `"cloud_operator_bound"` to `"g8e.cloud.bound"`. Values now follow the `g8e.*` prefix convention.
* **`SessionEventWire.user_id` addition** — `SessionEventWire` now includes a top-level `user_id: str` field. Previously, `user_id` was nested inside the event data. Consumers should expect `user_id` at the top level of `SessionEventWire` JSON.
* **`ApprovalType` dot-separated convention** — `ApprovalType` values use dot-separated format: `"agent.continue"`, `"command"`, `"file.edit"`, `"intent"`, `"stream"`. This is consistent with the `EventType` dotted naming convention. Consumers using underscore-separated values (`"file_edit"`, `"agent_continue"`) must migrate.

### Known Limitations

* **Receipt signature verification** — The Gateway signs `ActionReceipt`s with its Actuator Ed25519 private key, but no mechanism exists for distributing the Gateway's public key to Engine instances. Consumers cannot cryptographically verify receipt authenticity. See [Encryption Architecture](../../architecture/encryption.md#receipt-signature-verification) for details.
