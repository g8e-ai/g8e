## [2.3.2] - 2026-10-06

### Overview

v2.3.2 is a patch release focused on making the native platform practical to start from a fresh clone and deploy across local, SSH, Docker, Windows, and WSL environments. It expands `operator deploy` into a bounded fleet workflow, replaces the interactive-only host launcher with explicit unattended and setup modes, makes model-provenance preflight progress event-driven, and fixes cross-platform networking, process, filesystem, provider-loading, and status-typing issues.

This release also removes the legacy organization-specific demo stacks, the `g8e demos` command group, demo-derived compliance import and verification paths, and stale checked-in release-evidence workspaces. Evaluation campaigns and signed release compliance reporting remain supported. The removal also retires the host-native release smoke runner; restoring an equivalent runner is an unresolved release-readiness gate.

### Added

* **Local, SSH, and Docker Operator Fleet Deployment** — `g8e operator deploy` now deploys data, provenance, inference, or observer Operators locally, over SSH, or as isolated containers on an explicit Docker context. It supports numbered batches of up to 5000 Operators per host, non-overlapping `--start-index` ranges, bounded parallelism, role-specific `operator start` flags, separate owner-facing and worker-facing Gateway endpoints, automated request-specific enrollment approval, retry, command-channel readiness checks, and session reporting.
* **Safe Docker Operator Runtime** — Added a runtime-only Operator image and build helper. Docker deployment pins one inspected image ID per batch, validates daemon compatibility and Gateway reachability before creating fleet resources, preserves per-Operator named volumes across owned redeployments, refuses resources whose ownership labels do not match, permits only explicit read-only bind mounts outside protected runtime paths, publishes no inbound ports, and does not grant privileged access.
* **Host Platform Lifecycle Commands** — Added unattended `make full`, interactive `make full-setup`, identity-resetting `make full-reset`, dry-run planning, aggregate and component status targets, and targeted Ensemble and Operator start/stop/restart targets. The launcher reads an allowlisted set of endpoint and host values from `.env` as data, can generate commands for remote role hosts, keeps isolated per-role working directories, and preserves workload data when identities need re-enrollment.
* **Cross-Platform Onboarding** — Added `uv` bootstrapping, a CI onboarding smoke workflow, Windows virtual-environment/tool discovery, and expanded Windows setup support. A new PowerShell helper can inspect, apply, or remove narrowly scoped Windows-to-WSL Gateway port forwarding and firewall rules for LAN Operators.
* **Model-Provenance Preflight Progress** — Added the ephemeral `g8e.v1.inference.model.provenance.preflight.updated` SSE event. Campaign preflight now reports phases such as waiting for the Operator, attesting storage, ready, or failed while retaining the persisted attestation window as the authoritative evidence.

### Changed

* **Fresh-Clone Native Startup** — `make build` and `make up` now use the committed Explorer and Console embeds when their gitignored `dist/` directories do not exist. Explicit release embed targets remain strict. Gateway port selection probes the same wildcard bind used by the child process and skips reserved loopback ports, allowing startup when port 8080 is already occupied.
* **Host Launcher Configuration** — `make full` now requires an approved `G8E_OLLAMA_ENDPOINT`, consumes only registered user endpoint/host variables, treats exported variables as higher priority than `.env`, and leaves ports, models, and filesystem paths as explicit command-line settings. Local data-Operator and Ollama storage defaults are resolved consistently.
* **Receipt-Driven Provenance Readiness** — Model storage attestation no longer polls the persisted window. The Gateway registers for the exact Operator receipt and completion event before dispatch, verifies BEGIN and FINALIZE outcomes, propagates cancellation, and returns targeted timeout or Operator failure diagnostics.
* **Typed Case and Investigation Statuses** — Consolidated case and investigation status values into typed, canonical objects across the Gateway, Python protocol, Ensemble models, and Console. Python string enums now accept case and separator variations while preserving canonical wire values.
* **Provider Isolation** — Ensemble provider SDKs are loaded only for the selected provider, so an unavailable optional SDK no longer prevents unrelated providers from starting. Ollama endpoint normalization is provider-independent, and bracketed IPv6 loopback entries in `NO_PROXY`/`no_proxy` are normalized before third-party HTTP clients initialize.
* **CI and Test Tier Ownership** — `make ci` now sequences Console/adapter, platform, protocol, Ensemble, website, and script checks; integration tests that require real listeners, subprocesses, or external runtime behavior are explicitly separated from unit tests. Script and onboarding workflows have dedicated CI coverage.
* **Failure Handling** — Constructors and UUID generation paths that previously panicked now return typed errors to callers. Deployment and enrollment paths propagate those errors with operation context.
* **Build Cleanup Semantics** — `make clean` removes build and test artifacts without resetting Gateway runtime state, trust, or databases. Runtime reset remains an explicit `g8e gw clean` operation.

### Removed

* **Legacy Demo Stacks and CLI** — Removed the DHS, FedRAMP, finance, and healthcare demo trees; the `g8e demos` command group and scenario runner; the legacy agent-harness scenario implementations; and their Make targets. Workflows depending on those commands or files must move to maintained evaluation campaigns or a future replacement smoke runner.
* **Demo-Derived Compliance Paths** — Removed `g8e compliance demo-run`, demo scenario catalog validation/import, demo evidence handoff and verification, and the standalone COSAiS validation target. Signed public release bundles continue through `g8e compliance release-prepare` and the report/evidence commands.
* **Stale Release-Evidence Workspaces** — Removed checked-in `release-evidence/v2.2.5`, `v2.2.6`, and `v2.2.7` working directories. Canonical release-note projections remain the repository-owned public compliance artifacts.

### Fixed

* **Native Evaluation Rollouts** — Model maintenance resolves the embedded client to the executing Operator's binary on native hosts. Evaluation backups reserve unique directories when multiple snapshots are created within the same second, preserving existing evidence and automatic backup deduplication.

* **Public Feed Recovery** — Outbox recovery preserves and retransmits pending batches containing multiple records after interruption, using the batch's first sequence to validate continuity rather than its last sequence.

* **Background Memory Generation** — Memory summaries use a 2,048-token output budget so models without a documented output ceiling cannot generate indefinitely while evaluation assignments wait for their background work.

* **Single-Operator Tool Targeting** — Operator tool calls that omit `target_operators` now default to `["all"]` when exactly one Operator is bound. The default read the investigation's bound-Operator list, which enrichment never populated, so file, port, and listing tools failed validation despite a bound Operator. Enrichment now mirrors the BOUND Operators from the request context.
* **Inference Terminal-Response Diagnostics** — An invalid Ollama terminal response now names the failed condition (no done event, done event without a model, or an empty completion with its `done_reason`) instead of one generic message.
* **Tool-Rejection Reporting** — `g8e eval runs compare` counts cells whose provider rejected the tool declaration, so models without tool support are separable from models that call tools badly. Scoring is unchanged: scored requests still declare the full tool set and a rejection still grades as a failure.
* **Context-Window Overflow** — A prompt that fills the Ollama context window now fails with a distinct typed error instead of being reported as an invalid or empty provider response: `RECEIPT_FAILURE_CODE_CONTEXT_OVERFLOW` and `ErrInferenceContextOverflow` (HTTP 422) on the Gateway, and `ContextWindowExceededError` in g8ee, including for non-empty answers from a truncated prompt. Tribunal, auditor, triage, response analysis, title and memory generation, and the eval judge handle it explicitly without retrying, and an overflowed eval-judge call is errored rather than scored. For `ollama` and `g8e` providers the chat pipeline now drops the oldest whole history messages to fit half of `num_ctx` and tells the model that earlier messages were omitted.
* **Operator Tool Result Status** — g8ee now preserves failed file and filesystem results and their Operator error messages instead of treating every non-shell result as completed. Missing result payloads fail explicitly, port-check errors propagate, and shell errors retain the canonical error field. This fixes missing-file reads being reported to models as successful during evaluation recovery scenarios.
* **Provenance Completion** — Strict campaign verification waits up to five minutes for persisted provenance windows before checking the run, with missing-attempt diagnostics on timeout. The Provenance Operator limits concurrent storage attestations to two and checks cancellation between blob reads, preventing fast scoring from launching hundreds of competing model hashes. Each attempt retains independent hashing and strict digest validation.

* **Busy-Port Gateway Startup** — Fixed the parent launcher and Gateway child selecting different fallback ports when another process owns port 8080, and removed a misleading secondary wait error during failed-start cleanup.
* **Gateway Reachability** — Fixed Gateway listener configuration for localhost, LAN, Windows, and container clients, including separate Operator endpoints and host-side port probing behavior.
* **Windows Runtime Behavior** — Fixed hidden background process launch, noninteractive certificate import with PEM validation, replacement of read-only files during atomic writes, directory-vs-file error classification, Windows virtual-environment executable discovery, and browser/process test seams.
* **Operator Deployment Reliability** — Fixed endpoint flag shadowing, binary replacement while a process is running, Docker enrollment retry behavior, per-deployment ownership checks, role-specific readiness, and remote failure reporting.
* **Ensemble Startup Behind Proxies** — Fixed startup crashes caused by bracketed IPv6 literals such as `[::1]` in ambient no-proxy variables.
* **Console Object Status Handling** — Fixed case and investigation status parsing and display when API records use canonical typed values rather than the Console's previous loose string assumptions.
* **Filesystem Evidence Reads** — Fixed in-memory artifact reads and cross-platform atomic file handling used by compliance report construction.

* **Reported Full CI Run** — The requester reports that `make ci` completed end to end without errors on 2026-10-06. Full CI was not rerun during post-reboot validation.
