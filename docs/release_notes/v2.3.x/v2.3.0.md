## [2.3.0] - 2026-10-02

### Overview

v2.3.0 replaces the g8ed dashboard with the g8e Console, a React and TypeScript browser frontend that the Gateway embeds and serves at `/console/`, and reduces the unified Compose stack to four services: Gateway, Data Operator, Inference Operator, and g8ee. The console covers passkey sign-in, L3 approvals, Operator inventory and binding, cases, investigations, streamed chat, and per-role model selection. Removing a shipped component and adding the first browser frontend served by the Gateway itself is why this release is a minor version and not a patch.

The release also changes how evaluation results are scored and attributed. A campaign records the platform release that froze it, a provider or harness failure is `INVALID_EVIDENCE` instead of a model `FAIL`, every grade states its basis, stored scores are re-verified against their grades, and model output limits belong to the provider instead of platform defaults. The Explorer and its public wire contract carry the same release provenance and typed live events.

Two changes alter trust-boundary behavior and deserve review before upgrade. The Gateway now admits a `DOCUMENT_UPDATE` or `DOCUMENT_DELETE` envelope that names no Operator when it is an application envelope whose `acting_app_id` matches the caller's app certificate (it is how g8ee persists records for a browser session), and the ensemble browser proxy now stamps the Operators bound to the web session itself instead of trusting the browser. One Inference Operator now serves console chat and evaluation campaigns at the same time: the startup campaign binding is removed and campaign authority travels on each dispatch. Wire changes are confined to the evaluation protocol (`eval.proto`: release provenance and the typed `PublicLiveEvent`); no common, operator, or pub/sub contract changes, and L1-L5 verification is unchanged. v2.3.0 follows v2.2.7 directly: v2.2.8 was a draft that was never tagged.

### Added

* **g8e Console** — A React and TypeScript browser frontend (`console/`) embedded in the binary and served by the Gateway at `/console/` with a self-only Content Security Policy. It provides passkey bootstrap, sign-in, and CLI enrollment; L3 transaction approval, CLI recovery approval, and platform enrollment review; Operator inventory with deploy commands, bind/unbind to the web session, and stop; cases with multiple investigations, each a chat session with streamed replies, governed command activity, and in-line ensemble approvals; and passkey management. `make console-build embed-console` refreshes the embed and `make console-embed-check` detects drift. See [Console Architecture](../../architecture/console.md).
* **Per-role model selection in the console** — The Inference view assigns a provider, endpoint, API key, and model to the Primary, Assistant, and Lite roles. Assistant and Lite may inherit. The ensemble owns the provider list and field requirements (`POST /api/v1/settings/llm/get`), saves the selection to the caller's `user_settings` document (`POST /api/v1/settings/llm`), and applies it to the next chat request with no reload. API keys are write-only: they are reported only as set or unset, and a role that changes provider drops its stored key unless a new one is given. `POST /api/v1/settings/llm/models` lists the models an endpoint serves (Ollama, OpenAI-compatible, llama.cpp, Anthropic, Gemini) with the endpoint and key typed in the form or the role's stored ones. For `g8e` governed inference the Inference Operator binds each role's model (`--inference-<role>-model`): the view shows it read-only from the Operator's typed model inventory (`bound_model`), a `g8e` role stores no model, and any browser-supplied endpoint or key is ignored. A failed listing reports only the HTTP status or transport error class. The composer shows the Primary model and warns when none is selected. See [Console Architecture](../../architecture/console.md#model-selection).
* **New investigation in an existing case** — `POST /api/v1/chat` accepts `resource_creation.create_investigation` with `context.case_id` to open a fresh investigation under a case the caller owns; another user's case is reported as not found. The protocol `ResourceCreationRequest` and `protocol/models/chat_message.json` add the field.
* **Operator enrollment is announced to connected browsers** — Claiming an offline Operator slot and issuing a platform-enrolled Operator each publish `g8e.v1.operator.status.updated.active` to the owner's web sessions, so a console that is already open lists a newly approved Operator without a reload.
* **Assignment diagnostics** — `g8e eval runs assignments <run>` reports scenario, model/role or stack, repetition, duration, verdict, deterministic pass rate, and failed grades with recorded causes. `--failed` includes terminal results that did not pass, including invalid evidence. `--assignment <id>` shows every grade and its basis. `--json` carries canonical assignment/result protojson and explicit verdict and pass rate, preserving scored zero as `0` and an unscored result as `null`.
* **Execution log context** — Each assignment log line identifies the scenario, target, repetition, and duration beside lifecycle, verdict, pass rate, and failed grades.
* **Release-tagged campaigns** — A campaign now records the platform release (and source revision) that froze it, bound into its digest. Starting a run under a different release fails with `ErrEvaluationPlatformReleaseMismatch`. Campaigns frozen before v2.3.0 keep their digests; `g8e eval campaigns tag --release <vX.Y.Z> <campaign>...` asserts their release, and a campaign that recorded its release cannot be re-tagged (`ErrEvaluationReleaseRecorded`). `campaigns list` gains a `RELEASE` column and `campaigns show` a `Release` line, each marked `(recorded)`, `(asserted)`, or `unknown`.
* **Release provenance in campaign exports** — Export schema `1.2.0` adds `release`, `release_basis`, and `source_revision` to `run_summary.json` and SQLite metadata. The command's JSON report also identifies the release and basis. Untagged historical campaigns remain explicitly unknown. Compliance bundles retain the digest-bound campaign spec and exclude operator release tags from protected artifacts and inventories.
* **Public release provenance and filtering** — Assignment lifecycle/result protobufs and Explorer schema `1.6.0` preserve campaign release provenance through live events, snapshots, catch-up, verification revisions, and exports. The Explorer defaults to the platform release compiled from its build's `VERSION`, offers “All releases,” and distinguishes recorded, asserted, and unknown campaigns. Historical detail links remain readable. Malformed release tags stop publication instead of acquiring the publisher's identity.
* **Rollout qualifies a changed catalog under a new campaign ID** — When a campaign ID already froze a different scenario catalog, `g8e eval rollout run` freezes and runs the entry under `<campaign-id>-<8 characters of the catalog digest>` instead of failing with a frozen-spec conflict, and says so in its output. `--skip-verified` now skips only entries verified on the current catalog, and each rollout success reports the `campaign_id` it ran under. `g8e eval campaigns create` still fails on a conflict.
* **Contributor toolchain targets** — `make dev-setup` installs the pinned Go tools, the repo-root `.venv`, and Node dependencies (`dev-tools`, `dev-python`, `dev-node`); `make dev-check` verifies every tool `make ci` needs and runs before each `ci` target. The Linux and macOS setup scripts read every tool pin from the `Makefile`, install missing prerequisites with checksum verification, reject Windows shims on WSL, and finish with `make dev-check`. `make proto` installs any missing protoc plugin.
* **Console CI** — The `console-tests` job replaces the dashboard job. It runs typecheck, lint, the Vitest suite, a fresh build diffed against the committed embed, and the `g8e-adapter` build with `npm run gen:contract-pack:check`. `make ci-console` runs the console checks locally (lint, tests, embed check) after `make dev-check`; it does not build `g8e-adapter`.
* **Shared canonical-JSON number vector** — `protocol/vectors/eval/canonical_json_numbers.json` pins how the trace-digest encoder renders numbers (integral floats, `-0`, the plain/exponent switch at 1e-6 and 1e21) for Go and Python.

### Changed

* **Frontend sources moved to the repository root** — The evaluation explorer is now `evaluation-explorer/` and the audited adapter and contract pack are `g8e-adapter/`; Makefile, Compose, CI, setup scripts, and the explorer catalog generator use the new paths. The contract pack changes only its recorded generator path and hashes.
* **Console event registry is generated** — `make constants` now writes `console/src/generated/events.ts` (typed, `as const`) in place of g8ed's `events.js`; `make constants-check` verifies it.
* **Compose and `g8e docker` without a frontend container** — The unified stack is Gateway, Data Operator, Inference Operator, and ensemble. The Gateway no longer sets a CORS origin for port 3000, lists its own HTTPS origin as the passkey RP origin, and forwards console traffic to g8ee at `--ensemble-upstream-url` (`http://g8e-ensemble:8000` in Compose, through a new `g8e-ensemble` network alias; the default `http://127.0.0.1:8000` is the Gateway container itself). `g8e docker start` and `init` approve data operator → ensemble → inference operator, and the `--full` flag is removed from `docker start`, `reset`, and `rebuild`; a script that passes it now fails with an unknown-flag error. The root `.dockerignore` excludes `console/`, `g8e-adapter/`, and `evaluation-explorer/`, which reach the binary as committed embeds.
* **Browser proxy stamps Operator bindings itself** — The ensemble browser proxy sets `context.bound_operators` from the Operators the Gateway registry shows bound to the web session and discards a browser-supplied value. A registry failure yields an empty list, so the request proceeds with no Operator authority.
* **App-bound document writes need no Operator claim** — `verifyEnvelopeIdentityBinding` admits a `DOCUMENT_UPDATE` or `DOCUMENT_DELETE` envelope that names neither `operator_id` nor `operator_session_id` only when `source_component` is `AGENT` or `CLIENT`, `acting_app_id` is set, and a certificate URI SAN equals the app SPIFFE ID for it. Every other unbound mutation, including `EXECUTE_BASH`, `FILE_EDIT`, `RESTORE_FILE`, `MCP_CALL`, and `SHUTDOWN` (which the Gateway's command service also handles), still fails with `ErrIdentityBindingFailed`. L1, the universal L4 checks, and posture-required L2 and L3 proof still apply, and direct submission never synthesizes missing proof. This is how g8ee persists platform records for a browser session when no Operator is in the loop. See INV-AUTH-ID-05 in [Authentication](../../architecture/auth.md).
* **Platform enrollment fingerprints include the port** — The outbound Operator now computes its enrollment fingerprint with the same role and `port` inputs as runtime bootstrap, so the two agree. An Operator enrolled by an earlier release has a fingerprint without `port`; re-enrolling it after upgrade does not supersede the earlier document, so revoke the earlier enrollment explicitly.
* **Provider-owned output limits** — Removed platform tuning defaults and per-call output caps. The generation builder uses an explicit caller limit, otherwise a documented model ceiling, otherwise leaves the limit unset. Anthropic requires a limit and fails configuration when neither the caller nor the model supplies one. The governed inference safety ceiling remains 256,000 tokens (`constants.InferenceMaxOutputTokens`): a request above it is rejected and a request that states none runs under it. This change does not remove that execution boundary.
* **Explicit model-call attribution** — Every recorded model call states `scored_chain`, `post_turn`, or `grader`. Scored resource totals use only `scored_chain`; post-turn Codex calls remain in the trace, and semantic-judge calls use a separate grader context and records. Import rejects missing or unknown classifications and grader calls inside the scored trace's `model_calls`.
* **Smaller, cache-stable prompts** — Shared rules, personas, and tool descriptions use concise rule tables. Tests enforce a 10,000-character shared static-prefix budget, section and persona budgets, and byte stability across changing turn context. Live first-call token reduction, cache hit rate, and behavioral parity remain acceptance measurements, not claims from the character budget.
* **Count each independent grading observation once** — Deterministic grades carry a typed basis: observation, derived, or structural. Derived grades remain visible without padding the pass-rate denominator. The Triage call grade stays separate from task scoring and the verdict. The built-in catalog is `1.2.0`; verification skips grade recomputation for older catalogs.
* **Verify stored scores against their grades** — Assignment verification recomputes task, deterministic pass-rate, Triage, and tier scores from verified grades for current catalogs. Formation results receive this check when graded from role traces. Re-sealing a result cannot make forged scores verify.
* **Compare runs with the shared scoring rules** — `g8e eval runs compare` uses the assignment verdict and deterministic pass rate. `INVALID_EVIDENCE` cells remain visible, appear in the invalid-evidence count, and are excluded from regressions, improvements, and mean scores. JSON includes each cell's verdict and each side's `invalid_evidence` count.
* **Reject retired evidence declarations** — New scenario catalogs reject the `deterministic_grade` evidence type with `ErrEvaluationScenarioContractInvalid`. Stored catalogs remain readable under their recorded version.
* **Typed public live events** — Live events are now the protobuf message `PublicLiveEvent`, encoded only through the canonical protojson owner instead of a hand-written Go struct with `omitempty`. Progress counts and metric values track presence, so a zero (no progress yet, or a failed assignment's `pass` of 0) is emitted, and an event that omits a count is rejected by the Gateway validator and the Explorer's new `decodeLiveEventWire` rather than read as zero. The validator decodes the message strictly, so a field outside it is rejected, and requires each metric to carry exactly one finite value or an unavailable reason. On the wire a live event's `release_basis` is now the `PublicReleaseBasis` enum name, as on lifecycle and result records; the Explorer maps it to its lowercase view vocabulary. The Explorer view contract version is unchanged at `1.6.0`, which has not shipped.
* **Typed errors replace string errors on evaluation and CLI paths** — New sentinels in `internal/constants/errors.go` (`ErrGatewayUnhealthy`, `ErrEvaluationFlagsInvalid`, `ErrEvaluationLifecycleUnknown`, `ErrEvaluationDigestComputeFailed`, `ErrEvaluationTraceDigestMismatch`, `ErrEvaluationGradeBasisMissing`, `ErrEvaluationDerivedGradeContradiction`, and others) replace untyped `fmt.Errorf` strings, so callers use `errors.Is`.
* **Explorer content and layout** — The About view is rewritten around the platform's purpose and principles, the Methodology view is condensed, and the Live view places campaign details and public data beside the reading guide.
* **Generated constants and setup** — The constants generator formats its Go outputs before writing or checking them. Regenerated event and action constants change whitespace only.

* **g8e-provider roles use the Inference Operator's models** — g8ee reads the Operator's `role_bindings` (new `InferenceRoleBinding` in `OllamaModelInventoryResult`) and sets every role served by the `g8e` provider, including one that inherits it, to the Operator's model for that role before any call. Bindings are cached per Operator session. A stored or fallback model is never sent, and a `g8e` role the Operator serves no model for fails with a configuration error naming the flag to set. Request overrides (a campaign's registry-bound model) still take precedence. See INV-LLM-PROVIDERS-06 in [LLM Providers](../../ensemble/llm-providers.md).
* **One Inference Operator for chat and campaigns** — Authority is decided per request: a request without campaign authority runs on the role's configured model, and a campaign request carries its registry and digest on the dispatch. Chat and campaigns run concurrently on one Operator with nothing to switch.
* **The semantic judge never grades with the scored model** — The judge model is `eval_judge.model`, else the Lite model, read from the caller's settings before request overrides. Earlier runs judged with the campaign's own model (`judge_variant_id` equal to the scored model). Semantic grades are not comparable across that change; compare per-scenario verdicts and review flips (INV-EVAL-GRADE-02).
* **Scored turn provider follows its model role** — The scored chat turn uses the provider of the role it runs as (Assistant for Dash, Primary otherwise, or the campaign's designated role) instead of the Lite provider for every simple turn, so a role's model is never sent to another role's backend (INV-LLM-PROVIDERS-07). The console's warning about Lite and Assistant backends is gone with the behavior it described.
* **g8ee listens on loopback only** — Compose publishes the ensemble on `127.0.0.1:8000`. g8ee trusts the Gateway browser-proxy identity stamp, so it must not be reachable from other hosts. The Gateway reaches it on the Compose network, and host tools use `localhost`.
* **Provenance attestation preflight timeout** — The Gateway waits up to 5 minutes (`constants.ModelProvenanceAttestationPreflightTimeout`) for the Provenance Operator to hash a model, and the CLI allows that plus 15 seconds.

### Removed

* **g8ed dashboard** — The Node.js/Express static host and vanilla-JS SPA (`dashboard/`), its Docker image and Compose service (port 3000, `g8e-dashboard-data`), its CI job, `constants.DashboardDefaultPort`, and its documentation (`docs/dashboard/`, `docs/architecture/dashboard.md`). The console replaces it. The `dashboard` platform-enrollment component kind and the reserved `g8ed` name remain in the protocol. A stack created by an earlier release may still hold a `g8e-dashboard` container and a `g8e-dashboard-data` volume that Compose no longer manages; remove them with `docker rm` and `docker volume rm` if present.
* **Output-limit settings** — The `llm_max_tokens` and `eval_judge_max_tokens` user-settings fields, `AgentInputs.max_tokens`, `LLM_DEFAULT_MAX_OUTPUT_TOKENS`, and the `G8E_TEST_LLM_MAX_TOKENS` test variable. Limits now come from the caller or the model's documented ceiling.
* **`--full` flag on `g8e docker start`, `reset`, and `rebuild`** — The unified stack always starts in the default profile.
* **Startup campaign binding on the Inference Operator** — `--inference-campaign-id`, `--inference-model-registry-digest`, their `config.Inference` fields, and the `G8E_INFERENCE_CAMPAIGN_ID` and `G8E_INFERENCE_MODEL_REGISTRY_DIGEST` Compose variables. A dedicated campaign Operator rejected every console chat. A script or override that passes either flag now fails with an unknown-flag error.
* **Legacy g8ed settings routes** — `POST /api/v1/settings/user/get` (it returned stored API keys in plaintext and was reachable through the browser proxy), `PATCH /api/v1/settings/user`, and `POST /api/v1/settings/sync`. No caller remained after g8ed was removed; the console uses the `/api/v1/settings/llm` routes, which never return a key.

### Fixed

* **Three defects blocked streamed chat replies in the console** — A browser session routed SSE with an empty web session ID because `ValidateWebSessionCookie` returned the stored session body's ID, which the document does not carry; it now returns the cookie value that keyed the lookup. g8ee's writes of platform records for a browser session were rejected because every mutation had to name an Operator (see the identity-binding change above). And ephemeral stream events were sent with an `id:` of 0, which rewinds the client's `Last-Event-ID`; they are now sent without an `id:` line and never advance the replay-deduplication cursor, and the console resolves ephemeral event types to ID 0 instead of trusting `lastEventId`.
* **Newly approved Operators did not appear in an open console** — Enrollment and slot claim moved an Operator to `active` without announcing it. They now publish `g8e.v1.operator.status.updated.active`.
* **Enrollment and bootstrap computed different Operator fingerprints** — Platform enrollment omitted the port that runtime bootstrap included, so one Operator carried two identities. Enrollment now derives its role and fingerprint options through `operatorRole` and `operatorFingerprintOptions` (see the fingerprint change above for the upgrade effect).
* **Browser investigation queries were not scoped to the caller** — The Gateway's `GET /api/v1/investigations` rewrite sent no `user_id` filter, and g8ee filtered only on the request body, so a browser session could list other users' investigations. The proxy now always sets the session user, and g8ee overrides any caller-supplied `user_id` with the authenticated user.
* **Bound Operators never reached the ensemble from the browser** — Chat, stop, and approval-response requests through the ensemble browser proxy carried no `context.bound_operators`, so binding an Operator in the browser had no effect on chat. The proxy now stamps the Operators the registry shows bound to the web session and discards browser-supplied values.
* **User settings cache invalidation** — Saving user settings now invalidates the document's cache entry, so the next request reads what was written, including when KV cache reads are enabled.
* **Console chat returned nothing** — g8ee sent its stored or fallback model for Lite-role title, triage, and memory calls, the Inference Operator rejected each with HTTP 403 (`model override not permitted by role authority`), and after five rejections g8ee's circuit breaker for `/api/v1/inference/dispatch` opened and failed every later call, including the Primary reply. g8ee now sends the Operator's model for each role (see Changed), and the breaker counts only server errors that were not retried: a 4xx is an answer from a healthy server and no longer opens it.
* **Agent state stuck after the first run** — g8ee reported `completed` or `failed` and then `running` for the next run of the same persona agent, which the Gateway's transition table rejects, so every later state push failed with HTTP 400 and the projection stayed stale. Chat and Tribunal now report `idle` after each terminal state.
* **Operator default models lost their tools** — `qwen3:1.7b` and `qwen3.5:0.8b`, the Inference Operator's default Assistant and Lite models, were missing from g8ee's model registry, so a chat on them ran with no tools and no thinking. Both are registered.
* **Campaign runs failed at provenance preflight with `tls: bad record MAC`** — Hashing a multi-gigabyte model takes longer than the Gateway's 30-second write timeout, which cut the attestation response mid-record. The attestation handler clears the write deadline (the probe bounds its own wait), and the wait now allows for large models.
* **Semantic judge rejected on a shared Inference Operator** — The grader dispatches without campaign authority but used the campaign's model, which the Operator rejects for a plain request; two of eight assignments in a smoke run lost their semantic grade. See the judge change above.
* **`./g8e test e2e` skipped the console test** — The default e2e selection still named `TestDashboard_` after the dashboard test became `TestConsole_Index`, so a default run silently excluded it. The default now selects `TestConsole_`, as `make test-docker` does.
* **Provider and harness failures counted against the model** — A provider error, execution error, escalation, or grader failure no longer publishes a model `FAIL`. Each terminal lifecycle now publishes its own outcome (`provider_failed`, `execution_failed`, `escalated`, `grader_failed`, `invalid_evidence`, `stopped`) from one mapping, and its verdict is `INVALID_EVIDENCE`: shown, with no `pass` metric, and excluded from `runs compare` and pairwise agreement. The Explorer shows each outcome and filters failures by it. An unrecognized lifecycle is an error, not a model failure. Run and per-model `pass_rate` now divide by assignments judged on the model, so a provider outage no longer lowers it; with none judged the rate is unavailable rather than zero.
* **Export pass-rate denominator** — Model CSV and SQLite exports use the same judged-assignment denominator and publish a `judged` count. One pass, one miss, and one provider failure exports as `0.5`; with nothing judged the CSV cell is empty and SQLite stores `NULL`. Coverage continues to count all terminal assignments.
* **Failed scores displayed as unavailable** — The Explorer's wire decoder materializes the protobuf default of zero for a present score record whose `value` is omitted. A missing `task_score` record is a validation error instead of an inferred verdict.
* **Live rows showed the wrong outcome or later evidence** — Terminal rows display the verdict outcome while retaining lifecycle in detail. Started rows no longer receive final assignment metrics. Assignment metric updates carry the designated role and binary `pass` metric, which the stream reads without deriving a pass from a rate.
* **Scenario applicability lost at adaptation** — Benchmark observation metrics use the shared metric decoder, preserving normalized `scenario_not_applicable` reasons.
* **Failure cause missing from live rows** — A failed row's Status tooltip displays the existing public failure sentence from the matching assignment. Assignment details show the same sentence. The tooltip is limited to failed terminal events and matching dataset, assignment, and run identity. Grade basis stays private.
* **Stale embedded Explorer** — Rebuilt the production Explorer and refreshed Gateway assets through `make embed-explorer`, which also carries the `v2.3.0` current-release default.
