# Changelog

All notable changes to this project are documented in per-release notes under [`docs/release_notes/`](docs/release_notes/).
This file serves as an index — each entry links to the full release notes for details.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## v1.7.x

| Version | Date | Description | Notes |
|---------|------|-------------|-------|
| 1.7.4 | 2026-08-15 | Demo, packaging, and enrollment refactor: consolidates Docker builds into a single always-FIPS repo-root `Dockerfile` (removes `Dockerfile.fips`, `demos/Dockerfile`, and `demos/fedramp/compose.fips.yml`; demos now build from the root Dockerfile via `context: ../..`); rewrites the healthcare demo to use the native `run_shell_command` tool via a `paop` wrapper instead of a custom MCP downstream (removes `pa_api_server.py` and the `pa-submission-service`/`message-broker`/`reporting-db`/`rabbitmq` containers); removes notary/passkey enrollment, posture switching, and host-CLI enrollment from the `demos run <org>` automated orchestration so DHS and FedRAMP demos are real end-to-end smoke tests with zero human interaction (removes DHS scenario 2 `dhs-release` and FedRAMP scenario 3 `fedramp-escalate`, renumbers remaining scenarios DHS 5→4 / FedRAMP 5→4); makes passkey enrollment required only for notary posture (optional for doctrine and consensus) with posture-aware `gw start` next-steps output; adds a blocking browser-restart gate to `auth enroll` that prompts the user to close all browser windows and press Enter after the trust store changes (skipped for internal callers and when the trust store is unchanged); prints the passkey enrollment URL to the terminal before opening the browser; removes the deprecated `RegisterPasskeyViaBrowser` wrapper; fixes the frontend demo's CORS preflight (204 per Fetch spec) and passkey-challenge (200 or 400) assertions via a new `demoStepHTTPAny` helper; fixes the FedRAMP `verify_ops.py` KSI path by mounting `fedramp-gateway-state` read-only into the cloudsvc container; fixes the PyPI publish verification job to poll the PyPI JSON API before installing so CDN propagation races do not cause spurious verification failures; makes `gw start` copy the running binary into `.g8e/bin/` so the re-executed gateway has a stable binary location (adds `PermFileExecutable`, `ErrBinaryResolveFailed`/`ErrBinaryCopyFailed`/`ErrBrowserRestartDeclined`, `ContinueFunc`, `BinDir` in `paths.Infra`, `.g8e/bin` in `CreateRuntimeTree`). Notary posture itself is not removed from the platform — `demos scenarios run <notary-scenario>` still works for manual testing. | [v1.7.4](docs/release_notes/v1.7.x/v1.7.4.md) |
| 1.7.3 | 2026-08-14 | PKI common-name constant centralization and release process doc cleanup: extracts the hardcoded `"g8e Root CA"` root-CA subject CN into a single typed constant `constants.RootCACommonName` and replaces every scattered string literal and package-local copy (`gateway_certs.rootCommonName`, platform `g8eRootCommonName`) across gateway certificate generation, per-platform OS trust-store installation, and stale-anchor enumeration (internal refactor only — on-wire CN value, certificate subjects, trust-store matching, and stale-anchor detection are unchanged); clarifies the separation of duties in `docs/devs/release_process.md` between the agent (PR prep) and the release owner (commit, merge, CI gate, `make release`). | [v1.7.3](docs/release_notes/v1.7.x/v1.7.3.md) |
| 1.7.2 | 2026-08-14 | CLI enrollment refactor: replaces the scattered `BootstrapWithURL`/`CLIEnroll`/`ReEnroll`/`EnrollWithGateway`/`AutoRenewCertificate` transport with a single `EnrollmentCoordinator` owning the enrollment state machine, adds human-approved CLI recovery flow (one-time browser approval, opaque token, proof-of-possession), adds mTLS-protected CLI certificate rotation endpoint, builds in OS trust installation before browser launch (`--no-system-trust` opt-out), removes `--tpm` flag (file-backed EC P-256 on all platforms), and removes legacy per-platform trust-install script routes (`/web-cert.sh`, `/web-cert.ps1`, `/.well-known/g8e/pki/trust-windows`) and `handleCLIEnrollment` (`/api/v1/auth/cli/enroll`). Breaking: clients calling the removed enrollment endpoint must migrate to recovery/bootstrap. | [v1.7.2](docs/release_notes/v1.7.x/v1.7.2.md) |
| 1.7.1 | 2026-08-10 | Gateway construction refactor: collapses `mcp.GatewayService` two-phase construction (`SetRuntimeDeps`/`RuntimeDependencies`/`atomic.Pointer`) into single-phase construction with lazy forwarding adapters (`GatewayEnvProcAdapter`, `GatewaySessionValidatorAdapter`) to break the circular dependency, decomposes `HTTPHandlerDependencies` into per-controller `Deps` structs (16 controllers), promotes `mcp`/`pubsub`/`passkey` direct accessors to thin controller wrappers, removes `gateway.Stores` leakage past `CanonicalDBService` (11 narrow accessors + lint guard test), folds `InitHTTPHandler` into `NewGatewayModeService` with a `SetConsensusService` narrow setter, and removes noop stubs from outbound governance deps in favor of nil-with-fail-closed-nil-check. Internal construction/refactor only — no wire protocol, on-disk schema, or user-facing CLI behavior changes. | [v1.7.1](docs/release_notes/v1.7.x/v1.7.1.md) |
| 1.7.0 | 2026-08-07 | SSE routing model refactor: replaces the three-way mutually-exclusive routing model with a two-dimensional `user_id` (ownership, always required) + exactly one session ID (delivery) model, removes the `user_id`-only fan-out route (eliminating cross-session approval leakage), moves routing/identity IDs out of URL query strings into headers/auth context, adds `SubmitterCLISessionID` to suspended transactions for session-scoped approval events, makes `sse_events.user_id` NOT NULL with a CHECK constraint, and splits the SSE integration test file into 5 focused files. | [v1.7.0](docs/release_notes/v1.7.x/v1.7.0.md) |
